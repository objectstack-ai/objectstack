fix(service-storage): stored bytes are previewed in place only when they begin with their type's signature

Clause-②: no
Metadata-protocol: none

The local adapter's byte route now answers a file on the inline allow-list inline only when its stored bytes begin with the leading signature of that type: PNG, JPEG, GIF, WebP, AVIF and BMP images, PDF, and each of the 13 allow-listed audio and video types. Plain text has no signature, so it is previewed when the body opens with a byte-order mark or carries no binary data byte (the WHATWG MIME Sniffing standard's text-or-binary rule). Any other body, an empty one included, is answered as an `attachment` under the default sandbox policy, with `nosniff` as before. The type and the file name answered are unchanged.

The fix for a host: nothing to change. A file whose bytes are what its type says previews as before; one that is not still downloads under its own name and type.
