fix(approvals)!: an approval request whose flow package was uninstalled never reads another package's flow of the same name (ADR-0150 D8 row R7)

Clause-②: yes (narrowing) — an approval request stamped with the package it was opened on (`process_package`), whose package no longer holds a flow of the request's name while another package does, moves FROM reading that other package's flow TO reading none, at four doors: (1) send-back (`POST /approvals/requests/ID/revise`) FROM checking the other package's revise edge, and returning the request on its graph, TO `409 RESOURCE_CONFLICT` (reason `not-held-by-qualifier`, the stamped package as the qualifier, every holder named) with nothing written; (2) the request read (`GET /approvals/requests/ID`) FROM serving the other package's `flow_route` and `flow_steps` TO serving neither; (3) the stranded-resubmit continuation's revise window FROM the other package's window TO the same `409`; (4) the queue package a re-resolved slate reads a `queue` approver's name from FROM the other package TO none (the environment-wide read a request with no flow takes). The other package is read today through the bare name (the stamped package withdrew from a name two packages held) or through the run's key (the stamped package was the name's one holder, and the other package installed the name after it left). First-party callers in that position: 0 (no first-party package uninstalls a flow that another first-party package ships under the same name). Unchanged: a request whose stamped package still holds the name, beside a second holder or alone, and a request naming no package; with no holder of the name left, every door answers as for a deleted flow, as before.
Metadata-protocol: none

**BREAKING** for an approval request opened on a package's flow after that package is uninstalled while another package ships a flow of the same name. FROM the request answered from the other package's flow TO refused `409 RESOURCE_CONFLICT`, naming every package that holds the name. The fix: install the request's package again (the refusal names it) to act on the request; nothing else answers it from a flow it was not opened on.
