Tooling-only: `check:adr-anchors` now knows the difference between a record and a **decision** — anchoring code to a tombstone is refused (#7329). Releases nothing; no package changes.

`docs/adr/0107-withdrawn-hook-body-write-set-static-gap.md` (#6676) is the corpus's first tombstone: a file whose entire content is "this number is withdrawn, do not reuse". It was written to make the historical `ADR-0107` citations resolve, and it does. But the gate assembled its record set from filenames alone, so the same file also satisfied the anchor loop's `records.has(...)` guard — a guard that was never meant to accept it. Measured on `main` @ `69fde55`: a shard in `scripts/adr-anchors/` citing `ADR-0107` made the gate print OK and exit 0, anchoring live content to a number whose own record says nothing in it is in force. Nothing had done this, and the only thing standing in the way was a reader noticing that the required `invariant` field — "state what the ADR decided" — cannot be written truthfully for a number that decided nothing.

The two audits want opposite answers about the same file, so one set was not enough. A tombstone number is now in `records` (citations resolve — the job it exists for) **and** in `nonDecisions` (anchors refused). No live record's treatment changes, and the failure names the two real routes out: anchor the live decision that actually governs the code, or write it under the next free number — never revive this one, which would retroactively re-point every historical citation of it (#6634).

The marker is the **filename**, `NNNN-withdrawn-<slug>.md`, for the reason the `.vN` version rule and the cross-repo qualifier are also spellings rather than lists: a structural signal is available to every future record without editing the gate, and it is legible to anyone reading `ls docs/adr/`. A `status:` field in YAML front-matter was the more obvious design and was rejected on three measurements — zero of the 119 records carry front-matter today, so it introduces a repo-wide convention for one file; the records' status lines are free prose and are already deliberately outside this gate's rules; and #6741 routes *any* diff touching `docs/adr/**` to the maintainer's own merge, which would couple a script-only fix to a governance approval while failing open in exactly the same way. An explicit list in the script was rejected as the one option needing a gate edit per future tombstone.

The anchor loop's ADR-id judgement is extracted into `anchorIdProblem` so `--self-test` drives the real function: 15 new assertions cover both directions over the same file (a tombstone still resolves citations, and is refused as an anchor), the `.vN` case, the prefix-not-substring boundary so a live decision *about* withdrawal keeps its anchors, the contested-number case (a tombstone sharing a number with a live record is a collision, and the live record keeps its anchors), and an ablation on the real tree replaying the exact probe that came back green on `main`.

Deliberately **not** done: the blanket "flag every gap in the ADR numbering" check #6676 floated. The census on #7329 is the reason — four holes, three causes: `0075` and `0083` are blameless number skips, `0001` is a deleted record already grandfathered, and only the `0107` shape carries the squat risk. A gate that alarms on innocent skips trades noise for a risk this change already covers.
