Tooling-only: shard the ADR-anchor registry into one file per anchor (#6957). `scripts/adr-anchors.json` — a single 343-line append-only array that every card adding an anchor had to edit — becomes `scripts/adr-anchors/<path with / replaced by __>.json`, 47 files, assembled in id order at read time by the new `scripts/adr-anchors.mjs`. `pnpm check:adr-anchors` reads the directory; its verdict, its anchor count (47) and every failure message are unchanged except that each now names the exact entry file to edit. Releases nothing — no package changes.

Why the layout and not better merge tooling: this repo has already answered this question twice, and the second answer is the binding one. `merge=os-regen` (#4675) is a **local** git facility, and the GitHub merge queue rebuilds each PR server-side where no custom merge driver runs — which is why #5837 had to *shard* the three hottest spec artifacts rather than route them. `scripts/adr-anchors.json` had the same shape and the same symptom: of the re-merge laps in 2026-08-06..10 where two sides both appended to it, one of two conflicted (PR #6608's only hand-resolved conflict that night). The cost that matters is not the lap — both this registry and its sibling ledger are consumed as **sets**, so a resolution that drops one side's entry produces no error anywhere: the anchor simply stops being checked, and the decision it protected goes back to being reversible by a patch-level changeset, which is #3723, the incident the gate exists to prevent.

Two properties are enforced rather than assumed, because they pull in opposite directions and only testing the first would produce a layout that also merges away the edits it must not. The shard filename is a pure function of the entry id, so two cards anchoring **different** files never share a file, and two cards anchoring the **same** file collide in git as they should. Order is derived (sort by id), never declared: an index file would itself be the single append-only file every card must edit, reintroducing the exact conflict being removed.

Nothing left version control and no reviewable diff was traded away — the same bytes are committed, one entry per file, and a new anchor is now a new file instead of a hunk in a shared blob.
