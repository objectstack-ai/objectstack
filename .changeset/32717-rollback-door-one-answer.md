fix(metadata)!: `DatabaseLoader.registerRollback` answers an addressed rollback to a version its address's history does not hold "not found", as `MetadataManager.rollback` does, and a version's existing history row, never the restored body's package stamp, says whose version it is (#32717)

Clause-②: yes (narrowing) — for a type stored per `(package, name)` (`PACKAGE_SLOTTED_STORE_TYPES`; at this release `api`, `agent`, `skill`, `action`, `email_template`, `permission`, `flow`, `picklist`, `mapping`, `dataset`, `webhook`, `tool`), called directly on `DatabaseLoader.registerRollback`. Narrowed: an addressed rollback (`{ packageId }`, a package or `null` for the environment) to a version attributed to no package, on a name one row slot holds, and one addressing a package to the environment's own version while that package's row is the name's one slot (M1), wrote the version into that row and now answer `Version N not found in history for TYPE/NAME (package PKG)` (or `(environment)`), writing nothing; an addressed rollback to a version attributed to no package, on a name two row slots hold, with a restored body stamped for one of them (`_packageId`), wrote it into that package's row (addressing it) or answered that the version was that package's (addressing the other) and now answers `409 RESOURCE_CONFLICT` (`ambiguous-in-environment`, naming every holder). Widened: a rollback naming no package to a version attributed to no package, on a name one row slot holds, with a restored body stamped for a package that holds no row of the name, answered `409 RESOURCE_CONFLICT` (`not-held-by-qualifier`) and now lands in the one row, as the same version restored with an unstamped body does. `MetadataManager.rollback` answers every one of these as before.

**BREAKING** for a caller of `DatabaseLoader.registerRollback` that addresses a package (or the environment) and restores a version that address's history does not list. No first-party caller reaches it: `MetadataManager.rollback`, its one caller in the workspace, reads the addressed history first and already answered these requests "not found" or `409`, and the REST `/meta/:type/:name/rollback` door goes through the protocol's own repository. The fix: roll back naming no package on a name one row slot holds (`registerRollback(type, name, body, version)`), which restores such a version into that row as before, or address the package the version is attributed to (its `getHistory(type, name, { packageId })` lists it).

ADR-0150 D3/D4: an address names whose versions a rollback restores, and only a version's history row says whose it is. The two rollback doors of the metadata service now answer one request in the same words:

- **A version attributed to no package** (a history row written before `sys_metadata_history.package_id`, or one `SysMetadataRepository` wrote before it recorded the column), addressed: FROM written into the addressed row at `registerRollback` and "not found" at `MetadataManager.rollback`, TO "not found" at both while one row slot holds the name, and `409` naming every holder at both while several do, as before. Naming no package it lands in the name's one row at both doors, as before.
- **The environment's own version, addressing the package whose row is the name's one slot** (M1: a package took over the package-less row, or saved after it was removed): FROM written into that row at `registerRollback` and "not found" at `MetadataManager.rollback`, TO "not found" at both. Naming no package it lands in that row at both doors, as before.
- **Whose version it is.** FROM the version's history row's attribution, else the restored body's package stamp when the row was attributed to none, TO the history row's attribution whenever the row exists; the body's stamp stands in only for a version with no history row at all (history not tracked, or no row of that version). A version attributed to no package is therefore never attributed by the body a caller hands in: on a name two row slots hold it is refused `409` naming both, ⛔ never written into the row of the package the body names.
