fix(runtime)!: a multi-package artifact binds each package body's hooks and functions under that body's package, as its actions are since #32333 (ADR-0150 D3/D4)

Clause-②: yes (narrowing) — a hook in package body B, a body other than the artifact's own, whose `handler` names a function only another body A of the same artifact declares is no longer bound: FROM bound and running A's function (every hook and function of the artifact was registered under the artifact's own id) TO refused at bind with `INVALID_REFERENCE` (400), logged at error, the hook never running; and a flow of the artifact's own package whose `script` node names a function only another body declares, which no hook under the artifact's id names, FROM running it as the artifact's own TO the package-scoped answer (ADR-0150 D3): that body's function when its package is in the flow package's declared closure, else refused `outside-closure`. And a hook name one package body other than the artifact's own declares, which the artifact's top level also carries for an input with no `manifest` (the ADR-0130 residual), FROM both hooks bound under the artifact's id TO neither bound, refused at bind and logged at error with `RESOURCE_CONFLICT` (`ambiguous-in-environment`) naming the body: nothing in the artifact tells the residual's copy from the body's, the shape #32355 refused for a job; a residual twin of the artifact's own body's hook binds as before. Three engine calls move with it: `unregisterHooksByPackage('app:ARTIFACT_ID')` and `unregisterFunctionsByPackage('app:ARTIFACT_ID')` FROM removing every body's hooks and functions TO removing the artifact's own package's (and the top level's), and `functionHoldersOf(name).packageItem(ARTIFACT_ID)` FROM answering every body's function TO the artifact's own package's (with any body's function a hook under the artifact's id names, which stays there). Measured first-party: 0 (the one first-party composition, `examples/app-multi-package`, declares no hook, function or flow; no first-party code calls those engine methods with a composed artifact's id outside the binder). It also widens: a hook in body B naming a function the engine holds under B's own package (`app:B`) binds, where it was refused `INVALID_REFERENCE`; and a flow in body B naming B's own function runs it, where it was refused `outside-closure` (or ran the artifact's owner's holder) whenever B's closure did not reach the artifact's own package, unless a hook under the artifact's id names that function too, which keeps it there as before.

**BREAKING** for a multi-package artifact (`packages[]`, as `composeStacks(…, { manifest: 'preserve' })` emits) whose hook in one package body names a function only another body declares. Before, every hook and function of such an artifact was bound under the artifact's own id (`app:ARTIFACT_ID`, the last input's manifest), so a body's hook could name any body's function; now each body's hooks and functions are bound under that body's package (`app:PACKAGE_ID`), except a function a hook under the artifact's id names (a top-level hook's, or the artifact's own body's), which stays there with that hook as before, and a hook resolves its `handler` in its own package only (ADR-0150 D3), so that hook is refused at bind with `INVALID_REFERENCE` and does not run. FROM a hook in package B naming A's function TO declaring the function B's hook needs in B's own body, under a name of its own (`composeStacks` refuses one function name in two stacks), or moving the hook into A. FROM a top-level hook sharing a package body's hook name TO renaming one of the two. The same cause moves a flow of the artifact's own package that names another body's function: it now reaches that function only through its package's declared closure (`dependencies`), else it is refused `outside-closure`; FROM relying on the artifact's id TO declaring the dependency on the package that holds the function, or keeping flow and function in one package. In-process code that unregisters or reads by the artifact's id moves too: `unregisterHooksByPackage('app:ARTIFACT_ID')` and `unregisterFunctionsByPackage('app:ARTIFACT_ID')` reach only the artifact's own package's hooks and functions; FROM removing `app:ARTIFACT_ID` alone TO removing each `app:PACKAGE_ID` the bundle's bodies name as well, or re-binding the artifact. No source in this repository calls them outside the binder.

- **One rule for every family.** `bindAppArtifactHandlers` binds a body's hooks and functions the way it binds its actions: a hook whose name one body carries binds under that body's package; a name two bodies carry stays one hook under the artifact's owner unless the two are held apart (child N's namespace co-owner rule, `namespaceNameConflicts`), in which case each body binds its own; a hook the top level carries and no body declares stays under the artifact's owner. A function one body declares is registered under that body's package; a function no body declares (a top-level function, or a ref `os build` lowered out of a body's hook) is registered with the hooks that name it, else under the artifact's owner; and one that the hooks of two or more bodies name (one callable two bodies' hooks share) stays under the artifact's owner with every hook that names it, as before, since a function keeps one package holder. Likewise a function one body other than the artifact's own declares, which a hook under the artifact's owner names (a top-level hook, the artifact's own body's hook, or a hook name two bodies of one namespace carry, which the install gate refuses first), stays under the artifact's owner with that hook and with its declaring body's own hooks that name it, so each of them binds and runs it as before. A bundle with no `packages[]` binds exactly as before.
- **Firing order.** Each package's hooks keep the order the artifact carries them in, and the packages bind in the order their first hook appears, so two bodies' hooks of one `priority` on one object and event may now fire grouped by body where they interleaved before. Where the order between them matters, give them distinct `priority` values.
- **Re-bind.** A re-bind tears down the hooks of every owner the artifact's previous bind on that engine recorded, and the functions of a package body the new bundle drops, so a dropped body's hooks stop firing and its functions leave the engine.
- **Unchanged.** The job rulings (Q1-B, a job's `pull`; Q2-O1, a job's `organization`), the line on platform-internal scheduled work, the hooks with no `body` a door with no runtime module withholds (`withholdHooksWithoutBody`, across every body), and the rule that nothing resolves a bare name to a package hold as before; the install-local door (`MarketplaceInstallLocal`) and `AppPlugin` both bind through this one function.
