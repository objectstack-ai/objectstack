fix(metadata-protocol)!: a save naming a package of a runtime object whose owner is its package-less definition is refused before any write, with a way out that moves the object into that package (ADR-0029 D9.9)

Clause-②: no (narrowing)

<!-- adr-0087: not-required (no-migration-prescription) No metadata moves: no spec key, authorable spelling, object definition or stored shape is added, removed, renamed or re-shaped, no stored row is rewritten, converted or deleted by this change, and no exported declaration is added, removed or narrowed, so there is nothing for `objectstack migrate meta` to rewrite. What narrows is the accept set of the object save door for one shape: a save naming a package of an object whose registry owner is its package-less definition (the `sys_metadata` sentinel), or a save naming no package that the door addresses to such a package's row, is refused, where it was written and then discarded by the registry. The remedy is in the requests a caller sends (deletes and saves through the same doors), never a rewrite of a package source or a stored row. The other categories are closed on facts: the package publishes (not unpublished); no ADR-0087 id is named or touched (not registered or already-registered); and nothing exported is removed or narrowed (not runtime-interface-only, type-surface-only or runtime-export-retired). -->

**BREAKING** (an accept-set narrowing), shipped as `minor` under the launch-window convention for breaking changes.

An object has exactly one registry entry, so it has exactly one owner (ADR-0029 D3), and `sys_metadata` must not describe a shape the registry cannot hold (D9.9). A runtime object first saved naming no package is owned by that package-less row. A save naming package `Q` beside it was written and answered `200`, but the registry refused `Q`'s row into a warning and kept the package-less definition. The metadata read then served `Q`'s row while the data plane served the package-less one, before and after a boot, and at boot `Q`'s row was counted in `errors`. The package-less state is no authoring destination (ADR-0070), so the refusal does not say "bind it to `sys_metadata`". It names the way into `Q` that is true in the state it answers.

What changes for you, where object `NAME` is owned by its package-less definition and `Q` is any package. Every refusal below is `422 OBJECT_OVERLAY_PACKAGE_MISMATCH` with nothing written. The error carries `packageId: Q` and `ownerPackageId: null`.

- FROM `PUT /api/v1/meta/object/NAME?package=Q` (`saveMetaItem({ type: 'object', name: NAME, packageId: Q, … })`) answering `200` "Saved object … package=Q" with a `Q`-bound row stored that nothing served, TO the refusal: "Move object 'NAME' into package 'Q' first: delete its package-less definition without dropStorage, which keeps its table and records … then send this save again. …".
- FROM the same save as a draft (`PUT /api/v1/meta/object/NAME?package=Q&mode=draft`, Studio's designer) answering `200` with a `Q` draft that could never go live, TO the refusal: "Move object 'NAME' into package 'Q' first: … then save it naming 'Q' in publish mode, which serves it at once, and draft after that. …".
- Where a `Q` row is already stored beside the package-less one (the rows this defect wrote before the refusal existed), two saves change:
  - FROM `PUT /api/v1/meta/object/NAME?package=Q` answering `200` over that row, TO the refusal: "Object 'NAME' is served by its definition bound to no package; its stored definition bound to 'Q' is never served. To move the object into 'Q': delete the 'Q' row (REST: DELETE /api/v1/meta/object/NAME?package=Q), then the package-less definition without dropStorage … then save it naming 'Q' in publish mode. …".
  - FROM `PUT /api/v1/meta/object/NAME` naming NO package answering `200`, TO the refusal. The door addresses a save naming no package to the item's one package binding, which is `Q`'s row, so the edit was written there and never served. The refusal reads: "A save naming no package of object 'NAME' is addressed to its stored definition bound to 'Q', which is never served: … Delete the 'Q' row first (REST: DELETE /api/v1/meta/object/NAME?package=Q), then send this save again: it then saves the package-less definition. …".
- FROM promoting `Q`'s draft of the object (`POST /api/v1/meta/object/NAME/publish?package=Q`, or `POST /api/v1/packages/Q/publish-drafts`) answering success with `Q`'s active row stored beside the package-less one and never served, TO the refusal. This reaches a draft stored before the package-less row existed, or one a draft save naming no package wrote over the rows above. The per-item publish answers `422`; `publish-drafts` answers `200` with `outcome: 'refused'` and the draft in `failed[]` with this code (ADR-0067 D2). The text reads "Move object 'NAME' into package 'Q' first: delete its package-less definition without dropStorage … then publish this draft again: it then serves the object at once. …". Where a `Q` active row is also stored, it names deleting that row first, as above. The draft stays stored.
- The boot's reason for those rows changes. `loadMetaFromDb` still keeps the package-less owner and counts `Q`'s row in `errors`. Its warning, `[Protocol] Failed to hydrate object/NAME: … (code=OBJECT_OVERLAY_PACKAGE_MISMATCH)`, now carries the move above, ending "The row bound to 'Q' is not registered.", where it carried the registry's "already owned by package \"sys_metadata\"" text.

**Remedy, in one line per state.** Do not send the request again unchanged; follow its order. With no `Q` row stored: `DELETE /api/v1/meta/object/NAME` (no `package`, no `dropStorage`), then `PUT /api/v1/meta/object/NAME?package=Q` in publish mode. That publish-mode save makes `Q`'s row the owner at once and at every boot; a draft save registers nothing, so draft only after it. With a `Q` row stored: first `DELETE /api/v1/meta/object/NAME?package=Q`. Then either send the save naming no package again, which now edits the package-less definition, or move the object as above. For a refused publish of `Q`'s draft: the same deletes for its state, then the same publish; the draft's promotion makes `Q`'s row the owner. A `DELETE` naming no package over those rows removes the `Q` row too: it is addressed the same way. No step drops a table or a record.

**Unchanged.**

- A save naming no package where only the package-less row is stored (its own re-save), in either mode.
- The D9.9 refusal for an owner bound to a real package: same code, status and prescription.
- An object with no owner, and an object a code package ships.
- Every type except `object`.
- Stored rows are not rewritten on upgrade.
