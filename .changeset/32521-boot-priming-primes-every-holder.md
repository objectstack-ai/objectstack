fix(metadata)!: the boot priming pass primes every holder of a name two packages hold, of a type stored per `(package, name)`, so a bare read of that name is refused after the pass as without it (#32521)

Clause-②: no (narrowing) — on a host that wires a `DatabaseLoader` (none in the workspace), after the boot priming pass (`MetadataPlugin`'s eager bootstrap) a read naming no package (`MetadataManager.get`, `getDiagnosed`) of an `api`, `agent`, `skill`, `action`, `permission`, `flow`, `picklist`, `mapping` or `dataset` whose name two packages' stored rows hold is refused `409 RESOURCE_CONFLICT` (`ambiguous-in-environment`, naming both), where it served the body of the row saved last; the same read without the pass already refused. Beside a package-less row of that name saved last, a read naming a package that holds none of its rows answers nothing, as without the pass, where it served that row. The runtime's bare `/actions` door is refused the same way (below). For `flow`, two readers past objectql's start-up sync narrow too (below): objectql's package-scoped resolver refuses the bare name naming both, where it resolved the row saved last, and the automation boot pull arms neither flow of the name, with a warning, where it armed that row's. The other moved answers hand on, register or warn about more holders and refuse nothing.
Metadata-protocol: none

**BREAKING** for one kind of host, at three faces: a host that wires a `DatabaseLoader` and, after the boot, reads with no package a name two packages hold now gets `409` naming both instead of one package's item; on such a host objectql's resolver refuses a bare `flow` name two packages' rows hold, and the automation engine arms neither flow of it, so a flow that dispatched after a boot stops dispatching (a warning names both). Name the package that holds it, or rename one of the two. Nothing in the workspace wires the loader.

What moves, for every unbundled type in `PACKAGE_SLOTTED_STORE_TYPES` (at this release nine: `api`, `agent`, `skill`, `action`, `permission`, `flow`, `picklist`, `mapping`, `dataset`), and only for a name two or more packages' stored rows hold. `email_template` (bundled) already answered every row and is unchanged.

- `DatabaseLoader.loadMany` and `loadManyKeyed`: a name two or more packages' rows hold answers one row per `(package, name)` — the key `MetadataManager`'s plural reads keep one entry per since #32517 — each the row saved last of its package (its highest version), FROM one row per name, the row saved last. `loadManyKeyed` entries carry each row's package. One package's action bound to several objects is still one row, the binding saved last. `load` and `list` still answer one per name.
- `MetadataManager.loadMany` stamps each body of a name a loader's keyed read holds for two or more packages with the package of the keyed entry whose own body it is (the same content, each entry once), FROM unstamped (#32458's stamp names one holder per name only). Only where that loader's bodies of the name are exactly its rows keyed by it; otherwise none is stamped, so no body takes a package its row is not bound to. With both holders stamped, `MetadataManager.loadMany` / `loadManyKeyed` hand on both (one item per `(package, name)`, #32517), FROM the row saved last alone.
- The boot priming pass registers the items a package holds first, then the ones no package holds. With two holders it fills each package's slot, FROM the slot of the row saved last alone. After the pass a bare read is refused as above; a read naming the other package answers that package's body from its registered slot, stamped with its package, FROM its row read through the loaders unstamped; `list` keeps both, FROM the row saved last alone for rows bound by the `package_id` column only. A package-less row beside the two stays the environment's own item, on any host: the pass does not stamp a package-less stored row with the host's declared package (ADR-0150 D4 makes a package-less item a holder's customization under a name one package holds only), so it holds the name's bare slot and `list` keeps it, a read naming either holder answers that holder's own body and a read naming a package that holds none answers nothing, all as without the pass, FROM the row saved last alone in the registry (when that is the package-less one, filed into the host's slot on a host that declares a package, and answering a read naming a package with no slot of its own). The host's own file item of such a name keeps the host's stamp, as before: it fills the host's slot and its row, over a row an earlier boot seeded from it.
- Callers of `MetadataManager.loadMany('action')` and `loadManyKeyed('action')` on such a host. The runtime's bare `/actions/:object/:action` door, when no protocol merged listing serves (`collectActionDeclarations` over the metadata service), sees both packages' declarations of a name and answers `pickActionHolder`'s refusal naming both (`409`), FROM serving the one declaration that reached it. objectql's authored-action rebind keys `object:name` with no package and keeps the one later in the read's order, then its own read of every authored row, as before. objectql's action audit (`loadManyKeyed`) counts each package's declaration, FROM one.
- objectql's start-up sync (`loadMetadataFromService`) reads `loadMany('flow')` on such a host: both packages' flow of one name reach `registerItem`, each under its own package, so the ObjectQL registry lists both, FROM the row saved last alone (registered under its package). Three readers of that registry move:
  - objectql's package-scoped resolver (`resolvePackageScopedName`, which the automation engine asks through `flowNameResolver`), asked for the bare name by a caller with no package: refused `ambiguous-in-environment` naming both, FROM resolved to the row saved last. A narrowing.
  - The automation plugin's boot pull (`listItems('flow')`, `resolveFlowPrecedence`, `registerFlow`): arms neither flow; the precedence warns once that it arms neither, and `registerFlow` refuses the body with a warning naming both, FROM arming the row saved last. A narrowing: a flow that dispatched after a boot stops dispatching.
  - The registry's own lookup, `SchemaRegistry.getItem('flow', name)`: with no package, the first holder registered (the row the store returned first), FROM the row saved last, the only one; naming the package whose row was not saved last, that package's own flow, FROM the other package's. Beside a package-less row of the name saved last, the package-less flow still answers every such read, and both packages' flows are registered beside it, FROM the package-less flow alone. No production reader reaches it with two holders on a host that wires the metadata service: the bare item read answers through its package-scoped read first, the layered read and the credential carry-forward ask the metadata service first (which refuses the name `409`), and every other caller reads another type or names a package.
  The cold-boot bare-name seal then sees the name held twice and warns once naming both (`'warn'` mode), FROM no warning, but only where the two holders meet under the bare-name rule: `flow` is narrowed to the namespace, so two installed packages that declare two different namespaces get no warning, while the resolver still refuses the bare name. objectql's other synced types (`object`, `view`, `app`, `hook`) are not stored per package and do not move, and the hook binder does not either.

Not changed: a name no package or one package holds. A package-less row beside one package's row is that holder's customization (ADR-0150 D4), never a second holder: the plural reads still hand on one item for it (the row saved last; the earlier loader's across loaders), and every read after the pass answers what it answered, whatever package the host declares. This entry replaces the closing "Not changed" paragraph of #32458's entry: the boot pass no longer primes one row per name of a name two packages hold.
