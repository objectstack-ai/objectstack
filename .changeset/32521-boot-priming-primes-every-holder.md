fix(metadata)!: the boot priming pass primes every holder of a name two packages hold, of a type stored per `(package, name)`, so a bare read of that name is refused after the pass as without it (#32521)

Clause-②: no (narrowing) — on a host that wires a `DatabaseLoader` (none in the workspace), after the boot priming pass (`MetadataPlugin`'s eager bootstrap) a read naming no package (`MetadataManager.get`, `getDiagnosed`) of an `api`, `agent`, `skill`, `action` or `permission` whose name two packages' stored rows hold is refused `409 RESOURCE_CONFLICT` (`ambiguous-in-environment`, naming both), where it served the body of the row saved last; the same read without the pass already refused. Beside a package-less row of that name saved last, a read naming a package that holds none of its rows answers nothing, as without the pass, where it served that row. The runtime's bare `/actions` door is refused the same way (below). The other moved answers hand on or register more holders and refuse nothing.
Metadata-protocol: none

<!-- adr-0087: not-required (no-migration-prescription) No key of any schema is added, removed, renamed or re-shaped, and no stored row changes: what moves is how many of a name's stored rows a plural read hands on and the boot pass registers, which no stored row records, so there is nothing for `objectstack migrate meta` to rewrite. -->

**BREAKING** for one caller: a host that wires a `DatabaseLoader` and, after the boot, reads with no package a name two packages hold now gets `409` naming both instead of one package's item. Name the package that holds it. Nothing in the workspace wires the loader.

What moves, for `api`, `agent`, `skill`, `action` and `permission` (the unbundled members of `PACKAGE_SLOTTED_STORE_TYPES`), and only for a name two or more packages hold. `email_template` (bundled) already answered every row and is unchanged.

- `DatabaseLoader.loadMany` and `loadManyKeyed`: a name two or more packages' rows hold answers one row per `(package, name)`, each slot's row saved last (its highest version), FROM one row per name, the row saved last. `loadManyKeyed` entries carry each row's package. `load` and `list` still answer one per name.
- `MetadataManager.loadMany` stamps each body of a name a loader's keyed read holds for two or more packages with the package of the keyed entry whose own body it is (the same content, each entry once), FROM unstamped (#32458's stamp names one holder per name only). Only where that loader's bodies of the name are exactly its rows keyed by it; otherwise none is stamped, so no body takes a package its row is not bound to.
- `MetadataManager.loadMany` and `loadManyKeyed`: a name two or more packages hold across every loader keeps one item per store slot (the package and the slot identity, which for an object-bound action is its object and name), an earlier loader's item kept over a later loader's item of the same slot, FROM one per `body.name`. So such a name is two items, and an earlier loader's item no longer hides a later loader's item of another package.
- The boot priming pass registers the items a package holds first, then the ones no package holds. With two holders it fills each package's slot, FROM the slot of the row saved last alone. After the pass a bare read is refused as above; a read naming the other package answers that package's body from its registered slot, stamped with its package, FROM its row read through the loaders unstamped; `list` keeps both, FROM the row saved last alone for rows bound by the `package_id` column only. A package-less row beside the two stays the environment's own item, on any host: the pass does not stamp a package-less stored row with the host's declared package (ADR-0150 D4 makes a package-less item a holder's customization under a name one package holds only), so it holds the name's bare slot and `list` keeps it, a read naming either holder answers that holder's own body and a read naming a package that holds none answers nothing, all as without the pass, FROM the row saved last alone in the registry (when that is the package-less one, filed into the host's slot on a host that declares a package, and answering a read naming a package with no slot of its own). The host's own file item of such a name keeps the host's stamp, as before: it fills the host's slot and its row, over a row an earlier boot seeded from it.
- Callers of `MetadataManager.loadMany('action')` and `loadManyKeyed('action')` on such a host. The runtime's bare `/actions/:object/:action` door, when no protocol merged listing serves (`collectActionDeclarations` over the metadata service), sees both packages' declarations of a name and answers `pickActionHolder`'s refusal naming both (`409`), FROM serving the one declaration that reached it. objectql's authored-action rebind keys `object:name` with no package and keeps the one later in the read's order, then its own read of every authored row, as before. objectql's action audit (`loadManyKeyed`) counts each package's declaration, FROM one. objectql's `loadMetadataFromService` (`object`, `view`, `app`, `flow`, `hook`) and the hook binder read no type stored per package and do not move.

Not changed: a name no package or one package holds. A package-less row beside one package's row is that holder's customization (ADR-0150 D4), never a second holder: the plural reads still hand on one item for it (the row saved last; the earlier loader's across loaders), and every read after the pass answers what it answered, whatever package the host declares. `MemoryLoader`'s own `loadMany` and `loadManyKeyed` still answer one item per name (covered by #32517). This entry replaces the closing "Not changed" paragraph of #32458's entry: the boot pass no longer primes one row per name of a name two packages hold.
