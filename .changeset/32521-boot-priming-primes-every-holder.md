fix(metadata)!: the boot priming pass primes every holder of a name of a type stored per `(package, name)`, so a bare read of a name two packages hold is refused after it as without it (#32521)

Clause-②: no (narrowing) — on a host that wires a `DatabaseLoader` (none in the workspace), after the boot priming pass (`MetadataPlugin`'s eager bootstrap) a read naming no package (`MetadataManager.get`, `getDiagnosed`) of an `api`, `agent`, `skill`, `action` or `permission` whose name two packages' stored rows hold is refused `409 RESOURCE_CONFLICT` (`ambiguous-in-environment`, naming both), where it served the body of the row saved last; the same read without the pass already refused. **BREAKING** for one caller: a host that wires a `DatabaseLoader` and, after the boot, reads with no package a name two packages hold now gets `409` naming both instead of one package's item. Name the package that holds it. Nothing in the workspace wires the loader.

What moves, for `api`, `agent`, `skill`, `action` and `permission` (the unbundled members of `PACKAGE_SLOTTED_STORE_TYPES`). `email_template` (bundled) already answered every row and is unchanged.

- `DatabaseLoader.loadMany` and `loadManyKeyed` answer one row per `(package, name)`, each slot's row saved last (its highest version), FROM one row per name, the row saved last. `loadManyKeyed` entries carry each row's package. `load` and `list` still answer one per name.
- `MetadataManager.loadMany` and `loadManyKeyed` keep one item per store slot (the package and the slot identity, which for an object-bound action is its object and name), an earlier loader's item kept over a later loader's item of the same slot, FROM one per `body.name`. So a name two packages hold is two items, and an earlier loader's item no longer hides a later loader's item of another slot of the name.
- The boot priming pass registers every item `loadMany` hands on, the ones that hold no package first. With two holders it fills each package's slot, FROM the slot of the row saved last alone. After the pass a bare read is refused as above; a read naming the other package answers that package's body from its registered slot, stamped with its package, FROM its row read through the loaders unstamped; `list` keeps both, FROM the row saved last alone for rows bound by the `package_id` column only. With one holder nothing moves: the bare read answers it.
- A package-less row beside one package's row of a name: the pass registers the package-less item first, so the package's item takes that slot over and the reads answer what they answer without the pass (the package's item), FROM the row saved last (the package-less body, filed into the package's slot when it came last). On a host that declares its package (`MetadataPlugin`'s `packageId`), the pass stamps the package-less item with the host's package, as before; registered beside the other package's item, a bare read is refused naming both, FROM the row saved last. Rows of these shapes are not written by `DatabaseLoader.save`.
- Callers of `MetadataManager.loadMany('action')` and `loadManyKeyed('action')` on such a host. The runtime's bare `/actions/:object/:action` door, when no protocol merged listing serves (`collectActionDeclarations` over the metadata service), sees both packages' declarations of a name and answers `pickActionHolder`'s refusal naming both (`409`), FROM serving the one saved last. objectql's authored-action rebind keys `object:name` with no package and keeps the one later in the read's order, then its own read of every authored row, as before, FROM the one saved last. objectql's action audit (`loadManyKeyed`) counts each package's declaration, FROM one. objectql's `loadMetadataFromService` (`object`, `view`, `app`, `flow`, `hook`) and the hook binder read no type stored per package and do not move.

Not changed: `MemoryLoader` (the artifact door's store) still answers one item per name from its `loadMany` and `loadManyKeyed` for these types. This entry replaces the closing "Not changed" paragraph of #32458's entry: the boot pass no longer primes one row per name.
