fix(spec, runtime): `composeStacks` admits two packages' object-less action of one name from two namespaces under `manifest: 'preserve'`, as install does, and the boot registers each package's actions under that package (ADR-0150 D4)

Clause-②: yes (widening) — `composeStacks([a, b], { manifest: 'preserve' })` no longer refuses `STACK_COMPOSE_ACTION_KEY_COLLISION` when two packages of two different namespaces each declare one object-less action of a name: each body stays under its own package, as installing the two one by one already admits. A multi-package artifact's action handlers are now registered under the package that declares each, where they were all registered under the artifact's own id, so a package-qualified call (`POST /actions/NS/global/NAME`, `executeAction` with `packageId`) reaches the actions of a package other than the artifact's own id: measured on an object-less action, it answered `404` before. Measured first-party: 0 (the one first-party composition, `examples/app-multi-package`, declares no action).
Metadata-protocol: none

- **Compose.** Under `manifest: 'preserve'`, an object-less action key declared by two or more input stacks is admitted when each stack is one package (a `manifest` with an `id` and no `packages` list of its own), no two are one package, and no two meet under the install gate's namespace rule: both declare a namespace and the two differ. The rule's namespace half is one function, `namespacedHoldersMeet` (`@objectstack/spec/kernel`), which the install gate's `bareNameHoldersMeet` (`@objectstack/objectql`) now calls too. Still refused, as before: the same pair under the default manifest (`'last'`, `'first'`, an index), where package identity is lost (the refusal now adds one sentence naming `manifest: 'preserve'` as the way to keep both); two packages of one namespace; two bodies of one package; a package with no namespace; and every object-bound key.
- **Boot and install.** `bindAppArtifactHandlers` (used by `AppPlugin` and by the install-local door, `MarketplaceInstallLocal`, on install and rehydrate) binds what a bundle carrying `packages[]` reconciles to (nothing a composition replaced) and registers each action whose key one body carries under that body's package, `app:PACKAGE_ID`. A key two bodies carry stays one handler under the artifact's owner, as before, except the object-less pair of two namespaces, which each body binds under its own package. An action the top level carries and no body declares stays under the artifact's owner. A re-bind tears down every package owner the previous bind of that artifact registered, so a package body the new bundle drops stops running. A bundle with no `packages[]` binds exactly as before. In the booted pair, `POST /actions/alpha/global/NAME` and `/actions/beta/global/NAME` each run their own body, and the bare `POST /actions/global/NAME` answers `409 RESOURCE_CONFLICT` naming both packages. `listRegisteredActions()` reports such a handler's `package` as its own package's owner (`app:PACKAGE_ID`), where it reported the artifact's. Hooks and functions stay under the artifact's owner.
