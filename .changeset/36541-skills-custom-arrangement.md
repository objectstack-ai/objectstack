The `objectstack-data` skill teaches the whole-arrangement keys of the paired `.custom` package's object extension:

- Object Extension Model: only the object extension of a base's paired `.custom` package may write `fieldGroups` and `relatedLists`, in the shape an object declares them. A written key replaces that arrangement whole (the owner's and every `place`); an unlisted field shows after the last group, an unnamed tab still shows after the listed ones, and `{ list: 'crm_note', hidden: true }` hides a tab. In any other package both keys are refused at save, publish and install and by `os validate` / `os build`, with the prescription to use `place`.
- Eval: a new `objectstack-data` case moves an installed object's tab arrangement from an add-on package's extension, where it is refused, to the pair's extension, and names `place` as what the add-on package writes. The `place` case no longer says an extension has neither key.
