# 立卡门与定级判据

见 SKILL.md 〈分诊座位职责〉与〈平台读数纪律〉的指针行;本文是「什么才算一张卡」与
定级、读数三组判据的执行说明。

## 立卡门

出处 —— 维护者 2026-09-21 逐字,不译:

> 刚才 os-sam 又被封号了,也是因为分诊批量处理issue的时候,所以现在 issue 太多对于车队是负担。 19546 我希望在创建issue 的环节就卡死,没必要的issue就不要创建。

- 立卡只为四类,正文首行写出类别字母;⛔ 其余一律不立卡,不论它叫什么。
- (a) 有具名落点或复现的产品缺陷,即 `pm:queue` 的定义。
- (b) 只有维护者能做的决定,落卡即带「维护者速读」与四棱块。
- (c) 维护者直派的任务,正文引其原话。
- (d) 协调节点:跨仓/跨层父单与它的逐层子单。
- ⛔ 不是卡:仪器误报与门禁假读数 —— 既不派 dev,今亦不立卡。
- ⛔ 不是卡:席位自己的失误、协议观察与「记住这条」,它们进座位贴或收班简报。
- ⛔ 不是卡:三类外的 `finding` —— 原为首触即关,今门前即拒。
- ⛔ 不是卡:丢卡重建,除非它自身即 (a)–(d)。
- ⛔ 不是卡:既有卡一条评论能承载的指针/知会/请求 —— 评论是加速器不是记录。
- ⛔ 不是卡:sweep 每 fire 重导的 pin/bump/卫生提醒。
- 每次 POST 之前正文答三件:类别字母、动手的读者(哪个席位哪一步)、查重词与命中数。
- 缺任一件的卡由分诊首触即关、不定级,关单一行点名缺的是哪一件。
- 「动手的读者」与 Acceptance notes 同一问:说得出具体 PR 或人 ⇒ 写进去,说不出 ⇒ 不立卡。
- 配额:一席每 fire 至多立三张;sweep 超出的折进一张带清单的卡,或折进座位贴。
- 分诊席的存量清理仍走维护者确认的十张一组,⛔ 不因本门改批量。
- 写节奏 ⛔ 非可选:REST 写(评论/标签/关单/立卡)间隔 ≥3 秒,每账号每小时 ≤40 笔。
- 收到 429 或次级限流 ⇒ 该席本 fire 停写,并把停写记在座位贴上。
- 关单 ⛔ 永不由脚本循环连发:须维护者确认的分组,且逐笔之间留间隔。

## 定级判据(北极星「优先级」的执行说明)

- 假绿另有条款:绿线被读作「已核对」而实际没核对 ⇒ 一次人眼捕获即一次实测代价。
- 「仪器为车队服务」的四种答案 ⛔ 不压成两条;假红的标准代价形态是席位顺从它。
- 点名一次被假红占住的席位动作(具名那张卡),与点名一次派错/落不了同等成立。
- 沿链继承只给上界,界内哪格由失效形态定:墙齐平,税降一格;可重入队的 PR 是税。
- 北极星第 4 条只认出货面(`skills/**`、产品文档),⛔ 不含 `.claude/**` 内部协议。
- 它认的是一句说错的话,⛔ 不是一句缺席的话;缺句按覆盖不足走北极星第 2 条。

## 读数判据(判据的可达半径与零)

- 判据有可达半径:半径内(本仓 CI、席位动作、run record)测出的零是真的零。
- 半径外 = 出货给第三方的面:`packages/*/dist`、`.d.ts`、`content/docs/**`、`skills/**`、墓碑处方。
- 半径外含拒绝消息、CHANGELOG 与协议的接受/拒绝行为;「点不出受害者」⛔ 不是证据。
- 判据是「它对不对」,错 ⇒ 留;`packages/spec` 的「辅助面」⛔ 不蕴含「可关」。
- 落点在半径内 ⛔ 不蕴含所护的在内:追「它最终护的是谁」⛔ 不追它住在哪个目录。
- 零成读数须三件全立:① 同主体必中词证总体可达;② 探针问的是契约里真有的键/位置。
- ③ 这个总体就是该现象会出现的地方;缺任一件,那个零只是探针的自画像。
- 「某目录里没有 X」前先读其 README 与 `.gitignore`:被 ignore 的目录是约定 ⛔ 不是空集。
- 前缀匹配 ⛔ 不是精确匹配:同族别名会撑满前缀,命中数与零一样会骗人。
- 全板枚举每 fire 至多一次,⛔ 不反复实扫;统计走 `board-archive` 离线做,巡查按日。
