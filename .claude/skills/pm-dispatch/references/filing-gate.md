# 立卡门与定级判据

## 立卡门

> 出处,维护者 2026-09-21 逐字不译:刚才 os-sam 又被封号了,也是因为分诊批量处理issue的时候,所以现在 issue 太多对于车队是负担。 19546 我希望在创建issue 的环节就卡死,没必要的issue就不要创建。
> 之前封号的时候讨论过 issue 和 pr 应该使用 claude app 创建,名称应该是 claude(bot)

- 立卡只为四类,正文首行写立卡门类别 ①–④;⛔ 其余一律不立卡,不论它叫什么。
- 首行并写 `Source: maintainer | topic #N | fleet`:`maintainer` = 维护者自立,或引其原话带链接;
  `topic` = 他开或确认的专题子卡;余与无正面证据者皆 `fleet`;测试 agent 立卡亦带座位签名。
- ① 有具名落点或复现的产品缺陷,即 `pm:queue` 的定义;其内的 `finding` 限三类且带 `reach:`。
- ① 含用户可见的体验缺陷,与功能缺陷同等:界面上稳定复现、落点具名、预期不凭审美。
- ⛔ 不是卡:纯审美偏好、重设计与新功能提议(立 `Feature`)、无用户可见代价的性能观察。
- 判例:仪表盘刷新按钮独占一行、首屏白占约 120px ⇒ 立;「配色换个好看的」⇒ 不立。
- `reach:` 二选一:公开入口(HTTP/界面/`os validate`/保存)实测一次错误结果;或具名真实生产者。
- 两种例外照立,要点首条「先测可达性」:发版固化的错误文字;维护者直派。
- ⛔ 不经本门:安全发现(含可能泄露数据),不论多确凿;去向只照 `security-findings.md`。
- ② 只有维护者能做的决定,落卡带「维护者速读」与四棱块;车队 `Feature` 归此,免决策箱。
- ③ 维护者直派的任务,正文引其原话;④ 跨仓/跨层协调父单(`tracking`,非 `pm:epic`)及子单。
- 增改 pm 规则的卡只在维护者点名时立(归 ③,正文引点名原话);⛔ 席位自提不立。
- 新接口/协议键/元数据类型/审计种类/新能力另立 `Feature` 卡,⛔ 不作 `Bug` 选项,分诊拆。
- ⛔ 不是卡:在建功能(码未合并)的问题,在该功能的卡与 PR 里修;合并后发现的才立 `Bug`。
- 车队立的同专题卡只在改同一文件时互挡(判据同区租约重叠检查);次序偏好列在专题卡。
- 挡路卡只挡本卡一部分 ⇒ 把要等的部分拆成单卡挂 `Blocked-by:`,其余照常排队。
- ⛔ 当前值(冻结、暂停、重点、只做 p1、并发)不进技能,只住座位贴与项目记忆;
  单卡裁决只住该卡;唯常设规则进技能,须维护者明言长期有效或由他合并该规则 PR。
- 技能 PR 正文逐条引来源;引文读作临时(先/暂时/这次/现在)或只对一席说 ⇒ L1、L2 退回。
- 卡号、评论 id 与带日期的引文 ⛔ 不进技能正文;规则的出处只住落地它的 PR。
- ⛔ 不是卡:席位自己的失误、协议观察与「记住这条」,它们进座位贴或收班简报。
- 「搭下个碰 X 的 PR」不算 `carrier:`;已落地工作欠的后续照立卡,⛔ 不按「不是卡」压下。
- ⛔ 不是卡:丢卡重建(除非自身即 ①–④)、sweep 每 fire 重导的 pin/bump/卫生提醒。
- ⛔ 不是卡:既有卡一条评论能承载的指针/知会/请求;那条评论即其记录。
- UI 卡写明所需通用块或 spec 契约门;要产品命名 widget/dialog/hook/命名空间的卡退回重立。
- POST 前正文答四件:类别、业务理由、动手的读者(哪席哪步)、查重查询与命中数(含已关)。
- 车队立的卡(席位、代立发现、清单、分诊)建卡带 area、type、级与正文定级行,缺一拒收。
- 维护者或外部人立的卡由分诊首触补齐 area 与 type;人定的级 ⛔ 不改,分诊与各席同此。
- 改级前读现级末次 `labeled` 事件:带 `performed_via_github_app` 或 bot actor 才算车队,余人定。
- 对人定的级有异议 ⇒ 只在卡上评论一行理由;级与卡的状态 ⛔ 不动。
- 业务理由:谁受益、什么场景、不做会怎样;③ 以原话代,④ 承父单;分诊 ⛔ 不代写。
- 清楚且合北极星方向 ⇒ 照常定级入队;与「What gets built」不符或无受益者 = 站不住。
- 缺失或站不住 ⇒ `Triage: returned` 退回立卡人,留 `finding`,改后再读;⛔ 不代写不关卡。
- 涉及产品取舍或方向不明 ⇒ 入决策箱,先过天花板档决策线程;⛔ 不替维护者判需求。
- 批量立卡(一次 ≥10 张):审计评论带 `Batch-of:` 行,总监席每源抽 ≤5 张呈维护者过目。
- 缺件卡由分诊(单车道仓 `repo:*` 席)首触补齐卡与一次检索可推三件,写进定级评论并定级。
- 补不齐(四类皆非)者才因缺件首触即关 not_planned,一行点名所缺。
- 「动手的读者」与 Acceptance notes 同一问:说得出具体 PR 或人 ⇒ 写进去,说不出 ⇒ 不立卡。
- 说不出的形态:`.changeset/*`、无人在改的文档页、生成物、已扫完的批次,兜底不成立。
- 配额:每 fire 不限张数,逐缺陷各立一张、各过本门;折清单卡可选、不强制;守批量写间隔。
- 例外:L1/L2 后续(nit/接受的偏差/同车道 diff 外发现)每 PR 一卡 `review follow-ups of PR #N` 逐项勾,
  后轮追加 ⛔ 不另立;① 缺陷仍各立;p3 文案/文档 nit 入该区 `<area> loose ends` 卡,无则才立。
- L1/L2 立卡前搜 open 卡 `PR #N` 与文件路径,同一发现追加;技能/ADR 文本卡照 `triage-duties.md`。
- 分诊席的存量清理仍走维护者确认的十张一组、只备下一组,⛔ 不因本门改批量。
- 读到 `User` ⇒ 记座位贴、本 fire ⛔ 不立新卡;认领仍靠 assignee,署名仍是文本的 session ID。

## 定级判据(北极星「Priority」的执行说明)

- 表 ⛔ 本文不抄:本仓照北极星(大专题、核心功能与界线在「Product areas」,Bug 表、安全表
  与补充规则在「Priority」第 2 条);cloud 以其仓 `docs/strategy/core-functions.md` 为准,两步同此。
- 第一步先判仓库(病根在平台 ⇒ 在 objectstack 修),再定 `area:*` 与 issue type(定义见第 2 条)。
- type 逐卡定不随专题;`pm:epic`/`tracking` 卡不带 type;运维、验证与维护者动作卡 ⇒ `Task`。
- 第二步定级照第 2 条:只有 `Bug` 与安全卡查表;`fleet` 源 `Feature`(含体验类)定 p3。
- 「具名客户」只指真实外部用户,定级评论写谁说了什么;测试 agent 自建应用的需求不算。
- 读码得出且写明机制的发现与实测者同按表定级;⛔ 无证据上限。
- 清单项会 fail、标题断言该能力而 steps 到不了(补步骤)、无项断言(补账本):一律查表,
  核心功能 ⇒ 断;⛔ 不继承清单项的 `priority`。
- 清单断言缺陷(产品对、清单错)按 p2 修;发版窗内挡验收判定者,被挡卡 `Blocked-by:` 指它。
  「平台测试清单反复变红，肯定要修啊」(维护者)。
- 挡路卡取自身与所挡 open 卡里最高的级,同仓跨仓同,`Feature` 亦然;余「有人在等」不升级。
- p0 照北极星;发版阻塞卡只在发版窗内升 p0(⛔ 不打 `target:`),发版后回查表所得的级。
- 定级行:`area · type · severity · reach · evidence (measured or read)`;公开卡 ⛔ 不写安全机制。
- 假绿(仪器):绿线被读作「已核对」而实际没核对 ⇒ 一次人眼捕获即一次实测代价。
- 「Instruments serve the fleet」的四种答案 ⛔ 不压成两条;假红的标准代价形态是席位顺从它。
- 北极星「Priority」第 4 条只认出货面(`skills/**`、产品文档)说错的话,⛔ 不含 `.claude/**`。

## 读数判据(判据的可达半径与零)

- 判据有可达半径:半径内(本仓 CI、席位动作、run record)测出的零是真的零。
- 半径外 = 出货给第三方的面:`packages/*/dist`、`.d.ts`、`content/docs/**`、`skills/**`、墓碑处方。
- 半径外含拒绝消息、CHANGELOG 与协议的接受/拒绝行为;「点不出受害者」⛔ 不是证据。
- 判据是「它对不对」,错 ⇒ 留;`packages/spec` 的「辅助面」⛔ 不蕴含「可关」。
- 落点在半径内 ⛔ 不蕴含所护的在内:追「它最终护的是谁」⛔ 不追它住在哪个目录。
- 零成读数须三件全立:① 同主体必中词证总体可达;② 探针问的是契约里真有的键/位置。
- ③ 这个总体就是该现象会出现的地方;缺任一件,那个零只是探针的自画像。
- 「某目录里没有 X」前先读其 README 与 `.gitignore`:被 ignore 的目录是约定 ⛔ 不是空集。
- 前缀匹配 ⛔ 不是精确匹配:同族别名会撑满前缀,命中数与零一样会骗人。
- 全板枚举每 fire 至多一次,⛔ 不反复实扫;统计走 `board-archive` 离线做,巡查按日。
