# 座位贴协议细则

见 SKILL.md 〈座位贴协议〉;本文是接管、移交、回收那一刻要查的协议细则。

## 贴的四段与派生视图

- 四段的现值由在任座位在写侧刷新时收缩;⛔ 岗位说明 PR 不代改贴正文。
- 标题即状态板,固定格式 `[PM seat] <座位名> — <状态>`;`label:pm:seat` 列表页即舰队状态板。
- 状态词表:`🟢 <github-login>` 在任、`🟢 Routine`、`⏳ vacant`、`⏸️ paused`。
- assignee = 在任 PM 的 GitHub 账号,退场或回收时摘除;无 assignee = 空缺,与标题互为校验。
- 例外:Routine 座位的 bot 身份通常不可被 assign,以标题为准。
- 多场席(总监):`🟢` 后写召唤账号,状态块逐场一行(会话 ID + 锚);无在任者、无接管。
- 当前 PM 段登记三元:GitHub 账号(`get_me` 自查)、会话 ID 或 Routine ID、上任时刻。
- 审计与认领评论的作者字段是平台盖章的硬读数,接管仲裁与活性判定优先用它对账正文。
- 班次叙事 ⛔ 不进贴正文:逐卡状态在卡与 PR 上必填,轮次合计走轮次报告。
- 接管压缩:接任 PM 把交接的有效内容按四段模板重述为新正文,编辑历史即存档。
- 旧账留在上一版 body revision,审计评论带版本指针(哪一版、何时)。
- 超大贴由半状态巡查的 report-only 项浮出,⛔ 不等读取失败。
- 热文件串行队是跨轮跨班次的常设事实:文件 → 有序卡片清单 → 每张卡认领的区域。
- 新增座位贴(拆域)先查 `pm:seat` 索引再立贴。

## 活性、写侧刷新与收班

- 活性惰性半边在接管冲突时评估一次:Routine 座位查调度器 `last_fired` 与 `next_run`。
- 会话座位查最近一条产出评论的时间戳;回收 = 改正文 + 审计评论。
- 常设半边是分诊轮的座位贴活性巡查,同一判据,细则见 `dispatch-runbook.md`。
- 可跑读法:本车道 `pm:dispatched` 卡按 `updated_at` 降序一搜,或读最近一条认领评论。
- 写侧刷新点的三个时刻:派发时、收班时、暂停或交接前。
- 协议升级迁移状态、或巡检发现正文不符时,当场改正文 + 审计评论。
- Routine 座位的收尾简报也落自己的座位贴,它是下一轮自退守卫的读数。
- 安置默认离任留守;留不了才热移交:在飞卡落收单注记 + 点名看护者。
- 收单注记写评审判据、落地步骤与当前状态;看护只守落地,⛔ 评审判断不可外包。
- 看护者默认下任座位;在跑云会话经 poke 触发器投递,⛔ 非 `SendMessage` 直投。
- 收班序列:贴正文与标题刷新在先,简报评论是最终一笔;继任的释放判据 = 简报在。
- 标题滞后是可修半状态,坐席时顺手修,⛔ 不是阻塞。
- 留守写面恰为简报点名的项:已 ACCEPT 待队列 PR、落地中的评审链载体;残余定时器同界。
- 末尾巴合并 ⇒ 贴上一条尾清注记;继任立即坐席,点名集作围栏。
- 标题词表不扩,收班座位恒 `⏳ vacant`;留守登记(谁、哪些尾巴)= 说明段一行。

## 交接收尾清单(漏一步就是留残缺现场)

1. 立即停止新派发。
2. 在手工件逐件处置:能收则收,收不完留守或热移交;⛔ 不为清零而等。
3. 全量枚举本车道队列、决策箱与 findings,形成接任台账。
4. 贴正文改 `⏳ vacant` + 台账:前任会话 ID、注销时间、队列快照、串行队、跨车道备忘。
5. 收班简报与审计评论存档;接任指引 = `/pm-dispatch 接手` + 先读座位贴。
6. `list_triggers` 清点本会话全部自设定时器,逐个清理或随移交物转交。
7. 移交中 PR 的定时器随 PR 走;留守保留的定时器只触点名项。
8. 本座位派出的 dev 会话由离任 PM 自己逐个 `archive_session`,归档义务 ⛔ 不可移交。
9. 确须留跑的会话在座位贴里点名,写明归档不随交接转移,⛔ 不留作接任者的欠账。
10. 向维护者交最终报告。

- 会话句柄是账号作用域的,细则见 `dispatch-runbook.md`。

## 座位 Routine 创建

- 由维护者在 claude.ai 的 Routines UI 创建,凭据随 Routine 所挂 repo sources 走。
- Routines UI 并无 GitHub 连接器入口。
- 会话内 `create_trigger` 的 fresh-session Routine 不挂 repo sources,拿不到 GitHub 工具。
- 表现为静默零产出;⛔ 不要在会话里 `create_trigger` 出一个座位 Routine 就当它在跑。
- 模型不能经 API 钉住,同样在 UI 钉;Routine 继承环境默认模型,环境默认变了它跟着变。
- 创建后先手动 fire 一轮烟测,判据取 GitHub 上的产出:标签写入、审计评论、座位贴编辑。
- ⛔ 不取会话看起来起来了;零产出即技术性失败。
- 回滚 = `delete_trigger` + 清空座位登记 + 失败注记。
- 档位按职责挑,⛔ 不按重要性挑;档位与 cron 是维护者在 UI 上的可调项。
- 协议文本 ⛔ 不复制其当前值,座位贴才是现状。

## Epic 车道收尾与僵尸回收

- 收尾四步一组,缺一步就是过夜半状态。
- 最后一个 sub-issue 关闭 → 父单留总结评论 → 关父单并摘 `pm:epic` → 领地段标注收官。
- 僵尸判据:父单正文有登记,但整棵子树 ~48h 无任何认领、分支或 PR 动静。
- 命中 ⇒ 分诊座位在父单评论询问,再静默一窗后摘 `pm:epic` 收回子树。
- 子树内仍在飞的认领按认领协议由原认领者跟完。
- 领地防撞是声明式的,不是机械保证;撞上由合并队列兜底。
- 领地声明越窄越诚实,越宽越要在父单正文里说明为什么。

## 发版板运维(`target:<major>`)

- 生产者:主仓归分诊座位,objectui 与 cloud 归各自整仓座位。
- 其余座位不打不摘,误判走上报;⛔ 三个生产者各扫各的 backlog。
- 消费者:维护者的发版清单 = 三仓三条查询 `label:target:<major> is:open`。
- 等价的 org 级搜索仅是备用写法;归零 = 可发版指三张板都空,单看主仓归零不是。
- ⛔ 不用姊妹仓命中即误标的旧读法:它教读者销毁真实阻塞的唯一证据。
- 鲜度:每 ~5 轮对板上 open 项做过时前提检查,已修或不成立的摘牌 + 一句评论。
- 发版时刻 = 清板不是重扫,板上每条三选一:修掉、摘牌、明示接受带病发布。
- 明示接受 = 摘标签 + accepted-for-GA 评论留痕,并进 release notes 的 known issues。
- 三仓各自执行、读数回贴;⛔ 不因前端仓或独立部署整批默认接受。
- 发版前置:清板动手之前先取一次 pin 读数,⛔ 一次即止不是重扫。
- pin 滞后 ⇒ console bump 单必须已存在且已上板,或按标准形态明示接受。
- 两者都不成立 ⇒ ⛔ 不 cut。
