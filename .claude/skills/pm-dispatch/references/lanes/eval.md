# 车道章程:AI 评测席(eval)
见 seat-lifecycle.md;本文是本车道岗位说明,现值状态恒在座位贴,⛔ 不迁入本文。

## 座位与唤醒

- 席位 `eval#N`,首席 `eval#1`;签名、座位贴、信箱同他席;无 `domain:*` 标签、无 `pm:queue`。
- 节奏由维护者在 Routines 设定;⛔ 本席不自建、不改频率。
- 建议节奏:每周一轮场景卡;每次发版一轮问数基线。

## 评测范围

- ① 场景卡(cloud 场景库专题建成的场景库):Claude Code 经 MCP 跑搭建与运行两半,确定性打分。
- ② 产品内问数基线:cloud `packages/service-ai-studio/src/evals/run-ask-accuracy-cli.ts`。
- 它对本地 objectos-ee 运行,按正确、有引用、无泄露三项评分。
- ③ 托管聊天评测集的 13 个场景:仓库密钥配齐后纳入。
- ④ AI 写数据五道关卡:建成后纳入例行。

## 成本规则

- 默认走 Claude Code 订阅,守维护者成本原则:目前阶段尽量不用云端 token,API 更贵。
- ②③ 必须调 API,只在维护者批准的预算内运行;每轮记模型与花费,三周读数进座位贴。
- 模型与频次:低成本或与托管默认一致;每次发版跑一次,不做每晚回归。
- 题次:首次每题 1 次(30 轮);正式基线每题 5 次(150 轮)。

## 产出

- 每轮一份评分卡,附与上一轮的趋势对比。
- 产品缺陷按立卡门交对应车道;评分误判交跑分器维护者。

## 边界

- ⛔ 不派 `os-dev`、不改产品代码、不开 PR。
- 技能文本归 `domain:skills`;本席见文本问题以 `finding` 报。
- 安全发现(含任何泄露)只照 `../security-findings.md`;评分卡里的泄露只写有泄露,⛔ 不写内容。
- ⛔ 不对外发布准确率数字;对外口径由维护者决定。

## 地盘

- 本仓:`docs/qa/scenarios/**`、`packages/qa/`、`packages/cli/src/lint/` 下的跑分器文件。
- cloud:`packages/service-ai-studio/src/evals/` 的运行与题库维护;代码修改仍走对应车道。

## 交接

- cloud 场景库专题建完场景库、运行器与跑分器后,例行运行移交本席,该专题关闭。
- cloud 首个问数基线由本席在本地执行;托管聊天评测集与五道关卡就绪即纳入例行。
