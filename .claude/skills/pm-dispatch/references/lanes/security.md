# 车道章程:安全席(security)

见 seat-lifecycle.md;本文是本车道岗位说明,现值状态恒在座位贴,⛔ 不迁入本文。
永不公开的规则只住 `../security-findings.md`(下文「第 N 节」皆指它),本文只指向、⛔ 不复述。
本文与座位贴不载任何发现、编号、路径、对象名或机制。

## 座位

- 席位 `security#N`,首席 `security#1`;签名、座位贴、坐席与收班同他席。
- 无 `domain:security` 标签、无 `pm:queue`、无文件面:私卡照第 3 节,修复落在归属包。
- 坐席者 = 能读写本仓安全公告的账号(管理员或安全经理)的会话;读不了公告 ⛔ 不坐。
- 公告的读、建与写只照第 3 节。

## 接收与台账

- 接收 ①:发现者的一次 `Notify: security · GHSA-ID`(私有仓 `#N`)门铃,私卡已由其经中继建好。
- 接收 ②:无门铃的 `triage` 公告(外报或中继实测):经 `advisory_read` 读,座位贴记 `received`。
- 判定:发现 ⇒ 中继 `advisory_state` 置 `draft` 走派修;非发现 ⇒ 置 `closed`,台账记非发现。
- 中继拒或本席空缺照第 3、9 节。
- 云席列不了本仓公告,中继也拒裸集合:编号只来自维护者、门铃或中继实测。
- 读出的公告明文只印本席进程 stdout(`--reveal`),⛔ 不进文件、日志或后台任务输出。
- 台账住座位贴,一份一行:不透明编号 · 会话 · 状态;⛔ 无细节;修复的认领只记台账。
- 状态词表:`received` → `fixing` → `merged` → `closed`;挑中发布再 `awaiting publish` → `published`。

## 派修与复核

- 修复照第 3 节派发;L/XL、build 重、长跑或浏览器验证走 `mode:cloud`,余 `mode:subagent`。
- 修复 PR 的契约复核归本席,照第 6 节;要定契约的修复交维护者前照下节。

## 呈维护者

- 任何问题呈维护者前,先由隔离 agent 以 `CONTRACT_REVIEW_TIER` 复核其分析;⛔ 不写模型名。
- 复核者只拿分析与证据,⛔ 不拿本席结论;核四轴、选项无漏、推荐成立、证据为真。
- 问题随附复核判词与全部异议。
- 每次发版前呈发布与否清单:上次发版后 `closed` 的公告,高危、中危在前;先经上条复核。
- 修复在版本 X 内,只当其合并提交是 X 打标提交的祖先(`git merge-base --is-ancestor`)。
- ⛔ 合并时刻早于打标时刻不是证据。
- 维护者批准即 `awaiting publish`;本席经中继发布即 `published`,照第 3 节;⛔ 不发清单外的。

## 收口(逐对象)

- PR 由合并队列合入;本席确认 MERGED 后照 `../landing-operations.md` 收口其卡。
- 公告:修复合入即经中继 `advisory_state` 置 `closed` 并记座位贴,⛔ 不逐份请示。
- 云卡:工作落地即由本席归档;子代理自行结束并删自己的 worktree。

## 误公开的卡(第 7 节)

- 本席照第 7 节接管;巡查自读公开仓 open 的 `security` 标签卡,标签即转交;私有仓的是私卡。
- 分诊即推维护者并转交本席(`triage.md`);`Notify: security · #N` 只为提速;本席空缺照第 7 节。

## 收班

- 台账与每份在飞公告留在座位贴,⛔ 不释放进 `pm:queue`;接任者坐席即接台账。
