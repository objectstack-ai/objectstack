## TL;DR

The platform already has a semantic layer. ADR-0021's `dataset` declares a base object, the relationships to include, named dimensions and named measures; `compileDataset` turns it into a Cube and `DatasetExecutor` runs it; every face of it passes one gate chain (API exposure → object read admission → field admission → read scope with tenant, RLS, controlled-by-parent and sharing folded in). Reports and dashboards take their numbers from it. **The AI does not.** Product AI (cloud's 问数) and external AI (MCP) both query objects directly and guess from keywords which field "营收" is, which is the drift ADR-0021 exists to end: the card's baseline is cloud#3578, 16 of 30 questions on the wrong object before its fix.

Two things are missing, and this record adds exactly those two:

1. **Business vocabulary on measures and dimensions** — `synonyms: string[]` (the words people use: 营收 → 收入, 销售额, revenue) and a `description` (one or two sentences of business definition: 「已赢单金额合计，按成交日期归月」). Today a member carries `label` only; `description` exists on the dataset alone and the schema says so in a guidance entry.
2. **Two tools, defined once, served twice** — `list_datasets` (the catalogue: datasets, members, vocabulary, and which of the caller's terms matched which member) and `query_dataset` (a `DatasetSelection` against a saved dataset, run through `IAnalyticsService.queryDataset` under the caller's `ExecutionContext`, answering rows **plus a provenance block naming the dataset and the measures used**). They are `AIToolDefinition`s with one executor in `@objectstack/service-analytics`; MCP registers them through the same optional-member bridge seam `aggregate_records` uses; cloud's service-ai registers the same definitions. One 口径, two transports.

The selection rule is deliberately small: a term that matches a measure's name, label or synonym **wins**; several matches → the AI asks, it does not pick; no match → the object query the AI runs today, with the answer's provenance saying no governed metric was used. The tools add no gate and bypass none — they are a fourth caller of `queryDataset`, not a fourth face — and the measurement in [Permissions](#d4--permissions-the-tools-add-no-gate-and-bypass-none) found no path that leaks, so no finding card is filed with this record.

## Context

### The layer exists, and what it carries today

- **Author surface** — [`packages/spec/src/ui/dataset.zod.ts#DatasetSchema`](../../packages/spec/src/ui/dataset.zod.ts): `name`, `label` (`I18nLabelSchema`, required), `description` (`I18nLabelSchema`, optional), `object`, `include` (to-one hops, capped at three by ADR-0071), `filter`, `dimensions`, `measures`, `protection`, the `MetadataProtectionFields` and `OverrideDeclarationFields` spreads, and a `superRefine` that refuses duplicate member names and dangling `derived` references. `#DatasetDimensionSchema` carries `name`, `label` (optional), `field`, `type`, `dateGranularity`, `nullLabel`; `#DatasetMeasureSchema` carries `name`, `label` (optional), `aggregate`, `field`, `filter`, `format`, `currency`, `polarity`, `derived`, `duration`. Both are `strictObject`s with an `aliases` map (misspellings → the right key) and a `guidance` map (prescriptions for keys that have no destination). **Neither carries `synonyms`, and both carry a `guidance.description` entry reading** 「a measure has no `description` — its author-facing text is `label`. `description` is declared on the DATASET itself; put the explanation there」. The translation schema restates it as [`packages/spec/src/system/translation.zod.ts#DATASET_MEMBER_NO_DESCRIPTION`](../../packages/spec/src/system/translation.zod.ts); the dataset translation group carries `datasets.<name>.label`, `.description`, `.dimensions.<d>.label`, `.measures.<m>.label` and nothing else for a member.
- **`label` is an `I18nLabel`** ([`packages/spec/src/ui/i18n.zod.ts#I18nLabelSchema`](../../packages/spec/src/ui/i18n.zod.ts)): a string, or an inline locale map (`{ en, 'zh-CN', … }`) that no bundle extracts. The compiler reads it with `resolveI18nLabel(…, REGISTRY_LOCALE) ?? name`; the REST door translates a SAVED dataset's labels at the metadata boundary before `queryDataset` runs (so axes and legends are localized through the query, not through `/meta`).
- **The Cube layer underneath already has member descriptions.** [`packages/spec/src/data/analytics.zod.ts#DimensionSchema`](../../packages/spec/src/data/analytics.zod.ts) and the measure schema beside it declare `description`; `AnalyticsService.getMeta` (`packages/services/service-analytics/src/analytics-service.ts#AnalyticsService.getMeta`) publishes `title` and `description` per cube, measure and dimension, filtered through `isCubePublic`. **`compileDataset` writes no description onto the Cube it emits** — the dataset has none to write — so the discovery surface lists datasets with labels only. The reader for a member description exists one layer down; only the author key is missing.
- **ADR-0021's proposed `certified` measure key never shipped.** ADR-0021 D1 lists it (「governance: blessed metric (the review checkpoint)」); the schema on `main` has no such key, correctly under ADR-0049 — nothing read it. It is discussed, and not revived, in [M3](#m3--a-governance-marker-now-or-after-the-first-measurement).
- **Authored datasets exist on both sides.** `examples/app-crm/src/datasets/opportunity.dataset.ts` declares `crm_opportunity_metrics` (dimensions `stage`, `account`, `close_date`; measures `opp_count`, `total_amount`, `avg_amount`, labels only); hotcrm ships eight (`src/sales/datasets/*.dataset.ts`, `src/revenue/datasets/product.dataset.ts`), also labels only. These are the first vocabulary the child cards author.

### The executor and its gate chain (measured on `origin/main`)

Every dataset query — REST door, dashboard widget, report, Studio preview — ends in `AnalyticsService.queryDataset` (`packages/services/service-analytics/src/analytics-service.ts#AnalyticsService.queryDataset`), which compiles the dataset inline into a **request scope** (`#AnalyticsService.requestScope`; the shared registry is the configuration door `#AnalyticsService.registerDataset`, which only tests call today) and answers through `#AnalyticsService.callCtx`. That one method is the gate chain, in order:

1. **Exposure** — `#AnalyticsService.assertQueryObjectsExposed`: every object the compiled cube touches (base and each `include` target) must be API-exposed (ADR-0049 `apiEnabled` / `apiMethods`) and not `internal` (ADR-0100). Refusal is the same shape as "no such cube".
2. **Object read admission** — `#AnalyticsService.assertReadAdmitted` → `ISecurityService.canReadObject`, fail-closed (403 on deny, 503 when the service cannot answer; [`packages/services/service-analytics/src/read-admission.ts#assertObjectsReadable`](../../packages/services/service-analytics/src/read-admission.ts)).
3. **Stored-metadata body and hash refusal**, and **internal-field refusal** — a grouping, filter or aggregate member on those columns is refused, not run.
4. **Field admission** — `#AnalyticsService.assertFieldsReadable` ([`packages/services/service-analytics/src/field-read-admission.ts#assertNamedFieldsReadable`](../../packages/services/service-analytics/src/field-read-admission.ts)): every field a member reads must be in `getReadableFields` ∧ `getQueryableFields`; `packages/services/service-analytics/src/analytics-service.ts#AnalyticsService.assertDatasetFieldsJudgeable` refuses a member over an expression field, because its readability cannot be judged.
5. **Read scopes** — `callCtx` asks the security service's read filter per object and hands the strategies a `getReadScope(objectName)` hook. The filter it receives folds tenant isolation (layer 0), RLS, the controlled-by-parent leaf and the **sharing filter** into one predicate with a deny sentinel, fail-closed ([`packages/plugins/plugin-security/src/security-plugin-read-filter.ts`](../../packages/plugins/plugin-security/src/security-plugin-read-filter.ts), module header).

Below `callCtx`, `DatasetExecutor` ([`packages/services/service-analytics/src/dataset-executor.ts#DatasetExecutor`](../../packages/services/service-analytics/src/dataset-executor.ts)) is **pure query construction** — its header says 「RLS/tenant scoping is NOT handled here — it is enforced inside the strategy via the StrategyContext read-scope hook (D-C)」 — and the three faces each apply the scope:

| Face | Where the scope lands | What it declines |
|---|---|---|
| **ObjectQL** — [`packages/services/service-analytics/src/strategies/objectql-strategy.ts#ObjectQLStrategy`](../../packages/services/service-analytics/src/strategies/objectql-strategy.ts) | `engine.aggregate` under the engine's security middleware, plus the strategy's own `withReadScope` second belt. Cross-object grouping is FK-expand; a referenced row the caller may not read is re-bucketed as [`packages/services/service-analytics/src/strategies/cross-object-rebucket.ts#RESTRICTED_BUCKET`](../../packages/services/service-analytics/src/strategies/cross-object-rebucket.ts) (`'(restricted)'`), never shown. | nothing it can scope; falls to the native face for what it cannot group |
| **Native SQL** — [`packages/services/service-analytics/src/strategies/native-sql-strategy.ts#NativeSQLStrategy`](../../packages/services/service-analytics/src/strategies/native-sql-strategy.ts) | the scope is compiled into the SQL by [`packages/services/service-analytics/src/read-scope-sql.ts#compileScopedFilterToSql`](../../packages/services/service-analytics/src/read-scope-sql.ts), fail-closed: a scope it cannot compile is a refusal, not an unscoped query | the ADR-0139 D6 ReadableIds leaf (`#findReadableIdsLeaf`), federated objects, nested relations, cross-field comparands — each a declared decline |
| **Preview** (ADR-0037) — [`packages/services/service-analytics/src/preview-evaluator.ts#evaluateAnalyticsQueryOverRows`](../../packages/services/service-analytics/src/preview-evaluator.ts) | the same exposure, admission and field gates are asked before the seed rows are read; draft rows are the caller's own pending seed | anything the two faces above decline |

Verdict of the measurement the card's item 4 asked for: **no path was found on which row-, field- or sharing-level enforcement is skipped.** The sharing filter rides inside the read filter the security plugin builds, so it is applied wherever RLS is. No finding card is filed with this record. The ADR-0021 Correction's 2026-05-31 sentence that the Cube layer 「bypasses RLS/tenant」 described the pre-D-C runtime; D-C and the chain above are what closed it, and the integration tests beside the service (`dataset-rls-integration`, `controlled-by-parent-leaf-three-faces`) hold it.

### What is still not executed, and what the AI path must not depend on

ADR-0021's Correction (revised 2026-05-31) stands on `main`: `QuerySchema.joins` / `having` / `windowFunctions` ([`packages/spec/src/data/query.zod.ts#QuerySchema`](../../packages/spec/src/data/query.zod.ts)) are declared and not executed by `IDataEngine`; only the native face emits a join, and only the relationship-derived joins a dataset's `include` compiles to. Consequences this record binds the AI path to:

- The tools accept a **`DatasetSelection`** ([`packages/spec/src/api/analytics.zod.ts#DatasetSelectionSchema`](../../packages/spec/src/api/analytics.zod.ts): `dimensions`, `measures`, `runtimeFilter`, `timeDimensions`, `dateGranularity`, `order`, `limit`, `offset`, `timezone`, `compareTo`, `totals`), **never a `QuerySchema`** and never a Cube `AnalyticsQuery`. There is no key through which an AI could ask for a join, a `having` or a window; cross-object reach is the dataset's `include`, authored by a human.
- No raw SQL. `generateSql` / `/analytics/sql` are not exposed to the AI, and the dataset schema's `DATASET_NO_SQL` guidance refuses `sql` / `expression` / `formula` on members. This is ADR-0021's author-surface rule carried to the reader.
- No inline dataset from the AI. The REST door accepts `dataset` (inline, for Studio preview) or `datasetName`; `query_dataset` accepts `datasetName` only. An AI that could author a dataset inline could author its own 口径, which is the drift this record ends.

### The AI does not read datasets, and the two registries

- **Product AI** lives in cloud (service-ai left objectstack under ADR-0025 S2). The card names the files: 问数 queries objects through `cloud:service-ai/src/tools/query-data.tool.ts` and `cloud:service-ai/src/tools/data-tools.ts`, finds the object by keyword scoring in `cloud:service-ai/src/tools/schema-retriever.ts`, and charts through an inferred cube rather than an authored dataset (`cloud:service-ai/src/tools/chart-copy.ts` documents the two paths). Nothing there reads `dataset` metadata.
- **MCP native tools** come from one seam. [`packages/mcp/src/mcp-http-tools.ts#wireBridgeTools`](../../packages/mcp/src/mcp-http-tools.ts) registers `#registerObjectTools` (`list_objects`, `describe_object`, `query_records`, `get_record`, and `aggregate_records` **only when the bridge implements the optional `aggregate` member**), `#registerActionTools`, `#registerFederationTools` and `#registerFileTools` over a [`packages/mcp/src/mcp-http-tools.ts#McpDataBridge`](../../packages/mcp/src/mcp-http-tools.ts) — 「every method runs AS the authenticated principal」. Two bridges implement it: the HTTP one built per request in [`packages/runtime/src/domains/mcp.ts#buildMcpBridge`](../../packages/runtime/src/domains/mcp.ts) (through `callData`, so RLS and permissions apply) and the stdio one, [`packages/mcp/src/stdio-data-bridge.ts#createStdioDataBridge`](../../packages/mcp/src/stdio-data-bridge.ts), whose `aggregate` asks API exposure, relation-target exposure and the stored-metadata refusals before the engine. OAuth scopes narrow registration by **tool family** (`packages/mcp/src/mcp-http-tools.ts#RegisterObjectToolsOptions`: `data:read` → list/describe/query/get/aggregate, `data:write` → create/update/delete, `actions:execute` → actions; [`packages/spec/src/ai/mcp.zod.ts#MCP_OAUTH_SCOPE_DATA_READ`](../../packages/spec/src/ai/mcp.zod.ts)). **No tool in `packages/mcp/src` reads a dataset.**
- **The product-AI registry and MCP share one direction today, not one registry.** [`packages/mcp/src/types.ts#ToolRegistry`](../../packages/mcp/src/types.ts) is service-ai's function-calling registry (`getAll(): AIToolDefinition[]`, `execute(call)`); [`packages/mcp/src/mcp-server-runtime.ts#MCPServerRuntime.bridgeTools`](../../packages/mcp/src/mcp-server-runtime.ts) bridges such a registry INTO the MCP server (stdio hosts only; the HTTP transport injects only the authoring registry under `metadata:write`). The shared unit is therefore the [`packages/spec/src/contracts/ai-service.ts#AIToolDefinition`](../../packages/spec/src/contracts/ai-service.ts) (`name`, `label`, `description`, `parameters` as JSON Schema, `category`, `outputSchema`, `objectName`, `requiresConfirmation`), and the standing shape is: **a tool is defined once as an `AIToolDefinition` with one executor, and MCP bridges it.** D2 follows that shape rather than inventing a registry.

**What converges, and what this record takes from it:**

1. **Synonyms are a flat list of strings on the member**, not a locale map and not a separate linguistic model — Looker, Power BI, Snowflake and Databricks all land there; Power BI's linguistic schema is the one richer form and is being retired with Q&A. → D1's `synonyms: string[]`.
2. **The AI-facing text is the member's `description`** on five of seven (dbt, Looker, Tableau, Snowflake, Databricks). Cube alone separates a consumer-facing `description` from an AI-only `ai_context`; Power BI puts AI instructions at model level. → [M1](#m1--where-the-ai-facing-text-of-a-measure-or-dimension-lives) is the fork, with option A following the five.
3. **The AI chooses from a governed catalogue and never writes its own joins or SQL through the semantic layer** (Looker, Tableau, Cube, dbt's governed path). → D2's two tools over `DatasetSelection`; no `QuerySchema`, no inline dataset.
4. **Provenance is first-class**: a verified mark (Power BI), `verified_query_used` (Snowflake), 「verified by an agent author」 (Databricks). → D3's provenance block, produced by the tool, not typed by the model.
5. **Ambiguity ends in a question or a suggestion list, not a guess** (Snowflake, Looker, Databricks). → D3's rule 3. Where nothing fits, the platforms split between refusing (Tableau) and widening (Power BI, dbt's `text_to_sql`) → [M2](#m2--what-the-ai-does-when-no-dataset-covers-the-question).
6. **Verified / golden questions** are the second round everywhere they exist (Looker's 30–50 pairs, Power BI's verified answers, Snowflake's repository, Databricks' benchmarks), always after descriptions and synonyms. → [M3](#m3--a-governance-marker-now-or-after-the-first-measurement) recommends the same order.
7. **Smaller catalogues answer better** (Snowflake's ~10-column warning, Looker's ≤5 explores, Power BI's AI data schema, Cube's views). → `list_datasets` returns datasets, not objects; the dataset IS the curated subset, and D1 adds no dataset-level synonyms until the eval says they are needed.

## Decision

### D1 — Business vocabulary on measures and dimensions: `synonyms` and `description`

Both `DatasetMeasureSchema` and `DatasetDimensionSchema` gain two optional keys. Nothing else on the author surface changes.

| Key | Shape | What it is for | Reader (D6) |
|---|---|---|---|
| `synonyms` | `string[]`, each trimmed, non-empty, ≤ 60 characters, at most 20 per member, no duplicates after normalization | the words a person uses for this member in a question — 「营收」 → `['收入', '销售额', 'revenue', 'sales']`. **Matched, never displayed.** Mixed languages in one list are the normal case, not a smell | `list_datasets` term matching |
| `description` | `I18nLabelSchema` (string or inline locale map), ≤ 500 characters per locale | one or two sentences of **business definition**: what the number is and when to use it — 「已赢单金额合计，按成交日期归月；不含报价中与已丢单」. Read by the AI to choose and explain, and published on the Cube member so `getMeta` and future tooltips read the same text | `compileDataset` → Cube member `description` → `getMeta`; `list_datasets` |

**Relation to the keys that exist.** `label` stays the short display name drawn on axes, legends and tiles; it is also a match target (a label IS the first synonym). The dataset-level `description` stays what it is — the text that says what the dataset as a whole covers — and becomes the text the AI picks a dataset by. A member `description` says what one number means. The three are not interchangeable and the guidance entries say which to use for what.

**Strictness and aliases.** The two schemas stay `strictObject`. `aliases` gains `synonym`, `alias`, `aliases`, `alternateNames`, `terms`, `keywords` → `synonyms`, and `aiDescription`, `aiContext`, `hint`, `help`, `tooltip` → `description`, so an author who has written Cube or Power BI is pointed at the one key. The two `guidance.description` entries are retired (M1 option A) or rewritten to point at the new AI-only key (M1 option B); `DATASET_MEMBER_NO_DESCRIPTION` follows the same ruling.

**Validation, at the dataset level (`superRefine`, beside the existing unique-name check).** Normalize every match target — NFKC, case-fold, trim, collapse internal whitespace — and refuse the dataset when, **within one dataset**, a synonym equals another member's `name`, another member's `label` (any locale of an inline map), or another member's synonym. Two members that answer to the same word inside one dataset make the selection rule undecidable before the AI is even involved; this is Snowflake's uniqueness rule narrowed to the dataset. A synonym that equals its OWN member's name or label is dropped silently (harmless redundancy). **Across datasets** collisions are allowed and expected — 「营收」 may legitimately mean one thing in `sales_analysis` and another in `finance_close` — and D3's rule 3 turns them into a clarifying question. Validation errors answer in the existing `DATASET_INVALID` envelope with the two member names and the colliding word.

**i18n stance.** `synonyms` are **not** translation-bundle keys and are **not** locale-keyed: they are match input, the model matches across languages, and a locale map would invite the AI to read only the active locale's list — the one thing a synonym list must not do. The translation group gains `datasets.<name>.measures.<m>.description` and `datasets.<name>.dimensions.<d>.description` (member descriptions ARE display text, like labels) and a `guidance.synonyms` entry explaining why there is no `.synonyms` key. The REST door's translate-at-the-metadata-boundary step covers the new description keys with no change to the analytics service, which stays free of i18n.

**What this record deliberately does not add** (each revisited only when D5's measurement shows the need): dataset-level `synonyms` (the dataset's `label` and `description` are its match targets for now); `sample_values`; model-level free-text AI instructions (cloud may hold these in its planner prompt — they are not platform metadata); a `certified` flag or verified questions (M3).

### D2 — Two tools, one definition, one executor, two transports

**Names.** `list_datasets` and `query_dataset`, in the `list_objects` / `query_records` family's spelling. Both are **read-family** tools: under OAuth scope narrowing they register with `data:read` exactly as `aggregate_records` does (#2698's tool-family mapping — precedent, not a fork), and they are subject to the ADR-0090 D10 agent ceiling like every other read.

**Where the definition lives.** The input and output shapes are spec (`@objectstack/spec`, a new `ai/dataset-tools.zod.ts` beside `ai/mcp.zod.ts`), declared once as zod and projected to the JSON Schema an `AIToolDefinition.parameters` carries; `query_dataset`'s `selection` member is `DatasetSelectionSchema` **by reference**, the way that schema takes the shared members off `AnalyticsQuerySchema.shape` — one declaration, no private dialect for the AI. The executor lives in `@objectstack/service-analytics` (proposed name `createDatasetTools(deps)`, returning `{ definitions: AIToolDefinition[], execute(call, context) }`), because that package owns `queryDataset` and the catalogue is built from the same metadata the REST door resolves `datasetName` from.

**How MCP gets them.** `McpDataBridge` gains two OPTIONAL members, `listDatasets(opts)` and `queryDataset(opts)`, under the same graceful-degradation contract as `aggregate`: a bridge that omits them registers no dataset tools and nothing elsewhere changes. `wireBridgeTools` gains a `registerDatasetTools` step gated on `data:read` and on the members' presence. Both bridges implement the members by calling the service-analytics executor with the principal they already bind — `buildMcpBridge` on HTTP, `createStdioDataBridge` on stdio — so the MCP tool layer stays free of analytics code, exactly as it is free of engine code today.

**How product AI gets them.** Cloud's service-ai `ToolRegistry` registers the same `definitions` and delegates `execute` to the same executor. That is the `bridgeTools` direction already standing (definitions first, MCP bridges them); this record adds no second registry and no MCP-client hop inside the product.

**`list_datasets`.**

- Input: `{ terms?: string[] }` — the candidate words the caller lifted from the question (optional; without it the whole catalogue is returned). Strict object, aliases `query`, `q`, `keywords`, `search` → `terms`.
- Source: the metadata service's `dataset` items for the caller's environment (the same `getMetaItems({ type: 'dataset' })` read the REST door uses to resolve `datasetName`), localized at the metadata boundary for the caller's locale the way the REST door localizes a saved dataset.
- Admission, fail-closed, before anything is listed: a dataset is listed only if its base object AND every `include` target pass the exposure and object-read-admission doors the query would ask (steps 1–2 of the chain). A dataset that fails is **absent**, not marked — the same answer as "does not exist", the `CUBE_NOT_FOUND` / ADR-0110 D3 shape. A member whose fields the caller cannot read (step 4) is omitted, and the dataset entry carries `membersWithheld: true`, so the AI can say 「有些指标你没有权限看」 rather than 「没有这个指标」 — the ADR-0090 D10 rule that a narrowed read arrives with the narrowing stated. Datasets are not filtered by the agent ceiling beyond that; `diagnoseDelegation` on the base object is consulted by `query_dataset`, below.
- Output: `{ datasets: [{ name, label, description?, object, membersWithheld?, dimensions: [{ name, label, description?, type, synonyms? }], measures: [{ name, label, description?, aggregate, format?, polarity?, synonyms? }], matches?: [{ term, member: 'measures.total_amount' | 'dimensions.stage', matchedOn: 'name' | 'label' | 'synonym' }] }], partial?, warning? }`. `matches` is computed by the platform with the D3 normalization — deterministic, testable without a model, and the same function the spec validation uses. `partial` / `warning` follow `list_objects`' #6504 shape when the metadata read is degraded: never a count that is not a fact.
- Guidance to the model, in the tool's `description`: the D3 rule in three sentences, so an external MCP client receives the selection rule with the tool.

**`query_dataset`.**

- Input: `{ datasetName: string, selection: DatasetSelection }`. Strict; aliases `dataset`, `name` → `datasetName`, and the `DatasetSelectionSchema` aliases apply inside `selection`. No inline `dataset`, no `previewDrafts`, no `cube` (the selection schema's own guidance already refuses `cube`). `selection.limit` is capped by the tool at the bridge's `maxQueryLimit` (default 50 rows, as `query_records`).
- Execution: resolve the saved dataset exactly as `list_datasets` would (absent → `NOT_FOUND`, one answer for missing and hidden), then `IAnalyticsService.queryDataset(dataset, selection, context)` with the caller's `ExecutionContext`. **Nothing is added in front of `callCtx` and nothing is skipped**; the tool is a fourth caller, beside the REST door, the dashboard and the report.
- Output: the `AnalyticsResult` (`rows`, `fields` with `label` and `type`, the drill sidecars as they are) plus a **`provenance`** block the tool composes from the dataset it resolved — `{ kind: 'dataset', dataset: { name, label }, measures: [{ name, label, description? }], dimensions: [{ name, label }], filter: <the dataset's intrinsic filter, if any>, runtimeFilter?: <the caller's> }` — and `rowCount`, `truncated`. If the bridge's `diagnoseDelegation(object)` reports a narrowing, the statement rides along, as `query_records` carries it.
- Refusals answer in the ADR-0112 envelope with the codes the door already uses: `NOT_FOUND`, `PERMISSION_DENIED`, `INVALID_FIELD`, `DATASET_INVALID`, and the 503 admission-unresolved shape. The tool invents no code.

### D3 — The selection rule, and provenance the model cannot invent

The rule is stated once here and carried in three places: the tool descriptions (for MCP clients), cloud's planner (the product's enforcement), and the D5 evaluation (the measurement).

1. **Normalize** the question's candidate terms and every match target the same way: NFKC, case-fold, trim, collapse whitespace. Match targets are a member's `name`, its `label` in every locale, and each `synonym`. Equality after normalization is a **hit**; a substring, a stem or an embedding neighbour is **not** a hit (it may be offered in rule 3's question, never acted on).
2. **One hit → it wins.** The AI answers through `query_dataset` on that dataset and member, and renders the answer's source from the tool's `provenance` — 「指标：营收（数据集：销售分析）」 — never from its own recollection of what it asked. A measure's `description` is the sentence the AI uses to explain what the number includes.
3. **More than one hit** (two datasets, or two members, answer to the word) → the AI **asks**, listing each candidate's label, dataset label and description. It does not pick, and it does not silently prefer the first. (Snowflake's suggestions, Looker's clarifying question, Genie's follow-up.)
4. **No hit → fall back to the object query the AI runs today** (`query_records` / `aggregate_records`, or cloud's equivalents), and the answer's source says so in words — 「来源：对象 crm_opportunity 的 amount 字段合计（非指标口径）」 — so a reader can tell a governed number from an estimate. The posture of this rule is [M2](#m2--what-the-ai-does-when-no-dataset-covers-the-question); the card's wording (「没有命中时，再退回按对象查询」) is option A there.
5. **A dimension hit without a measure hit is not an answer**: 「按阶段」 picks a grouping, not a number; the AI still needs a measure hit (or asks).

Why the platform computes `matches` instead of leaving the whole rule to the model: 防 AI 犯错. The model still decides what the question's terms are; whether a term equals a synonym is a string comparison, and a string comparison belongs where it can be unit-tested and where every consumer gets the same answer.

### D4 — Permissions: the tools add no gate and bypass none

Measured in [Context](#the-executor-and-its-gate-chain-measured-on-originmain). The binding statements:

- `query_dataset` reaches data **only** through `IAnalyticsService.queryDataset` with the caller's `ExecutionContext`; it holds no engine, no driver and no SQL. Everything `callCtx` refuses for the REST door it refuses for the AI, in the same envelope.
- `list_datasets` asks the first two doors of the same chain for every dataset it lists and the field door for every member it lists. It never lists what `query_dataset` would refuse at the object level, and it names the withholding at the member level.
- The AI path depends on nothing in ADR-0021's unexecuted set: no `QuerySchema`, no `having`, no window, no raw SQL, no inline dataset. Its only cross-object reach is the human-authored `include`.
- The acceptance test for the two child cards that implement this is a **four-face parity test** in the shape of `controlled-by-parent-leaf-three-faces`: a row the REST door hides, the dashboard hides and the preview hides, `query_dataset` hides too, on both bridges — and the same for a field, a sharing rule and a tenant.
- A leak found while implementing is a **finding card**, filed before the PR, never a special case inside the tool. This record found none.

### D5 — The evaluation hook: cloud's `ask-accuracy` business-term set

The consumer's acceptance, named here, implemented in cloud (cloud#3825 item 3):

- `ask-accuracy` gains a **business-term** category: questions phrased with synonyms and business words (「本月营收多少」, 「上季度的成交金额按销售阶段」) whose expected answer is a dataset measure, over an app whose datasets carry D1 vocabulary. A question is scored on (a) the dataset and measure named in the answer's provenance, (b) no silent fallback when a hit existed, (c) a clarifying question when the set contains a deliberate cross-dataset collision.
- The baseline is the card's: cloud#3578, 16 of 30 on the wrong object before its fix. The target is the consumer's to set; this record asks only that the number be measured before and after the vocabulary is authored, so M2 and M3 are decided on a measurement.
- Objectstack's own acceptance is in D4 and D6: the parity test, the unit tests for normalization and matching, and the liveness rows.

### D6 — Enforce-or-remove: every key names its reader in its first implementation card

| `dimensions[].synonyms` | same | same | same |

The precedent for a key that lands `planned` is the ledger's own `overrides` row. If card 2 does not land in the same release train as card 1, card 1's keys are not released: a spec release that carries a key with no reader is what ADR-0049 removed from this surface once already. No key is retired by this record; the two guidance strings it changes are prescriptions, not keys.

## Consequences

- **One 口径.** 「营收」 in a dashboard tile, in 问数 and in an external agent is the same measure of the same dataset, and the answer says which. The drift ADR-0021 named is closed at the last surface that still had it.
- **The AI's reach shrinks, deliberately.** Through the semantic layer the AI can ask for what a human authored and nothing more: no join it invents, no field it guesses, no SQL. Its wider reach stays where it is today — the object tools — and is labelled as such in the answer.
- **Permissions are not a new problem.** Four callers of one gate chain, one parity test. The cost of a future gate change stays one place.
- **Authoring cost moves to admins, where it belongs.** A dataset with no synonyms works exactly as today; a dataset with them answers the questions people actually ask. The first vocabulary (card 6) is a day of work and is also the D5 test fixture.
- **Two transports, no second registry.** MCP clients and the product see the same two tools because they are the same two `AIToolDefinition`s; a change to the tool shape is one spec change.
- **Cost.** Protocol addition (p1): four optional keys on two schemas, two tool schemas, one new executor module, two optional bridge members, one translation-group extension, four ledger rows. No migration: every existing dataset is valid unchanged.

## Settled by precedent (kept out of the maintainer's section)

- **Where the layer lives** — ruled: cloud#3825 待裁 2, option A.
- **One registry** — the standing direction is `AIToolDefinition` first, MCP bridges it (`MCPServerRuntime.bridgeTools`); D2 follows it.
- **Which OAuth scope** — tool families map to scopes (#2698); a dataset read is a data read; `aggregate_records` is the precedent under `data:read`.
- **Hidden means not found** — `CUBE_NOT_FOUND` for a non-public cube; ADR-0110 D3's outage shape; #6504's rule that a count is never claimed when it is not a fact.
- **No SQL, no joins from the AI** — ADR-0021 D1 and D-A/D-C; `DATASET_NO_SQL`; the Correction's unexecuted set.
- **Every new key has a reader** — ADR-0049 / ADR-0078; D6.
- **Inline locale maps, never bundle-extracted, for `description`** — #6761 and the REST door's translate-at-the-boundary step; `synonyms` are not display text and get neither.
- **Three-hop `include` cap** — ADR-0071; the tools do not widen it.
- **Narrowing is stated** — ADR-0090 D10 and `diagnoseDelegation`; D2's `membersWithheld` and the provenance's narrowing statement.

## Decisions for the maintainer

Three forks that existing rules do not settle. Each lists 2–4 options with the recommendation and its consequences, weighed on the four axes with 项目长远合理性 at 50% (实际业务需求 20%, 防 AI 犯错 20%, 创业阶段不扩散 10%). 「推荐先只按①得出」: the recommendation below is the one 长远合理性 alone gives, then checked against the other three.

### M1 — Where the AI-facing text of a measure or dimension lives

维护者速读：指标/维度要有一句给 AI 看的业务定义。放在 `description`（与 Cube 层已有的键同名，五家平台都这么做），还是另起一个只给 AI 看的键？

| Option | What it is | Consequences |
|---|---|---|
| **A — `description` on members (recommended)** | Members gain `description: I18nLabel`; the compiler writes it onto the Cube member `description`; `getMeta`, future tooltips and the AI all read the same sentence. The two `guidance.description` entries and `DATASET_MEMBER_NO_DESCRIPTION` are retired with a history line. | One key, one text, one reader chain already present one layer down. Matches dbt, Looker, Tableau, Snowflake, Databricks. The text is visible to humans wherever the Cube description is shown, so an admin writes a business definition, not a prompt. Reverses a spec prescription that was correct only while the key had no reader. |
| **B — a new AI-only key (`aiContext`), `description` stays refused on members** | Cube's `ai_context` shape: a text only the AI reads, hidden from every human surface. | The AI's text is invisible to the admin surfaces that would catch a wrong definition; the day a tooltip is wanted the question re-opens with two keys; Cube is the only platform of seven that does this, and it does it because its `description` is already a public API field — a reason that does not apply here, since the dataset member has no description at all today. |
| **C — both now** | A and B together. | Two texts for one meaning; which one the AI trusts when they disagree is a new rule nobody asked for. 扩散. |

Recommendation **A**. 长远合理性: the key the whole industry reads, already present on the Cube layer this compiles to. 实际业务需求: the card asks for 「给 AI 的简短说明」, and a business definition is exactly that. 防 AI 犯错: one text, reviewed by humans where they already look. 不扩散: one optional key.

### M2 — What the AI does when no dataset covers the question

维护者速读：用户问「营收」，但没有任何数据集定义过它。是退回按对象查（今天的做法，答案标明「非指标口径」），还是不答、请管理员先定义？

| Option | What it is | Consequences |
|---|---|---|
| **A — fall back to the object query, labelled (recommended)** | D3 rule 4 as written: no hit → the object tools the AI uses today; the source line says in words that no governed metric was used. The card's wording. | No regression in coverage on day one — 问数 answers everything it answers today, and the governed answers are marked. The ungoverned answer can still be wrong in the cloud#3578 way; D5 measures how often the fallback fires, which is the list of datasets admins should author next. |
| **B — fall back only to objects no dataset covers** | If any dataset's base object is the object the question names, refuse to guess a field on it and ask the admin to define the metric; otherwise as A. | Closes the sharpest failure (a guessed `amount` beside a defined `total_amount`) at the price of a rule that needs the question's object resolved first — the keyword step that is the baseline's failure mode. More rule, mixed signal. |
| **C — refuse outside the semantic layer (Tableau Pulse's posture)** | Business questions are answered only from datasets; anything else is 「请先定义指标」. | The cleanest 口径 and the biggest day-one regression: most apps have few or no datasets today. Right as an eventual posture for a mature catalogue, wrong at the current stage. |

Recommendation **A**, with D5 reporting the fallback rate so the maintainer can move to B or C on a number rather than a guess. 长远合理性: the labelled fallback is what Power BI and dbt do and it degrades to C naturally as the catalogue grows. 实际业务需求: coverage today. 防 AI 犯错: the label is what stops an estimate being read as the 口径. 不扩散: no new rule beyond the label.

### M3 — A governance marker now, or after the first measurement

维护者速读：要不要现在就加「认证指标」（ADR-0021 当年提过的 `certified`）或「已验证问法」（Power BI / Snowflake / Databricks 都有），让 AI 只用/优先用被认证的？还是先只做同义词和说明，量过准确率再说？

| Option | What it is | Consequences |
|---|---|---|
| **A — not in this round (recommended)** | Every measure of an authored dataset is eligible; the dataset itself is the admin's blessing. `certified` stays unshipped under ADR-0049; verified questions stay cloud's eval set, not platform metadata. Revisit when D5 has a before/after number. | Smallest protocol addition; matches the order every surveyed platform took (descriptions and synonyms first, verified queries second). Risk: a draft dataset is as eligible as a reviewed one — mitigated by the fact that datasets are admin-authored metadata, not user content. |
| **B — ship `certified: boolean` now** | ADR-0021 D1's key, with a reader at last: `list_datasets` carries it, D3 prefers a certified hit over an uncertified one, and provenance says 「认证指标」. | Gives the review checkpoint ADR-0021 wanted. Adds a second dimension to the selection rule before the first is measured, and a flag an admin must remember to set. |
| **C — ship dataset-level verified questions now** | `questions: [{ question, selection }]` on the dataset: a human-approved question with its exact selection; a matching question is answered from the stored selection and marked verified. | The strongest accuracy lever in the survey, and the largest surface: a new key, a new match path, and a store that drifts when the dataset changes. The right second round, not the first. |

Recommendation **A**. 长远合理性: the platforms that have all three landed them in this order, and the key that is worth adding depends on which failure D5 shows (wrong metric → B; wrong shape of the same metric → C). 实际业务需求: the card asks for vocabulary and tools, not certification. 防 AI 犯错: fewer selection rules until one is measured. 不扩散: zero new governance keys this round.

## Non-goals

- Re-opening where the semantic layer lives, or whether the AI should author datasets (it does not; ADR-0021's author surface is for humans and for AI authoring under human review, not for a question-time agent).
- A natural-language-to-dataset compiler, a linguistic schema, or any text-to-SQL path through the semantic layer.
- Changing how dashboards and reports read datasets, or the Cube layer's own API.
- Executing `QuerySchema.joins` / `having` / `windowFunctions` — ADR-0021's Correction stands.
- Dataset-level synonyms, sample values, model-level AI instructions, `certified`, verified questions — each named above as a possible second round, none proposed now.
