## Warnings and notes

- **Form groups (step 3):** renaming a group in *Group properties* saved the label (`fieldGroups[].label` read back *Ticket* / *Details*) but the canvas header kept showing *New group*; the stored keys are `new_group` / `new_group_2`. Observed in-session, not re-checked after a reload.
- **Flow designer (step 5):** the edge **+** and the node's *Add connected node* both insert a `create_record` node without offering a type; the node inspector's *Node Type* list does not contain `notify`, so the inserted node cannot be turned into the one needed; and there is no gesture to connect two existing nodes. The way through was: select Start → palette → Notify (connected from the selection), delete the orphaned End, select Notify → palette → End.
- **Flow designer (step 5):** the toolbar kept reading *Trigger: autolaunched* after the Start node was set to *Record updated*; the stored flow `type` stays `autolaunched`. The flow still fired on the update (step 8).
- **Condition pickers (steps 4, 5):** subjects are shown as machine paths (`record.status`), not field labels.
- **Publish advisories (amber, not counted):** `flow-draft-status-ambiguous` on the flow (step 7); `security-private-no-readscope` on the permission set (8a).
- **End user (step 8):** the console's background reads answer 403 for the end user (`/api/v1/meta/_drafts`, `sys_activity`, `sys_comment`), and the record panel shows *You don't have permission to view activity / comments on this record* on the user's own ticket. Not red; not counted.
- **Vocabulary:** the task's *long text* is *Text · Text Area*; *picklist* is *Selection · Picklist* in the type list but `SELECT` on the canvas.
- **Driver note:** typing digits into the native date input on the create form did not set the value (an automation-input artefact — the edit form's date input took `fill`); not scored.
