# Record page v4 · design notes (2026-10-29)

## n41

面板模型（2026-10-29，维护者建议 + 席位综合）：右栏是一叠同形面板（时间线、每个关联表、审批、附件）。标题行：折叠 ▾ 紧跟标题文字（同 Claude Code「环境 ▾」），点标题即折叠；计数靠右；悬停时右端浮出 ⠿ 抓手 + ＋ ⤢ ⋯（不悬停时左侧不留空位），整行可拖；⋯ 悬停才出现，里面只有「隐藏」（维护者 2026-10-29：「隐藏按钮放出来感觉还不如之前的更多下拉」）；上移/下移不进菜单（「有了拖动，为什么还需要上移 / 下移」）——键盘排序作为拖拽的无障碍替代放在 ⠿ 抓手上：Tab 聚焦后 ⌥↑/⌥↓，tooltip 写明。0 条面板折成一行「还有 N 个空关联」。脚部「已隐藏 N 张 · 显示 · 恢复默认顺序」。头部动作行右端只有一枚「右栏」图标开关（⌘⇧,），不再有「时间线 | 关联」文字分段。

## n42

时间线与层级（2026-10-29）：没有「时间线开关」——时间线始终是右栏一块面板，面板标题行 ⊞ 升格为独立列、列头 ⊟ 收回；右栏整体由头部右端一枚图标开关。crumb 行取消：‹ 返回进标题上方小字；整页不画 ↑↓（维护者 2026-10-29：整页无兄弟集、看不到列表），抽屉顶栏保留 ↑↓ 与 ↑/↓、j/k 键，下钻层只留键盘。时间线默认是右栏最上面的面板（带紧凑输入框 + 最近 3 条 + 查看全部），面板标题行 ⊞ 升格为独立列；工作型对象（stage / option kinds / files）在三栏层默认升格。两栏层：右栏常驻、时间线折成面板，不再有「相关 N」栏开关。抽屉按自己的宽度套同一规则：≥760 两栏（详情 | 右栏面板），更窄才页签——今天 1123 px 的抽屉仍被强制页签，是缺口。

## n43

左栏「全部报表」（2026-10-29）：控制台对每个非 Studio 应用固定注入（objectui#13020），与应用自己的报表组重复、无报表的应用也挂着。方案 1+2：有报表组 → 「全部报表 →」并入组尾；无组但有成员可看的报表 → 底部一行；没报表 → 不画。不加元数据键。

## n44

并入 #27524（维护者 2026-10-29）：⑩ 子表紧凑行首列跳过回指当前记录的 FK——产品页的「商机产品明细」六行全是产品名是零信息；取第一个非本关系字段的列（商机名），chip 取数量/金额/状态。⑪ 折叠「动态」卡只留一行输入框（聚焦展开）+ 最近 3 条 + 查看全部，无筛选 chip 无工具条。

## n45

放大态（2026-10-29，维护者问「子表放大之后是否建议全屏 modal 浮出」，裁定不做 modal）：⤢ 仍是原地放大（?related=，Esc / ‹ 返回），但放大态把头部压成一行「‹ 返回 · 记录名 · 子表名 · 计数 + 动作」，要点条与阶段路径收起，表格占满其余高度；抽屉里占满抽屉主体。理由：modal 已退役、抽屉里会 dialog 叠 dialog、正文表编辑需要头部合计随之刷新、URL 可寻址与返回不必重做。

## n46 · 抽屉 v4（RecordDrawerV4Peek / RecordDrawerV4Max / RecordDrawerV4Enlarged）

抽屉 v4（2026-10-29，维护者三问：「drawer 已经很宽了，全屏之后更窄了」「抽屉盖住了列表合理吗」「抽屉 ⤢ 原地最大化 我觉得有必要」）：现状 size:'auto' 按字段数撑到 960/1200 并可拖到 95vw，1440 下比整页正文 1136 还宽，又有 80% 黑遮罩把列表盖死——两头好处都没拿到。改为：抽屉默认 md 720、可拖到 60vw（不再按字段数撑宽）、去遮罩、列表可读可点、点行换记录；⤢ 原地铺满内容区、留出侧栏（宽 = 100vw − 侧栏实时宽度；URL 不变、Esc/⤡ 还原、栈不动）；「在整页打开」只留列表行 ↗（#27031）与头部 ⋯；整页「收为抽屉」只对从 ↗ 进来的保留。#26679 的「⤢ 跳整页」就此退役。split 读者偏好不变。

## n47 · 顶行模型（三张面 + 放大态共用）

顶行模型（2026-10-29，维护者：「几个页面你要综合具体考虑，抽屉效果，最大效果，单独记录详情页的效果……如果都保留顶部行，切换按钮也可以放在顶部行右侧」「包括子表最大化的效果」）：三张面 + 放大态共用一条 40 px 顶行 = 框架控件；头部动作行只放业务动作（1 主 + 2 次 + ⋯）。顶行左端：抽屉/铺满「对象 · n / N」（下钻层 ← 路径）、整页「‹ 返回」；放大态是路径的一层「‹/← 记录 › 子表 · 计数」。右端固定顺序 ↑↓ · ⊟ · ⤢/⤡ · ✕，按面显隐：⊟ 只在该面层级真有右栏时出现；↑↓ 只在有列表上下文时出现（整页带 ?from= 列表轨迹才有）；⤡ 在整页上是「收为抽屉」、只对从 ↗ 进来的显示；✕ 只在抽屉类的面上、永远关整条路径；放大态无 ↑↓ 无 ⊟，整页放大态无 ✕。收编 #27524 第 4/7/12 项与 #27545 第 3 项。

## n48 · 窄层 = 单列堆叠，页签层退役（RecordDrawerV4Peek / RecordMobile）

窄层 = 单列堆叠，页签层退役（2026-10-29，维护者看到「drawer 带 tab、展开之后不是」，席位综合评估后荐堆叠，维护者答「同意」）：< 760 的任何容器（侧窥、手机）把右列整体接在详情列下面，顺序不变——详情分区 → 动态面板（输入框 + 最近 3 条 + 查看全部）→ 关联面板（空面板折行）。理由：分诊一次下滑看完、无额外 chrome、侧窥 → 铺满 → 整页是同一组块的连续展开、与 Linear / Notion / Attio / HubSpot 侧窥一致；长度靠分区折叠、空折行、动态只露 3 条压住。寻路如实测需要，再加一行锚点 chip「详情 · 动态 N · 关联 N」，先不加。收编 #27524 第 8 项；#27055 第 6 项的页签层由此退役。

## n49 · 分栏默认 + 顶行细节

分栏默认 + 顶行细节（2026-10-29，维护者问「显示抽屉时为什么要盖住列表，建议把列表缩窄吗」并让席位对照 Linear；席位建议，维护者令「按照你前面的建议重新更新设计图」）：① 列表 → 记录默认分栏：列表缩窄到剩余宽度（1440 下 464，只剩名字 · 状态 · 负责人；1280 下退成卡片行），记录 720 在右，列表全程可读可点、点行换记录；overlay 抽屉退为读者偏好（#27031 的显示菜单）与内容区不足约 1000 时的自动回退。② 顶行左端是面包屑「对象 › 记录名」，点对象名 = 返回；右端固定序「3 / 21 · ↓ ↑ · ⊟ · ⤢/⤡ · ✕」按面显隐（Linear 的「3 / 4 ↓ ↑」）。③ ↓↑ 步进后列表选中跟着走并滚入视口；步进保留上一条内容到下一条到达，?recordId= 更新不重渲染列表（Twenty #27438 / #28517 的教训）。④（撤回，见 n50）⑤ 整页：从 ↗ 进来带轨迹时顶行右端有计数 · ↓↑ · ⤡ 收为抽屉，直接打开只有 ⊟。待写入 #27524 第 7 / 12 项与 #27545。

## n50 · 常驻页签行；放大态 = 页签激活态

常驻页签行（2026-10-29，维护者看 Attio / Twenty 后：「右侧的 activity notes tasks 不就相当于我们的子表，他可以预览，也可以从顶部的选项卡切入」「关联多他不是也折叠到下拉了吗」；裁定「按这版改板：头部底边加常驻页签行，放大态改为页签激活态（头部原样），其余不动」）：记录头部块底边一行页签「概览 · 动态 N · 任务 N · 商机 N · +N ▾」，三张面同位置；每个页签 = 一个面板的放大面（动态页签 = 完整时间线，代替「查看全部 N 条」），放不下折进 +N 下拉、下拉带计数；顺序与显隐跟 record.related.arrangement 走（隐藏的面板进 +N 末尾）。放大态 = 页签激活态：顶行、头部原样，页签行下面换成占满的表格，URL 仍 ?related=object.field，Esc / 点「概览」回；不再是下钻一层，撤回「压头部 / 4 格要点 / 顶行变路径」。面板头 ⤢（tooltip「查看全部 N 条」）与计数 chip = 切到该页签。第 8 项「窄层无页签」仍成立：它否的是把概览切碎，这行页签不切概览。先例：Attio（Overview 分区 + 顶部页签 + 「+4 more」带计数）、Twenty、Linear 项目页、Salesforce「View All」。
