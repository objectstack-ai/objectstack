## @object-ui/plugin-list

ListView plugin for ObjectUI - unified view component with view type switching

## Installation

```bash
pnpm add @object-ui/plugin-list
```

The props a [`list-view`](/docs/ui/components/plugins#list-view) node reads on a page are generated from the spec into the component reference; this page covers using the plugin from React.

## On a page — `requiredPermissions`

A page `list-view` node is written in `@objectstack/spec`'s list view spelling,
with its keys in `properties`. `requiredPermissions` gates what the node draws:

```json
{
  "type": "list-view",
  "properties": {
    "data": { "provider": "object", "object": "deal" },
    "requiredPermissions": ["sales.view_pipeline"]
  }
}
```

`requiredPermissions` lists capabilities the viewer must all hold. A viewer
missing one sees "Insufficient permissions to view list." in place of the list,
as the record blocks show, and no records are queried.

`addRecord` draws an Add button, and `position` places it (`"top"`, `"bottom"`
or `"both"`). The spec row declares `enabled` default `true` and `position`
default `"bottom"`, but the renderer does not apply those defaults: it draws the
button only for an explicit `enabled: true`, and places an absent `position` at
the top. objectui#13099 owns that gap; until it lands, write both keys. A click opens the
create form the object list's New opens: the record-form overlay, or the
full-page create for an object whose `editMode` is `page`. The button is not
drawn for a viewer who may not create, or under a host that serves no create.
`mode` and `formView` are not read.

```json
{
  "type": "list-view",
  "properties": {
    "data": { "provider": "object", "object": "deal" },
    "addRecord": { "enabled": true, "position": "top" }
  }
}
```

`sharing` is not a published input of a page node yet: the Share button has no
action the spec declares.

## Rows and cards that open nothing

A React host whose row click (`onRowClick`) opens nothing for these rows passes
`rowOpensRecord={false}` to `ListView`, which hands it to the grid, the gallery
and the board. None of them then draws a row or card as something to open: the
grid's record-link cells are plain text and its right-click menu has no Open,
and the grid's phone cards, the gallery's cards and a board card that cannot be
dragged draw no pointer and no hover lift. The click still reaches
`onRowClick`, and row and card actions stay. Absent (or `true`), nothing
changes. It is a host prop, not a schema key: list metadata cannot set it. The
console passes `false` for a view authored `navigation: { mode: 'none' }` or
`navigation.preventNavigation: true` (whatever its mode) and for an object whose
data API serves no single-record read (objectstack#33317, objectstack#33548,
objectstack#33549).

## The object's Export switch

The list's Export entry (the wide toolbar's button and the Display panel's
footer) follows the object as well as the view. An object that sets
`userActions.exportCsv: false` gets no Export entry, in any format; the object
grid and a dataset report on that object hide theirs too. All three read one
verdict, `resolveEffectiveCrudAffordances(objectDef, effectiveApiOperations).exportCsv`
from `@object-ui/core`: the authored switch over the object's `managedBy`
default, ANDed with the caller's effective `export` API operation. Unset, the
switch is on in every bucket. It hides the entry and is not a permission: who
may export is the permission set's `allowExport`.
