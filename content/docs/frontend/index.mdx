ObjectStack gives you three ways to build UI the Console does not draw for you. Pick by where the
UI runs and who renders it.

| You want to… | Use | Where it runs |
| --- | --- | --- |
| Add a custom page to an ObjectStack app | [React pages](/docs/ui/react-pages): the page source is metadata | Inside the Console |
| Read and write ObjectStack data from your own front-end | [Client SDK](/docs/api/client-sdk) (`@objectstack/client`) | Your app, any framework |
| Render ObjectStack views, forms and dashboards in your own React app | The Object UI SDK, below | Your React app |

The first path is metadata like any other page, so it is documented with [Views & Apps](/docs/ui).
The rest of this section is the Object UI SDK.

## The Object UI SDK

The Object UI SDK is the set of MIT-licensed `@object-ui/*` packages that render ObjectStack
JSON schemas inside your own React app. JSON metadata goes in, and accessible, themeable
components built with Tailwind CSS, Shadcn UI and Radix primitives come out.

```bash
npm install @object-ui/react @object-ui/components
```

The ObjectStack Console is built from these same packages: it reads your stack's metadata from
the server and renders it through the renderer and component registry described here. If the
Console already does what you need, you author metadata and never touch the SDK.

## A small schema

```json
{
  "type": "data-table",
  "caption": "Users",
  "className": "rounded-lg border",
  "columns": [
    {
      "header": "Name",
      "accessorKey": "name",
      "sortable": true
    },
    {
      "header": "Email",
      "accessorKey": "email"
    }
  ],
  "data": [
    {
      "name": "Ada Lovelace",
      "email": "ada@example.com"
    },
    {
      "name": "Grace Hopper",
      "email": "grace@example.com"
    }
  ]
}
```

That schema renders through `SchemaRenderer` once `@object-ui/components` has been imported for
its registration side effects.
