## Highlights — 18.4.0

- **A name is held per namespace, and every item has an exact address.**
  Two packages of two namespaces may each ship a flow (`b96b875`, #32507), an
  email template (`f56354c`, #32214), a webhook (`e55347d`, #32577), an `api`
  item (`45f0f81`, #32092), or an agent or a skill (`9046e02`, #31973) of the
  same name (ADR-0150). `/meta` reads an item by its namespace or `_env`, and
  `?package=X` is the exact qualifier (`6dd196d`, #31959); `/actions` and
  `/automation` call by namespace too (`ca3629f`, #31979; `da1a01a`, #32001).
  A bare read of a name two packages hold is refused, naming each holder.
- ⚠️ **A minor that breaks.** 282 of the 1,252 entries are declared breaking:
  89 graded `minor` because they narrow the metadata protocol, and 193 graded
  `patch` under the level rule. 244 of them need you to act; 38 are converted
  by `os migrate meta`. Read
  [the version number](#the-version-number-is-not-the-signal).
- **A deleted record goes to the recycle bin.** A by-id delete keeps its rows
  in `sys_recycle_bin` with a retention stamp (`25e1c1a`, #30780, ADR-0148);
  REST doors list, restore, purge and empty an object's bin, and a delete
  answer names the entry to undo (`d4a8439`, #31595).
- **A datasource can be synced in, one way.** A job pulls a mapping's
  `datasourceSource` in windows into a `synced` target (`84aabea`, #32339,
  ADR-0153), and every pull leaves a `sys_sync_run` row and resumes from the
  last committed position (`ed95466`, #32385). SQL Server (`8c75f83`, #31381)
  and Oracle Database (`3aa0b42`, #31351) join as federation dialects.
- **Mobile push.** `requires: ['push']` and the stack's `push` key turn push
  on under `os serve` (`9ebca94`, #29968), a `notify` node naming `push`
  reaches the recipient's phones through APNs and FCM (`8aa2e91`, #29794), and
  push sends through the hosted relay, authenticated by the server's cloud
  binding (`97e4249`, #30749). `@objectstack/service-push` publishes for the
  first time.
- **A field declares what it was renamed from.** `renamedFrom` on a field
  (`f108e6d`, #30934) carries the old column's values to the new key in the
  schema sync (`45916c9`, #31402), and a position declares its earlier names
  the same way (`3a83b53`, #33008). A managed upgrade that renames or retypes
  a stored field is refused until it is declared or confirmed (`40eaae7`,
  #31243).
- **Members attach files.** Every signed-in member can attach files to the
  records they may edit and see those of the records they may read
  (`fd63747`, #32932). An object that does not declare
  `enable: { files: true }` now refuses attachments for everyone. See
  [before the first boot](#3-before-the-first-boot).
- **Sign-in and access tightened.** The access policy is set per organization,
  and the multi-factor requirement has three levels (`b5696b4`, #31013); an
  account with a second factor is signed in by no one-time code or link alone
  (`bb47215`, #32236); a banned user's API keys and OAuth tokens are refused
  while the ban holds (`f4cd4ec`, #30287; `b3d2f4b`, #30360); an AI service
  account is the agent principal of its own requests (`5a8dbc7`, #31867).
- **Four new `os migrate` commands.**
  `os migrate stored-references` (`0cd594b`, #31961),
  `os migrate stored-expressions` (`cd5f554`, #30227),
  `os migrate blank-multi-values` (`b13fc74`, #30508) and
  `os migrate recompute-home-amounts` (`31fe289`, #30183). See
  [after the boot](#4-after-the-boot).

## What's new in 18.4.0

### The version number is not the signal

Every package still versions in lockstep. The level of a release says whether
**the metadata protocol** moved, and nothing else:

| Kind of change | Level |
| :--- | :--- |
| Added to the metadata protocol: a new authorable key, accepted value or metadata type | `minor` |
| Narrowed or retired: a key removed or tombstoned, a value refused, a requirement tightened | `minor` |
| Semantic: the meaning or default of an authorable key changes | `minor` |
| Everything else: REST, drivers, services, the CLI, the Console, `feat:` and `fix!:` alike | `patch` |

So 18.4.0 carries 193 entries graded `patch` that say **BREAKING**, beside
89 graded `minor`. Of all 1,252, 169 are graded `minor` and 1,083 `patch`;
none is `major`. Pin exact versions of both scopes, and read the release
notes for every version you cross.

## Upgrade checklist

⚠️ For an 18.3.0 app. From 18.2.0, walk the
[18.3.0 checklist](/docs/releases/v18/18-3#upgrade-checklist) first, and so
on back to the [18.0.0 checklist](/docs/releases/v18/18-0#upgrade-checklist)
from 17.x.

### 18.4.0

<Callout type="warn">
**How far this list has been walked.** Once, by the post-release smoke
(#33105, cell D1): an app made by `create-objectstack@18.3.0` on its default
file database, with a user, a record and a setting written on 18.3.0, was
moved to 18.4.0, and everything read back. It ran the pin move, `os validate`,
`os build`, `os migrate plan`, `os migrate stored-references` (with and
without `--dev`), `os migrate stored-expressions`, the 18.4.0 boot and
`os migrate apply`; it did not run `blank-multi-values` or
`recompute-home-amounts`. That app declares one object and nothing a
narrowing below refuses, so the walk shows the commands run on an upgraded
database, not the refusals. The rest is compiled from the changesets; each
step names the entry it comes from.
</Callout>

#### 1. Move the pins

- **Move every `@objectstack/*` dependency, and every `@object-ui/*` one, to
  `18.4.0` together**, with `@objectstack/skills` and `create-objectstack`
  where you use them. Pin the exact version: a caret range takes every later
  18.x by itself, and a patch can break a non-protocol surface.
- **Drop `@object-ui/providers`**, which does not publish 18.4.0: its upload
  context is in `@object-ui/fields` and `@object-ui/data-objectstack`
  (`7a5f73e`).

#### 2. Run the build, and fix what it refuses

```bash
os validate
os build
os migrate meta --from 17     # the protocol-18 step, with this release's entries
```

Fix each refusal with its line in [需手动处理](#action-required) or
[自动迁移](#migrated-for-you). The ones an app is most likely to meet:

- a `manifest.namespace`, the stack's own or a `packages[]` body's, equal to
  `actions`, `connectors`, `global`, `hooks`, `oauth` or `trigger`: `os validate`
  and `os build` refuse it, and install also refuses `runs` (`93f0d43`,
  `ba8e993`). Rename the namespace;
- a namespace equal to an object name, or an object short-named `custom`
  (`2b3e3eb`), and inside one namespace a sharing rule, queue, assignment
  rule, hook, job, app, page, dashboard, report, book, cube or tool name that
  another package of the namespace already holds (`d655caf`);
- a field naming a sibling package's picklist without a declared dependency
  on that package (`80c4c9a`), and a select field bound to a picklist no
  loaded package declares (`699ebd8`);
- an object extension that re-declares an owner's field in `fields` beyond
  its display properties: write the change in `fieldPatches` (`a91ad42`);
- a flow with no `start` node, a node no edge reaches, or a text-vs-number
  comparison in a flow condition (`b2c0202`, `11c1326`, `9037b13`, `e8afd1e`),
  and a date or datetime field handed straight to a call that takes a
  timestamp (`4f1de9f`);
- a field marked `sortable: false` that a stored sort or a list view sorts by
  (`140d8ce`, `3a27208`, `c133cfe`), and a dataset or cube dimension over a
  formula field (`b618224`);
- a record page that places no component (`f0f729e`), and a `type: 'module'`
  package that defines more than one app (`9ae8291`);
- the `objectstack.manifest.json` keys `name`, `specVersion`, `skills`,
  `scaffold`, `visibility`, `publisher` and `isStarter`, and the single
  marketplace `category`, which the taxonomy facets replace (`a1afbb9`,
  `150f740`, `468e0c1`).

#### 3. Before the first boot

- **Declare `enable: { files: true }` on every object that takes
  attachments.** The storage service now enforces the opt-in itself, so on a
  composition that did not enforce it before, an object without it refuses
  every new attachment, administrators and the system path included, with
  `403 FILES_DISABLED`; attachments already stored stay (`fd63747`). The blank
  starter's `note` object declares no opt-in: the smoke's dev administrator
  was refused there (#33105, O1). In return, every signed-in member can attach
  to the records they may edit, and a member who can read but not edit a
  record is refused with `ATTACHMENT_PARENT_ACCESS` instead of
  `PERMISSION_DENIED`, still `403`.
- **Read email templates by their package.** Once two packages hold one
  template name, a read or a send that does not name the holder answers
  `409 RESOURCE_CONFLICT` naming both, and a packaged flow's `notify` template
  held only outside the package's dependencies fails its delivery with `409`
  (`f56354c`). The same holder rule refuses a bare by-name read on `/meta`,
  `/actions` and `/automation` where two packages hold the name (`6dd196d`,
  `ca3629f`, `da1a01a`).
- **Set `OS_AUTH_SECRET` on a declared multi-replica deployment** on the
  Redis cluster driver: `os start` refuses to boot without it (`470339e`), and
  `os serve` refuses a database local to each replica (`a386585`) and a local
  storage root not declared shared (`d5a3ad3`).
- **Keep one data-key file.** When two hold different keys, `os start` and
  `os dev` read with the one that opens the stored secrets, or a production
  boot refuses (`f6f663a`).

#### 4. After the boot

- **Run `os migrate plan`, then `os migrate apply`**, after the first boot on
  18.4.0. The activation ledger is keyed by `(metadata_type, package_id, name)`
  from this release (`5b7269f`), and on an 18.3.0 file database the smoke's
  first 18.4.0 boot left `sys_metadata_activation`'s unique index on
  `(metadata_type, name)` until a second boot or `os migrate apply` widened it;
  data reads were unaffected (#33105, O3). After `apply`, a second `plan`
  shows no change. `os migrate plan` on a database 18.4.0 has not booted yet
  may print a `DATABASE_ERROR … no such column: permission_set_package` line
  before a correct plan (#33105, O2).
- **Run `os migrate meta --stored`** to list and rewrite the stored rows the
  conversions touch.
- **Run `os migrate stored-references` with the deployment's composition**:
  `--dev` for an app served by `os dev`, or the `--preset` the deployment
  boots `os serve` with, and the deployment's `OS_AUTH_SECRET` in the
  environment. It lists the stored references the package-column backfills
  left naming no package, with every candidate, the names held twice and any
  installed namespace that spells an address literal (`0cd594b`, `93f0d43`);
  `os migrate stored-references bind` writes one reviewed row. It is read-only
  and exits 0 when the report ran. Run without the composition it reads less
  and still exits 0: on the smoke's dev app with no `OS_AUTH_SECRET` it read no
  `sys_user_permission_set`, `sys_audience_binding_suggestion` or
  `sys_approval_request`, and with `--dev` only `sys_approval_request` stayed
  unread (#33105, O4).
- **Run the stored-value commands, a dry run first and then `--apply`**:
  - `os migrate stored-expressions` fills a stored computed field (a
    non-`formula` field declaring `expression`) on the rows stored before it
    was declared, which hold `NULL` until each is next written; `--changed`
    also rewrites values after an expression changed (`cd5f554`). The boot
    names the command when a sample of rows needs it.
  - [`os migrate blank-multi-values`](/docs/deployment/cli#os-migrate-blank-multi-values)
    rewrites the `[]` and `''` still stored on optional multi-value columns to
    `null`, the form a cleared value is stored in now (`b13fc74`).
  - [`os migrate recompute-home-amounts`](/docs/deployment/cli#os-migrate-recompute-home-amounts)
    `--object <name>` recomputes the home-currency amounts a `record`-mode
    amount stores, at the rates in force now: run it after an exchange rate
    is corrected or added. Rows it cannot convert are listed and skipped, and
    keep its exit code at 1 until a re-run converts them (`31fe289`,
    `e2bcd5c`).
- **Update API clients for the doors that refuse what they used to serve**: a
  bare by-name read of a name two packages hold, on `/meta`, `/actions`,
  `/automation` and the dataset doors, answers `409` naming each holder
  (`6dd196d`, `5192297`, `fb71296`), and a qualified read takes
  `/meta/:type/:ns/:name` or `?package=`. A host that forwards to
  `AuthManager.handleRequest` now runs the mount-layer checks, so a request it
  admitted before can be refused, for example `403 IP_NOT_ALLOWED` (`19f9053`).
- **Check who can still sign in and act.** An account with a second factor is
  signed in by no one-time code or sign-in link alone (`bb47215`); a person's
  data access needs a current membership in the organization under every
  tenancy posture (`e542831`); a member removed from an environment is refused
  on their next request (`3631d11`); and an AI service account acts as the
  agent principal of its own requests, under the agent ceiling (`5a8dbc7`).
