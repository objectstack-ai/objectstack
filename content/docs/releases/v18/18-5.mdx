## Highlights — 18.5.0

- ⚠️ **A minor that breaks.** 67 of the 284 entries are declared breaking:
  24 graded `minor` because they narrow the metadata protocol, and 43 graded
  `patch` under the level rule. 45 need you to act; 22 carry an
  `os migrate meta` entry that lists what to check. Read
  [the version number](#the-version-number-is-not-the-signal).
- **The HTTP server holds a request-body limit.** A JSON, form or other body
  over 10 MiB is answered `413 PAYLOAD_TOO_LARGE` and is not read past the
  limit; `maxRequestBodyBytes` and `OS_HTTP_MAX_BODY_BYTES` raise it, and the
  storage upload doors keep their own limit (`67274ac`, #33172). A request
  path holding a backslash is answered `400` (`d4fbb4d`, #33225).
- **Single sign-on links accounts only where the provider has proven the
  domain.** With SSO domain verification on, a sign-in links to an existing
  account, or changes its email address, only at a domain the provider lists
  and has verified (`de5eb08`, #33307). A provider's domain list takes bare
  host names (`3c42e63`, #33267), an SSO provider creates an account only for
  an email address (`3c44a97`, #33418), and an Entra ID SAML provider keys its
  accounts on the object id (`480246b`, #33490).
- **Connectors and tools are held per namespace.** Two packages of two
  namespaces may each declare a connector of the same name, each materialized,
  connected and dispatched as its own instance (`322ded7`, #33431;
  `199e362`, #33218; `687e0a5`, #33281), and each ship a tool of the same name
  (`c747cf0`, #33124). A bare read of a name two packages hold is refused,
  naming both.
- **A disabled package holds no name.** The `/meta` reads and lists, the flow
  and connector doors and the email template send judge only the packages that
  serve a name (`02f55c5`, #33130; `3269cab`, #33405; `06b5669`, #33646;
  `9951f46`, #33361).
- **Refusals and advisories in the caller's language.** A metadata save's
  advisories and refusals (`548f8ff`, #33276), the duplicate refusal
  (`09da8c7`, #33348) and permission refusals (`a1e0402`, #33290) read in the
  caller's language, falling back to the workspace default, and the Console
  shows the server's sentence (`d95ddeb`, #33576).
- **Authoring.** `i18n.sourceLocale` names the language inline metadata text
  is written in (`0be91f0`, #33357); a hook written as a TypeScript `handler`
  can declare `refusals`, and a refusal code can hold several sentences
  (`53f5a4c`, #33641); a `controlled_by_parent` detail can ask read access on
  its master for writes (`df9fe94`, #33369); and analytics filters on a
  related record's field (`498c967`, #33512).
- **A new `os migrate` command.** `os migrate audit-side-copies` rewrites the
  audit copies written before the audit writer stopped copying another
  record's field values (`4e1d327`, #33607).

**Breaking: `os audit verify` fails on a row two checkpoints list**
(`ac0b9a5`, #33637).

- **From → to.** The 18.4.0 `os audit verify` passed a chain in which two
  checkpoints list the same row id. 18.5.0 reports it as a chain fault of the
  new kind `listed_twice`, naming the checkpoint and the rows, and exits `1`.
  The second listing holds nothing for that row. An 18.4.0 sealer could write
  such a chain when two of its late sealings overlapped: two replicas with no
  cluster service, whose lock is in-process only, or a lease that lapsed. A
  chain one sealer wrote at a time is not affected.
- **What to do.** Run `os audit verify` after the upgrade and read every fault
  it names. No tolerance and no repair ships for `listed_twice`, so a chain an
  overlapping 18.4.0 sealer wrote keeps failing the run; keep the report
  (`--json`, or the proof bundle `--out` writes) as the record of why. The
  18.5.0 sealer writes no new one: a late checkpoint leaves out every row a
  checkpoint stored meanwhile already lists (`f4cafd5`).
- **The checkpoints change shape.** A window now seals into checkpoints of at
  most 10,000 rows each, whose signed body carries `part_index` and
  `final_part`, stored in two new nullable columns of `sys_audit_checkpoint`.
  An 18.4.0 verifier fails the signature of every checkpoint that carries
  them, and the next checkpoint an 18.4.0 sealer writes is a `link` fault:
  roll back to 18.4.0 only before 18.5.0 seals its first checkpoint.

## What's new in 18.5.0

### The version number is not the signal

Every package still versions in lockstep. The level of a release says whether
**the metadata protocol** moved, and nothing else:

| Kind of change | Level |
| :--- | :--- |
| Added to the metadata protocol: a new authorable key, accepted value or metadata type | `minor` |
| Narrowed or retired: a key removed or tombstoned, a value refused, a requirement tightened | `minor` |
| Semantic: the meaning or default of an authorable key changes | `minor` |
| Everything else: REST, drivers, services, the CLI, the Console, `feat:` and `fix!:` alike | `patch` |

So 18.5.0 carries 43 entries graded `patch` that say **BREAKING**, beside 24
graded `minor`. Pin exact versions of both scopes, and read the release notes
for every version you cross.

### 需手动处理 — breaking changes you must act on [#action-required]

The 45 entries that are breaking and carry no registered ADR-0087 entry. Each
line says what now answers differently and what to do, from the changeset
under its commit; the CHANGELOG entry gives the full before and after. The
[upgrade checklist](#upgrade-checklist) puts the ones an app is most likely to
meet in order.

#### The HTTP server and API clients

3 entries.

- **A request body over 10 MiB is answered `413 PAYLOAD_TOO_LARGE`** on the
  data, API and auth routes of both HTTP doors, the self-hosted server and
  `createHonoApp`, and is not read past the limit. To keep larger bodies,
  raise the limit: `maxRequestBodyBytes` on `HonoServerPlugin` or
  `createHonoApp`, `HonoHttpServer.setMaxRequestBodyBytes()`, or
  `OS_HTTP_MAX_BODY_BYTES`. Or send the content as a file through a storage
  upload door, which keeps its own `max_upload_mb` limit (`67274ac`, #33172).
- **A request path holding a backslash is answered `400 Bad Request`** by the
  Node server, before any route runs, where `GET /api/v1/data\account` used to
  reach `/api/v1/data/account`. Browsers and `fetch` already send `/`; a client
  such as `curl` sends what you write. Send the path with `/`. The same
  upgrade, `hono` ^4.13.16 and `@hono/node-server` ^2.1.6, clears seven public
  advisories, and a streamed response whose stream fails in its first two
  reads is now a `500` instead of a truncated `200` (`d4fbb4d`, #33225).
- **`POST /api/v1/messaging/in-app-messages` no longer answers `200` when
  nobody received the message.** `recipients` counts only the people a
  delivery was accepted for; a send that reached nobody is `503
  SERVICE_UNAVAILABLE` when every delivery failed. Read a `200` as "at least
  one person", and handle the refusal (`118d37a`, #33347).

#### Security, identity, sign-in and approvals

12 entries.

- **SSO account linking needs a proven domain.** With SSO domain verification
  on, an SSO sign-in links to an existing account, or changes its stored email
  address, only at a domain the provider lists and has verified, matched
  exactly; a subdomain that is not itself listed is refused
  `EMAIL_DOMAIN_NOT_ALLOWED`. Before people at a subdomain first sign in
  through the provider, list that subdomain on the provider and verify it
  (`de5eb08`, #33307).
- **An SSO provider's domain list takes bare host names only.** Registering or
  editing a provider with `https://acme.com` or `acme.com:443` is refused `400
  VALIDATION_FAILED`, naming the entry. Write `acme.com`; for a provider
  already holding such an entry, send the bare names as `domain` to `POST
  /api/v1/auth/sso/update-provider` and verify the domain again (`3c42e63`,
  #33267). The boot warns about each stored provider with such an entry
  (`03dc626`, #33477).
- **The domain-verification request uses the provider's registered domain.**
  `POST /api/v1/auth/admin/sso/request-domain-verification` ignores a `domain`
  in the body; a provider whose domain list names no host is answered `400
  DOMAIN_VERIFICATION_FAILED`. A script reads the answer's `domain` and
  `dnsRecords` instead (`7e2eadd`, #33314).
- **An SSO provider creates an account only for an email address.** A SAML or
  OIDC sign-in that resolves a person to an opaque NameID or a user name no
  longer creates an account; an unmapped SAML sign-in reads the standard
  email and name claims before the NameID. Existing accounts still sign in.
  For a provider whose users are created this way, map an email attribute
  (`3c44a97`, #33418).
- **An Entra ID SAML provider keys its accounts on the object id.** Accounts
  made before keep their NameID key, and a sign-in now reaches them only
  through the account's email. For a provider that is not Entra ID and whose
  NameID differs between the sign-in page and the portal, name a stable
  attribute in `mapAccountKey` (`480246b`, #33490).
- **With SSO-only mode on, an IdP-provisioned user is given no local
  password.** `POST /set-initial-password`, the administrator's Set Password
  action and both reset doors answer `409 RESOURCE_CONFLICT` and write
  nothing; a platform administrator may still set their own (`30e364e`,
  #33177).
- **Under direct sign-in with the local path `off`, the last identity provider
  cannot be deleted** (`409 DELETE_RESTRICTED`) unless another way in remains.
  Register another provider first, or set
  `OS_AUTH_DIRECT_SIGN_IN_LOCAL_PATH=hidden` with email and password sign-in
  on (`a27d88d`, #33623).
- **The last platform administrator cannot switch `admin_full_access` off**
  when nobody could switch it back on. To switch it off, first declare a
  platform owner in `OS_PLATFORM_OWNER_EMAIL` (`d4cfbfb`, #33424).
- **Ban works without the better-auth admin plugin.** On a deployment with the
  admin plugin off, a row whose `sys_user.banned` is true is now refused a
  session with `403 BANNED_USER`. Before upgrading such a deployment, list the
  banned users, platform administrators first, and unban each one who should
  keep signing in: turn the admin plugin on, call `POST /admin/unban-user`,
  and turn it off again. The same change lets a managed environment add
  pending, SSO-only people with their positions, permission sets and manager
  (`cbb876c`, #33227).
- **The Setup › Diagnostics › Audit Log entry follows `view_all_audit_log`.**
  A custom permission set that grants `manage_platform_settings` without
  `view_all_audit_log` no longer shows the entry; grant it, or open the page by
  URL. A package entry contributed into `group_diagnostics` without its own
  `requiredPermissions` is now shown to every member who can open Setup:
  declare `requiredPermissions` on it (`8a8c21e`, #33349).
- **An out-of-office delegation with an inverted window, or with the
  delegator as their own delegate, is refused** `400 VALIDATION_FAILED` on
  `valid_until` or `delegate_id`; both shapes were stored and never rerouted an
  approval (`0bd902c`, #33284).
- **An approval request whose flow package was uninstalled is refused** `409
  RESOURCE_CONFLICT` when another package ships a flow of the same name,
  instead of being answered from that other flow. Install the request's
  package again to act on it (`b96dd30`, #33297).

#### Namespaces, packages and metadata reads

17 entries. A name two packages hold is read by its package (`?package=`, the
namespace address, or `/meta/:type/:ns/:name`); a bare read of it is refused
`409 RESOURCE_CONFLICT`, naming each holder.

- **A connector name two packages hold is refused at a bare read** (`GET
  /meta/connector/NAME`, `MetadataManager`, the history and rollback doors);
  an environment-authored flow's `connector_action` naming such a connector is
  refused naming both; a flow whose connector resolves to a package with no
  live instance is not dispatched; and a connector pull of a name with two
  instances answers `409 connector_name_refused`. Address the connector by its
  package. Ten moved answers are listed in the entry (`322ded7`, #33431).
- **A disabled package holds no name at the flow and connector doors.** A bare
  `/automation` name, the flow action and endpoint, and the connector address
  now count only the packages that serve a name. Re-enable the package, or
  address the serving holder by its namespace (`06b5669`, #33646).
- **A disabled package holds no name at the email template send.** A send of
  a name a disabled package holds resolves over the serving holders, and a
  caller whose own holding is the disabled one finds no template. Enable the
  package (`9951f46`, #33361).
- **A disabled package's customization pair and a dependent's added locale
  are left out of the metadata lists** (`GET /meta/email_template` and the
  execution list) while the package is disabled. Re-enable it to list them; a
  dependent's addition stays readable at the dependent's own address
  (`3269cab`, #33405).
- **A name a disabled package holds through a stored row is judged over the
  serving holders**: two enabled packages' rows of it answer `409` naming both,
  where save order decided, and an address naming a disabled customization
  pair answers `404`. Read each by its package (`02f55c5`, #33130).
- **Two packages' declared overrides of one flow or action name** each serve
  in their own package's slot, and the env-wide flow and action lists no
  longer carry an entry stamped with one package that holds the other's
  override. Read each override from its own entry, or by `?package=`
  (`8403725`, #33126).
- **The history and rollback doors refuse a bare two-holder name.** `GET
  /meta/TYPE/NAME/history` and `POST /meta/TYPE/NAME/rollback` of a name two
  holders hold answer `409`; add `?package=PKG`, once per holder the refusal
  names, and roll back to one of that holder's versions (`b462444`, #33193).
- **A function name the platform and a package both register is refused at a
  bare read**, naming both, and a name only a disabled package registers
  resolves to nothing. Address it by package (`resolvePackageScopedFunction`,
  or a packaged flow), rename one of the two, or enable the package
  (`5ea8ce5`, #33439).
- **The action activation door answers a two-holder name with `409`**, naming
  both, instead of `404` "has no declaration". Read the `409` as two holders;
  the door switches the name once one package holds it (`d3ceb1d`, #33399).
- **The action route answers by who holds the name on the routed object.** An
  action name held by a disabled package on the route, the environment on that
  object and one package elsewhere now answers "no declaration" there. Enable
  the package, remove its action, or address the environment's action at
  `/api/v1/actions/_env/OBJECT/NAME` (`0c2aeb9`, #33274).
- **An action authored in the environment on a packaged object is the
  environment's.** MCP `run_action` and `POST /actions/NAMESPACE/OBJECT/NAME`
  with the object's package namespace answer `404` for it. Call it by the face
  `list_actions` lists (`OBJECT-NAME`), its bare name, or
  `POST /actions/_env/OBJECT/NAME`; bind a flow action meant for a package's
  flow with `?package=` (`a752057`, #33071).
- **An install-local uninstall withdraws the package's action handlers and
  body hooks at once.** A call naming no package on a key another owner still
  holds now runs that owner's handler, and that owner's gates (`403`, `409
  ACTION_DISABLED`, `503`) can answer, as a restart already did. Nothing
  persisted changes (`ea67b26`, #33622).
- **`unregisterPackage` keeps the stored rows that name the package by the
  `_packageId` stamp alone.** Over a `DatabaseLoader`, the package's `object`,
  `view`, `app` and `page` items among them are now kept and reported. Run
  `detectStampOnlyRows`, then `unregisterPackage(P, { force: true })` or
  `unregisterPackageWithReport` to remove the package's own items. Rows that
  `@objectstack/metadata` 17.0.0–18.3.0 stamped with the host's package are
  the environment's: the entry says how to find them (`3825f57`, #33416).
- **On a host that wires a `DatabaseLoader`, an action is held per
  `(object, name)`.** A package-less save on an object no package binds the
  name to is the environment's own row, and a read naming a package reaches
  only that package's own binding: save the row as the package's
  (`_packageId`) if it is the package's (`fc283d6`, #33318; `0e9ff94`,
  #33422).
- **A boot no longer turns a name two packages' rows hold into one body.** On
  a host that wires a `DatabaseLoader`, a bare read of such a name after the
  boot answers `409` naming both. Name the package, or rename one of the two
  (`dd966fc`, #33299).
- **Addressed history and rollback on a name one row slot holds.** A direct
  `DatabaseLoader.registerRollback` call that addresses a package and restores
  a version recorded with no attribution, on a name several row slots hold, is
  refused naming every holder. Save the body into the package's row instead
  (`8c88db6`, #33464).

#### Flows and automation

1 entry.

- **A record-triggered flow is not armed while a subflow it calls retries an
  inline outbound call.** It still registers, warns once naming the call and
  the retried node, and `GET /automation/_status` reports it `bound: false`
  with `unboundCause: 'retried_callout_in_subflow'`. In the child the warning
  names, set `durable: true` on the `http` node, or remove the retry. A
  durable `http` node on a host with no messaging outbox is sent once in the
  background on the save path, not retried: wire the messaging service with
  reliable delivery to keep retries (`7ffbb1a`, #33265).

#### Metadata the build, lint and publish doors judge

3 entries.

- **The `object_extension` publish door folds the written entry among other
  packages' extensions by priority**, so it judges the definition `os build`
  judges: a formula cycle closed through a higher-priority package's field is
  refused, and a tie or an outranked entry `os build` accepts now publishes.
  Break the cycle, or rename the entry's field (`ee627c6`, #33702).
- **MCP `validate_expression` gives the publish gate's verdict** at a
  `validation` or `formula` site (`b22be27`, #33134) and at a `flow_condition`
  (`8835532`, #33168), so it answers `ok: false` for an expression the gate
  already refuses. Nothing the gate accepts moves; fix the expression the tool
  now names.

#### The data engine, seeds and import

3 entries.

- **A seed load for one organization writes as that organization.** Under a
  walled tenancy posture, a hook on a seeded row, and every engine read the
  write triggers, sees what a person of that organization sees. A hook that
  needs every organization's rows uses `ctx.api.sudo()` and filters them
  itself. A reference to a person resolves only to a member of that
  organization (`47a3b95`, #33222).
- **A seed that names a person by an id-shaped value is judged by
  membership.** If the person is not a member of the load's organization, the
  row is seeded with the reference empty and the load's error says so. Add the
  person to the organization, or name a member (`b95d915`, #33611).
- **A data import resolves a lookup cell within the row's own master.** A row
  that names a master and a detail only another master carries is refused
  `reference_not_found`, where it was linked across masters; and a caller who
  cannot read the target's master field is refused `reference_not_found` for a
  scoped cell. Fix the row's master, or grant read on that field. Rows that
  were refused `reference_ambiguous` now resolve (`b070e1c`, #33613).

#### Analytics and datasets

1 entry.

- **`query_dataset` refuses a selection with no measure**, `400
  VALIDATION_FAILED`, as `POST /api/v1/analytics/dataset/query` does, where
  the SQL driver answered `500`. Name at least one measure, as `list_datasets`
  lists them (`bf02d33`, #33141).

#### Files and storage

2 entries.

- **An upload link onto a file field whose `readonlyWhen` holds is refused at
  issue**, `403 FIELD_NOT_ACCESSIBLE`, and no link is written. Mint the link
  once the record's state unlocks the field, or use the record's attachments
  (`5430b4a`, #33079).

### 18.5.0

<Callout type="warn">
**This list has not been walked.** It is compiled from the changesets, ahead
of the cut; each step names the entry it comes from.
</Callout>

#### 1. Move the pins

- **Move every `@objectstack/*` dependency, and every `@object-ui/*` one, to
  `18.5.0` together**, with `@objectstack/skills` and `create-objectstack`
  where you use them. Pin the exact version: a caret range takes every later
  18.x by itself, and a patch can break a non-protocol surface. No package
  joins or leaves npm in this release.

#### 2. Run the build, and fix what it refuses

```bash
os validate
os build
os migrate meta --from 17     # the protocol-18 step, with this release's entries
```

Fix each refusal with its line in [需手动处理](#action-required) or
[自动迁移](#migrated-for-you). The ones an app is most likely to meet:

- an object that shows two visible fields under one label, a field of your
  own labelled like the injected `owner_id` the common case (`3cbf1f2`);
- a `nameField`, `displayNameField` or `activityMilestones[].field` naming no
  field of the object (`6222ecb`);
- a cycle of formulas, on the object or through an object extension
  (`6482c08`, `0ba30eb`), and an extension's computed field, validation rule,
  lookup leaf or record-mode amount that the object's own passes refuse
  (`3e19223`, `27d042f`, `bc50d11`, `06e53a7`);
- a `connector_action` whose input holds a key its action does not declare
  (`89defde`), which fails at run time, not at the build;
- a `packages[]` stack whose second app, or whose body objects' namespace
  prefixes, strict `defineStack` now judges per body (`2c98485`, `5b2ec82`),
  and a dashboard widget whose dataset sits outside the reader's declared
  dependencies (`40c73a8`).

#### 3. Before the first boot

- **Raise the request-body limit if your clients send bodies over 10 MiB**:
  `maxRequestBodyBytes`, or `OS_HTTP_MAX_BODY_BYTES` (`67274ac`).
- **Without the better-auth admin plugin, unban who should keep signing in.**
  Ban is enforced there from this release; list the users whose
  `sys_user.banned` is true, platform administrators first, and unban each one
  through the admin plugin before upgrading (`cbb876c`).
- **With SSO domain verification on, list and verify every subdomain** your
  people's existing accounts use before they next sign in through the
  provider, and rewrite a stored provider's domain entries as bare host names
  (`de5eb08`, `3c42e63`).
- **Declare `OS_PLATFORM_OWNER_EMAIL`** if you may need to switch
  `admin_full_access` off on a deployment whose platform administrators all
  hold it through the Default Organization (`d4cfbfb`).

#### 4. After the boot

- **Run `os migrate audit-side-copies`, a dry run first, then `--apply`.** It
  removes the side-copy columns that audit and activity copies written before
  this release still carry, on the live tables and the archive. Until it runs,
  the read-time redaction drops them, so it is cleanup, not a gate
  (`4e1d327`).
- **Update API clients for the doors that answer differently**: a bare read of
  a connector, tool, function or stored-row name two packages hold answers
  `409` naming each holder (`322ded7`, `c747cf0`, `5ea8ce5`, `d635599`); the
  history and rollback doors take `?package=` (`b462444`); a path with a
  backslash is `400` (`d4fbb4d`); an in-app message that reached nobody is
  refused (`118d37a`); and `query_dataset` needs a measure (`bf02d33`).
- **Check seed hooks under a walled posture**: a hook on a seeded row reads as
  the load's organization, so a hook that needs every organization's rows says
  so with `ctx.api.sudo()` (`47a3b95`).
- **On PostgreSQL, check `date` fields converted from `datetime` on a release
  before 18.4.0** for values stored one day early, as the `driver-sql`
  CHANGELOG entry describes (`01d206d`).
