## Highlights — 18.1.0

- ⚠️ **A minor that breaks.** 18.1.0 is a minor version, and 91 of its
  changesets are declared breaking. Under the level rule the maintainer ruled
  on 2026-10-21 (#25105, "ruling A"), the v18 line takes no further major: a
  change to the metadata protocol takes `minor`, and every other change takes
  `patch`, breaking or not. A non-protocol breaking change keeps its
  **BREAKING** banner and its ADR-0087 disposition. A `^18.0.0` range resolves
  18.1.0 by itself. Read [the version number](#the-version-number-is-not-the-signal)
  before you let it.
- **ADR-0131's last steps: an organization-less row confers nothing.** A grant row
  with no organization applies nowhere (`94842ba`, #24872), a settings or
  localization row with no organization answers no organization's read
  (`279fdcf`, #25226; `d196748`, #25301), the first organization no longer
  adopts orphaned rows (`e3190b9`, #25246), and a table the SQL and Turso
  drivers create carries its tenant column `NOT NULL` (`5e9b100`, #24940). On a
  database 18.0.0 created or the ownership ceremony certified, none of these
  rows exists.
- **A production `os serve` with no organization object is refused.**
  `--no-server` no longer gets round it (`ab488d9`, #25155), and neither does a
  `@objectstack/plugin-auth` that fails to load (`b2e964f`, #25231).
- **Nine metadata narrowings come with a conversion** that `os migrate meta`
  and the stored-row loaders apply: the `addRecord` block, `user` fields that
  reference another object, `has()` in `visibleWhen`, the `Field.select`
  shorthand, turso `encryptionKey`, the docs-viewer keys, `external` on a
  managed datasource, and `sys_notification_subscription`.
- **One federation rule at every datasource door.** An object's `external`
  binding on a managed datasource is refused at parse, at `defineStack`, at the
  metadata save doors, at `composeStacks`, at the datasource admin API and by
  Sync, as ADR-0015 §4.2 declares (`fe0ec2b`, `bda53bb`, `b9c7a8f`, `72a302a`).
- **A SQLite file the driver cannot read is refused, never replaced.** A
  corrupt or non-SQLite file fails `connect()` naming the file, where a
  development boot used to move it aside and start empty (`7f99616`,
  `d6a5fa3`, `27dc53b`, `4d99158`).
- **A disabled package is disabled on every door.** REST actions and the MCP
  bridges, stdio and `/mcp`, read objects and actions from the same merged
  view the Data API serves (`258f4e6`, `eee2f0d`, `8010b64`, `a1e51d6`,
  `fb7501b`, `882372d`, `72fad92`).
- **better-auth 1.7.3 → 1.7.12**, for the security fixes published since
  (`03966ce`, #25109). Sign-ins begun before the upgrade must be started
  again.
- **A cloud-managed environment closes its local sign-up doors.** This applies
  only to a process started with `OS_CLOUD_MANAGED=1`, which ObjectStack Cloud
  sets on its hosted containers (`c6bdcac`, #25399). It ships as `patch` and
  is breaking: see [Cloud-managed environments](#cloud-managed-environments-os_cloud_managed1).
  Self-hosted deployments are unchanged.
- **An `external` membership grade for portal users** (`9019af9`, #25515). A
  supplier's or customer's portal user is a member of the organization but
  reads only its own identity rows, and reaches data only through grants made
  to it (`45f9962`, #25541). A roster object can declare **membership keys** that a row policy reads
  as `current_user.KEY` (`dc532e8`, #25513; `e5eab06`, #25528).

## What's new in 18.1.0

### The version number is not the signal

Every `@objectstack/*` package still versions in lockstep. Since ruling A, the
level of a release says whether **the metadata protocol** moved, and nothing
else:

| Kind of change | Level |
| :--- | :--- |
| Added to the metadata protocol: a new authorable key, accepted value or metadata type | `minor` |
| Narrowed or retired: a key removed or tombstoned, a value refused, a requirement tightened | `minor` |
| Semantic: the meaning or default of an authorable key changes | `minor` |
| Everything else: REST, drivers, services, the CLI, the Console, `feat:` and `fix!:` alike | `patch` |

So a **patch** release can break a REST client, a boot or a deployment
script, and 18.1.0 carries 43 changesets graded `patch` that say **BREAKING**,
beside 48 graded `minor` ones. Pin exact `@objectstack/*` versions, and read the
release notes for every version you cross. Each entry in a CHANGELOG states its
kind on its own `Metadata-protocol:` line, and the GitHub Release body groups the
entries under the same five headings this page uses.

From 18.1.0 the scaffolds follow the same advice: `npm create objectstack`,
`os init` and `os create` write the exact `@objectstack/*` version
(`18.1.0`, not `^18.1.0`), and `--in-repo` still writes `workspace:*`
(`975d5b3`, #25539). A project scaffolded earlier keeps its caret ranges until
you change them. Measured: `create-objectstack@18.1.0` wrote `"18.1.0"` for all
nine `@objectstack/*` entries, and `create-objectstack@18.0.0`, run on
2026-10-24, wrote `^18.0.0` and installed 18.1.0.

### Breaking changes you must act on

The 82 entries that are breaking and have no ADR-0087 conversion, and one boot
refusal (`db1c7cc`) that its changeset declares as an addition. Each line names
the one fix; the CHANGELOG entry carries the full FROM → TO.

#### Boot and deployment

- **A production `os serve` that composes no organization object is refused,
  `--server` or not** (`ab488d9`, #25155). In 18.0.0, a production
  `os serve --no-server` booted when auth was on with no secret, or when the
  stack mounted no auth at all, and wrote rows with no owner. Now it is refused
  like the server boot, and a migrate-and-exit job (`OS_MIGRATE_AND_EXIT=1`)
  is too. Fix: set `OS_AUTH_SECRET`, and enable auth on a stack that mounts
  none. A development boot (`os dev`, `--dev`) and an embedded kernel are not
  affected.
- **A boot with no `OS_AUTH_SECRET` uses the temporary secret on a development
  boot only** (`6abee03`, #25563). It used it whenever `NODE_ENV` was anything
  but exactly `production` (unset, `staging`, a typo); now any boot other than
  `NODE_ENV=development` or `test` throws `OS_AUTH_SECRET is required outside
  development`. `os serve` and `os start` already default an unset `NODE_ENV`
  to `production`, so CLI boots behave as before: an embedder that builds its
  own kernel is the one that meets it. Fix: set `OS_AUTH_SECRET`, or
  `NODE_ENV=development` for a local boot.
- **A production `os serve` whose `@objectstack/plugin-auth` fails to load is
  refused, naming the load error** (`b2e964f`, #25231), `os start` included.
  18.0.0 booted it without auth, silently or with one
  `⚠ AuthPlugin failed to load` warning. Fix: reinstall the deployment's
  dependencies (`npm ci`, `pnpm install --frozen-lockfile`).
- **CORS reads one admission rule at every door** (`02e6d73`, #24873). A
  loopback origin beside an origin list is admitted on a development boot only,
  and an all-host pattern with credentials on fails the boot, as `'*'` already
  did. A comma-separated `cors.origin` string passed to `createHonoApp` now
  admits each origin it lists, where it admitted none. Fix: name your origins in
  `OS_CORS_ORIGIN` or `cors.origin`, including any loopback origin a non-development
  deployment is reached from, or set `OS_CORS_CREDENTIALS=false`.
- **`OS_CLOUD_MANAGED=1` without `OS_CLOUD_API_KEY` refuses a production boot**
  (`db1c7cc`, #25306), and any value of `OS_CLOUD_MANAGED` other than `1` or empty
  is refused. A runtime that binds its control plane only through
  `CloudConnectionPlugin`'s `controlPlaneApiKey` option is refused too: set
  `OS_CLOUD_API_KEY`.
- **better-auth 1.7.12** (`03966ce`, #25109). A Magic Link, OAuth, social, SAML
  or account-linking flow begun on 18.0.0 fails after the upgrade and must be
  started again. An OIDC SSO provider whose configured issuer differs from its
  discovery document's `issuer`, even by a trailing slash, is refused with
  `issuer_mismatch`. A PKCE mismatch at `POST /api/v1/auth/oauth2/token` answers
  `400 invalid_grant`, not `401`. Fix: tell users to restart pending sign-ins,
  and set each OIDC provider's issuer to the exact string its discovery document
  publishes.
- **`os migrate apply` exits `1` when it applied nothing because a confirmation
  was missing** (`62bc129`, #25004), as every other `os migrate` subcommand with
  a `--yes` gate does. Fix: a script that means to apply passes `--yes`; one
  that only wants to know runs `os migrate plan`.

#### Organization ownership (ADR-0131)

On a database that 18.0.0 created, or that `os migrate organization-ownership`
certified, none of the rows these entries stop reading exists. They reach you
only if an embedding writes rows with no organization, or a database skipped
the ceremony.

- **A grant applies only in its own organization** (`94842ba`, #24872). A
  `sys_user_position` or `sys_user_permission_set` row with no organization
  applies nowhere, and under `single` only the Default Organization's
  `admin_full_access` grant anchors platform-admin standing (`abc25a3`,
  #25141). Fix: an embedding that composes `@objectstack/plugin-security`
  without plugin-auth registers the organization object.
- **Settings and localization read the caller's organization only**
  (`279fdcf`, #25226; `d196748`, #25301; `9d60b42`, #25350). A tenant- or
  user-scope `sys_setting` row with no organization no longer answers every
  organization. Fix: run `os migrate organization-ownership --out PLAN`, then
  save each reported value again from inside its organization. A value meant for
  every organization belongs on a key declared at scope `global`. A host that
  binds its own engine states its organization source at `bindEngine`.
- **The first organization no longer adopts organization-less rows:
  `claimOrphanOrgRows` is retired** (`e3190b9`, #25246). Fix: on a walled
  store an earlier release created, run the ownership ceremony.
- **A table the driver creates carries its tenant column `NOT NULL`**
  (`5e9b100`, #24940), so a write that names no organization is refused at the
  database. Fix: carry the organization on the write
  (`{ ...row, organization_id }` or `context.tenantId`), or declare an object
  whose rows belong to no organization with `systemFields: { tenant: false }`.
- **Deleting an organization that still owns records is refused with `409`
  and a per-table count** (`688052e`, #25016). An empty one is deleted whole,
  with its teams and organization-admin grants. Fix: delete or move its records
  first.
- **The Default Organization does not move by slug** (`09e07c2`, #25286;
  `8dfd126`, #25265). Under `single`, re-slugging another organization to
  `default` is refused `403`, and creating a second organization is refused
  when it would leave nobody who can administer. Fix: keep the slug, and move an
  `admin_full_access` grant into the Default Organization instead.

#### Metadata the build and the save doors now refuse

Each is an error at `os validate`, `os build`, `os lint` and the matching save
door (`422 INVALID_METADATA`), where 18.0.0 accepted it.

- **An HTML email template body with a hole where the mail renderer's encoding
  does not suit it** (`9127f23`, #25212), and the same for an html or mjml
  `sys_notification_template` body (`284e048`, #25258). Fix: move the hole into
  element text or a quoted plain-text attribute. For a link, declare the
  variable `type: 'url'` and write it triple-braced as the whole double-quoted
  `href`.
- **A `validations[]` rule whose predicate reads `parent`** (`c5915b2`,
  #25052). Fix: put it on the field's `readonlyWhen` / `requiredWhen`, where
  `parent` is bound, or use a lifecycle hook.
- **A page component whose `properties` is present but not an object**
  (`c0ae356`, #25067), and **a props CEL slot over the platform's parse bounds**
  (`31f0f27`, #25088). Fix: write `properties` as an object, and shrink the
  predicate (an `||` chain becomes one `in [...]` test).
- **The retired list-view `filterableFields`, named** (`b42c621`, #24878). Fix:
  delete it; a curated filter bar is `userFilters`.
- **A `controlled_by_parent` object whose one required `master_detail` is
  `readonly: true` or `system: true`** (`02ad31a`, #25181), and every write that
  sets such a reference (`0148071`, #25256). Fix: declare the reference as an
  ordinary required field, or give the object its own `sharingModel`.
- **A stack that declares a webhook while `requires` lacks `'webhooks'` or
  `'realtime'`** (`baedcec`, #25057), refused by `defineStack` with
  `STACK_WEBHOOK_CAPABILITY_REQUIRED`. Fix: add both tokens.
- **A flow `get_record` node's `limit` that is not a whole number of at least
  1** (`303aef0`, #25357).
- **A `controlled_by_parent` detail whose master the engine cannot compose a
  read over refuses the boot** (`504d8b3`, #25166), where it booted and failed
  at read time.
- **`rollbackMetaItem` and `revertCommit` refuse a version the save door
  refuses** (`69913f8`, #25312), instead of writing it back live.
- **A bulk action `confirmText` the template cannot fill** (`ecb4e69`,
  #25451): a hole over a name that is neither `count` nor one of the action's
  params, a single-brace `{x}`, logic or an unknown formatter inside a hole, or
  a blank `''`. 18.0.0 warned. Fix: write holes over `count` or the params,
  double a literal single brace, and delete a blank `confirmText`. A view
  already stored still loads. *Probed on 18.1.0:* a view saved with
  `confirmText: 'Retitle {x} notes?'` answered `422 INVALID_METADATA` with
  `` A bulk action's `confirmText` reads `{{ }}` template holes (ADR-0032 §3),
  not the single-brace `{…}` dialect `` and named `count` and the param as the
  holes it binds; `'Retitle {{ count }} notes?'` saved.
- **A row policy that reads `x in current_user.KEY` which nothing owns, at the
  permission save door** (`b531016`, #25550). It answered 200 and matched no
  rows; it is now `422 INVALID_METADATA`. An object write is now judged by the
  RLS rule too, so an object whose `defaultRowScope` the CLI refuses, or a
  write that drops a field or membership key a stored policy reads, is refused.
  The gate blames a write only for a finding it adds, and drafts are not gated.
  Fix: declare the key on its roster object's `membershipKeys`, or register the
  resolver that stages it, before publishing the policy; use `in`, not `==`;
  change the policy before dropping what it reads. A bad `membershipKeys`
  declaration (a `userField` that is not a single user reference, a
  `valueField` that is not a reference, a key declared twice) is refused at
  `os validate` and `os build` too.

#### Datasources and drivers

- **An object's `external` binding on a managed datasource is refused from
  either side of the pair** at the metadata save doors and `composeStacks`
  (`bda53bb`, #25257), and the datasource admin API refuses to make a datasource
  managed while objects bind it (`b9c7a8f`, #25431). Sync (remote tables, object
  draft, import, catalog refresh) refuses a managed datasource with `400`
  (`72a302a`, #25167). Fix: declare the source `schemaMode: 'external'` (or
  `'validate-only'`) first, then bind objects; to make it managed, remove
  `external` from the objects first.
- **A SQLite file that is not a readable SQLite database fails `connect()`,
  naming the file** (`7f99616`, #25006; `d6a5fa3`, #25080), on the wasm driver
  too (`27dc53b`, #25200). A development boot no longer moves it aside and
  starts empty, and a read-only boot no longer opens an empty in-memory database
  over a file it cannot open or create (`4d99158`, #25007). Fix: restore from a
  backup, or move the file aside yourself; an absent file is created empty.
- **`SqlDriver.findWithWindowFunctions()` serves a closed set** (`6abee03`,
  #25563), and so do `driver-sqlite-wasm` and `driver-turso`'s local and
  replica transports: the function is one of `row_number`, `rank`,
  `dense_rank`, `percent_rank` or `cume_dist`, the direction `asc` or `desc`,
  and every `partitionBy` / `orderBy` field is quoted as a column. Anything
  else answers `400 INVALID_QUERY`. Fix: use one of those; send a window that
  takes an argument (`lag`, `lead`, `ntile`) through `execute()` with bound
  parameters.
- **On PostgreSQL, `introspectSchema` reads each table in its own schema**, and
  refuses a `search_path` that reaches one table name in two schemas (`74fcec1`,
  #24920). Fix: point the connection at one schema.

#### Security: master-detail writes and delegation

- **A `controlled_by_parent` detail's update, delete and batch create ask for
  edit access on every master involved** (`b289090`, #25042; `f46ef4d`,
  #25066; `3782b2d`, #25090), and an update no longer empties a detail's
  master reference. Fix: grant the caller edit access on the master, and move a
  detail by writing another master's id, never `null`.
- **On a walled posture, a delegated (on-behalf-of) operation runs only in an
  organization the delegator belongs to** (`2e242bb`, #25101; `331613c`,
  #25150; `5801a4f`, #25288). Fix: code that builds an `ExecutionContext` with
  `onBehalfOf` by hand sets `tenantId` to such an organization, or leaves it
  unset.
- **An out-of-office delegation applies only in its own organization**
  (`b3fddd1`, #25439). A `sys_approval_delegation` row with no organization
  reroutes nothing, and logs a warning. Fix: under `single`, run the ownership
  ceremony; under a wall, recreate the delegation in the organization it is
  for.
- **A `runAs: 'system'` flow that writes `sys_user_position`,
  `sys_user_permission_set`, `sys_invitation` or `sys_member` is refused**
  `403 PERMISSION_DENIED` (`a285ff2`, #25483). Fix: run a flow that grants
  positions or permission sets as `runAs: 'user'`, so the caller's own rights
  decide; invite, cancel, change a membership grade or remove a member through the
  organization endpoints.
- **Deleting a business unit that still has child units is refused**
  (`4b8f597`, #24984). Fix: re-parent or delete the children first.

#### REST, MCP and API clients

- **A disabled package's actions are refused on REST** (`258f4e6`, #25305:
  `404 OBJECT_PACKAGE_DISABLED` on `POST /api/v1/actions/OBJECT/NAME`; `eee2f0d`,
  #25318: the "no declaration" `404` on `.../global/NAME`), and **the MCP
  bridges read the merged view**, so `list_objects`, `describe_object`,
  `list_actions`, `run_action` and the `objectstack://objects` resources agree
  with `GET /api/v1/meta/object`, and an object declared `apiEnabled: false` is
  refused by every data verb (`8010b64`, `72fad92`, `a1e51d6`, `fb7501b`,
  `882372d`). Fix: nothing if the declarations say what you mean; otherwise set
  `enable.apiEnabled`, or re-enable the package.
- **Reassigning an approval to an address that resolves to no one is
  refused** (`a57643d`, #25592): `POST /api/v1/approvals/requests/:id/reassign`
  and `ApprovalService.reassign` answer `400 VALIDATION_FAILED` naming the
  address, where a `to` nobody holds was written onto the slate and the request
  waited on no one. A user id or email must belong to a member of the request's
  organization, and `position:<name>` must have a holder there; `team:`,
  `department:` and other addresses are always refused. Fix: reassign to a
  person in the organization, or to a held position.
- **`POST /api/v1/meta/:type/:name/rollback` takes `toVersion` as a JSON whole
  number of at least 1** (`0fab7ba`, #25532), and anything else answers
  `400 INVALID_REQUEST`. The query form `?toVersion=3` still works. Fix: send
  `{"toVersion": 2}`, not `"2"` or `2.5`. *Measured in the walk:* `{"toVersion":"1"}`
  and `{"toVersion":1.5}` answered `400` with `'toVersion' (positive integer) is
  required`, and `{"toVersion":1}` rolled the view back.
- **The Data API refuses a malformed or negative page window with `400`**
  naming the parameter (`17f3c65`, #25260), and the published list-query
  schemas declare it a non-negative integer (`5f30f00`, #25300). Fix: send a
  whole count of zero or more, or leave it out.
- **A credential is honoured only in the environment whose auth service
  validated it** (`1361a5a`, #25565), on every route behind the shared REST
  auth gate: crud, actions, import and export, batch, sharing, approvals,
  analytics, search and security, scoped and unscoped. Before, an environment
  with no `auth` service of its own fell back to the default environment's.
  A mismatch now answers the same `401` as an unauthenticated request. Only a
  multi-environment host whose per-environment kernels carry no `auth`
  service meets it; a single-kernel deployment is unchanged. Fix: give each
  environment's kernel its own `auth` service, and sign in to the environment
  you call.
- **`GET {base}/docs`, the OpenAPI HTML viewer page, is retired**
  (`1b3b65e`, #25124). `GET {base}/openapi.json` stays: point your own viewer
  at it.
- **The `/meta` read doors no longer serve a webhook's `secret` or `headers`**
  (`e939357`, #25036).
- **The CSV export marks a text cell its consumer would interpret** with one
  leading apostrophe, and the CSV import reverses it (`c4b49c3`, #25130). A
  program that reads the export some other way strips that apostrophe itself.
- **OAuth application registration takes `web` or `native` only**
  (`5872450`, #25038; `ba244f1`, #25099). Another type is refused
  `400 INVALID_REQUEST`, where it was registered as `web`.
- **`POST /api/v1/packages/:id/adopt-orphans` refuses a read-only package**
  with `422 WRITABLE_PACKAGE_REQUIRED` (`4cef6e2`, #24861). Adopt into a package
  you own.
- **A cloud-fetched marketplace install whose package ships a position,
  permission set or capability name an environment-authored item holds is
  refused** before any write (`8d9e8b9`, #25435), as the file-import install
  already was.
- **A marketplace upgrade that would un-make an access choice is refused until
  it is confirmed** (`448374d`, #25355). Re-send the request with
  `"confirmAccessUpgrade": "<findingSet>"`, or run
  `os package install <package> --confirm-access-upgrade <findingSet>`; the
  token confirms exactly the findings it names.

#### Messaging, settings and Cloud Connection

- **`sys_notification_template` refuses a row for a channel other than `email`
  or `sms`** (`d68aab6`, #25028), and an html or mjml body escapes every hole's
  value for markup (`a39389e`, #25076). Fix: delete or re-channel the row; move
  markup a payload carried into the template body.
- **A notification preference's User is a `sys_user` reference**, and the
  default for every user is an empty User instead of `'*'` (`e282f32`,
  #25178). The boot rewrites the old `'*'` rows and reports a collision it
  cannot resolve.
- **A settings value that misses the format of its `email`, `url`, `phone` or
  `color` type is refused**, saved or set as an `OS_*` override (`3b3830c`,
  #25022). Fix: correct the value, or unset the variable.
- **Branding drives the console's name, logo and colour under `single`**,
  `theme_mode` and `support_email` are retired, and under `group` and
  `isolated` the Branding namespace is not offered (`78ab647`, #24959). On a
  walled deployment `OS_BRANDING_WORKSPACE_NAME` no longer names sign-in emails
  and the authenticator entry: set `OS_APP_NAME` instead.
- **Cloud Connection follows one rule** (`c71d03a`, #25143; `ae58b26`,
  #25110). Its page and its connect and disconnect requests require
  `manage_platform_settings`, so an organization administrator holding only
  Setup Access loses them. A runtime holding the environment service key is
  platform-managed: it serves no Cloud Connection page and refuses to
  disconnect.

#### Cloud-managed environments (`OS_CLOUD_MANAGED=1`)

`c6bdcac` (#25399) is graded `patch`, because no metadata moves, and is
**BREAKING** for a process started with `OS_CLOUD_MANAGED=1`. Under that mode,
every audience posture but `invite_only` is refused, email sign-up is off,
member invitations (resends included), admin create-user and import-users
answer `409 RESOURCE_CONFLICT`, an admin password set on an identity-provider
account is refused, and only a platform administrator may set a first password.
People are invited from the organization in the cloud console and arrive on
their first sign-in; keep a local password only for the break-glass
administrator. **A self-hosted deployment, which does not set the variable, is
unchanged.**

### Converted for you by `os migrate meta`

Nine narrowings carry an ADR-0087 conversion on the protocol-18 step. A live
author is refused at parse, with the prescription. Stored rows and built
artifacts are converted where they load, and `os migrate meta --from 17` lists
the edits for your sources (`--write` applies the ones it can trace to one
literal). `os migrate meta --stored` lists and rewrites a deployment's stored
rows.

A stored block that omitted `enabled` drew no Add button; converted, it draws one |
| A `user` field whose `reference` is not `sys_user` (`2069b81`, #25074) | `user-field-foreign-reference-refused` | change it to a `lookup` on that object, and choose its `deleteBehavior` |

| The `Field.select` string shorthand keeps every character it does not document transforming, so `'no-overlay'` is refused (`386f60f`, #25122) | `field-select-shorthand-keeps-written-value` | write the option explicitly with the value you store |

  voluntary ownership ceremony that tightens them (`6251f59`, #25179), and

- **Package upgrades report what they un-make.** At boot an administrator is
  told when a package upgrade renamed, removed or collided with an access item
  the customer switched off, cloned or authored (`54df640`, #25311), and the

  flows, actions, webhooks, overlays, object extensions, navigation
  contributions and settings, on the `system.upgrade_impact` topic (`e207b97`,

- **`ObjectSchema.membershipKeys`** (`dc532e8`, #25513): a roster object
  declares the `current_user.KEY` sets it defines (`userField`, `valueField`,

  the declaration and the policies that read it (#25550). See
  [Semantic changes](#semantic-changes-in-1810) for what reads it.
- **Setup → Email states which mail transport is live** (`ab510f4`, #25448),
  and says so when no mail leaves the machine.
- **Setup → Positions says who holds each position and what it grants**,
  through `GET /meta/position?include=grants` (`27b3f1f`, #25369). Create User
  can grant a permission set in the same step (`3306cad`, #25381), and Create Key

  catalog keys rendered per recipient at delivery (`58cd58f`, #25014), and every
  approval notification uses it.
- **Translations** for `page:tabs` item labels (`30d21f6`, #25005), form view
  titles (`eddffc3`, #25035) and approval step labels (`b9a79ef`, #24943).
- **Flows.** `ExecutionStatus` gains `missed`, for a scheduled due time that
  passed while no kernel was ticking (`d12e650`, #25363), and a failed run
  carries the refusal its write node met as `userMessage` / `innerRefusal`

- **A bulk action's `confirmText` is a `template` slot** over `count` and the

### Semantic changes in 18.1.0

- **A declared membership key is staged per request** (`e5eab06`, #25528), so
  a row policy reading `current_user.KEY` now reads the roster object's rows:
  the distinct `valueField` values on the rows whose `userField` is the
  signed-in user and on which `filter` holds, inside the caller's own
  organization. Before this change such a policy matched no rows. Every miss
  fails closed: no roster row, more than 1,000 values, a failed read, a
  `filter` that does not compile, or a key two objects declare leaves the key
  unresolved, and a policy reading it matches nothing. Whoever can write a
  roster row can grant the key, and the object-level explain names each key a
  policy reads.
- **An `external` holder is its own posture** (`45f9962`, #25541). Its
  execution context carries `audience: 'external'`, and for it every object's
  org-wide default is owner-only: it reads and writes the rows it owns and
  the rows shared to it, by a share or a sharing rule, and a `public_read` or
  `public_read_write` object is not open to it. A row policy on a permission
  set or position it holds lifts that floor and bounds the rows instead. A
  `controlled_by_parent` detail follows its master. Nothing changes for a
  principal that does not hold the `external` grade, and no earlier release
  shipped it.
- **A share or sharing rule on a public object reaches an external member**
  (`4a25192`, #25591). On a `public_read_write` object, or a system object
  with no `sharingModel`, `SharingService.grant` now admits a `user` recipient
  who is an `external` member of the record's organization, and a sharing
  rule writes rows for the external members it expands to and skips the
  internal ones. Every other recipient keeps `422 SHARING_NOT_ENABLED`. The
  lint's `sharing-rule-object-not-shareable` on a public object is now a
  warning.
- **`FlowSchema.runAs` now says what a `system` run may not write**
  (`025f6de`, #25564): its description names the refused writes to the four
  identity-assignment objects (above, under security), and ADR-0087 D3 records
  the change of meaning as `flow-run-as-system-identity-assignment-write-refused`,
  so `os migrate meta` lists it for a flow that wrote those rows. It carries no
  conversion, and every flow parses as before.

#25541 and #25591 declare `Metadata-protocol: semantic` too; the GitHub Release
body files them under new capabilities, because each widens what a door
admits, and the counts above follow it. A change of meaning that also breaks
is listed with the breaking changes above.

## Upgrade checklist

⚠️ For an 18.0.0 app. From 17.x, walk the
[18.0.0 checklist](/docs/releases/v18/18-0#upgrade-checklist) first: its
database step, the organization-ownership ceremony, is the one an 18.1.0 server
also requires.

### 18.1.0

<Callout type="warn">
**How far this list has been walked.** On 2026-10-24, from 18.0.0, once: an app
scaffolded with `create-objectstack@18.0.0` (the `blank` template, pnpm, no
skills), pinned to exactly `18.0.0` with the override in step 1, was booted on
18.0.0 with `objectstack start` and `OS_AUTH_SECRET` set. It created a SQLite
database holding one administrator, signed up through the auth API, and three
notes. It was then moved to 18.1.0 from npm, and each step below was run. Each
line says how it was measured:

- **Measured in the walk** — the step was run, and the quoted text is what
  18.1.0 printed.
- **Probed on 18.1.0** — the walk's app carries none of it, so a probe was sent
  to the running 18.1.0 server, and the quoted text is its answer.

⛔ The walk was one small app on SQLite, under the `single` posture. Walled
postures, Postgres, MySQL, Turso, a multi-environment host, an embedded kernel,
a flow, a webhook and the skills sync were not walked, and no upgrade of a
production application was run for this page. A line with no mark is compiled
from the changesets.
</Callout>

#### 1. Move the pins

- **Move every `@objectstack/*` dependency to `18.1.0` together**, and
  `@objectstack/skills` with them, as in the
  [18.0.0 walk](/docs/releases/v18/18-0#1-move-the-pins). Pin the exact
  version: a caret range takes every later 18.x by itself, and a patch can
  break a non-protocol surface. A project `npm create objectstack` scaffolded
  before 18.1.0 carries caret ranges: replace each `^18.x.y` with `18.1.0` and
  reinstall. The walk moved nine exact `18.0.0` pins to `18.1.0`, and
  `pnpm install` left no `@objectstack/*` package at 18.0.0 in the lockfile and
  printed no peer-dependency warning. *Measured in the walk.*
- **Hold the CLI's own ranges with an override.** An exact pin does not hold
  the eight packages `@objectstack/cli` ranges (see
  [Release facts](#release-facts-as-measured)). With pnpm, add this to
  `pnpm-workspace.yaml`, at the version you pin:

  ```yaml
  overrides:
    '@objectstack/core': '18.1.0'
    '@objectstack/driver-memory': '18.1.0'
    '@objectstack/driver-mongodb': '18.1.0'
    '@objectstack/driver-sql': '18.1.0'
    '@objectstack/driver-sqlite-wasm': '18.1.0'
    '@objectstack/objectql': '18.1.0'
    '@objectstack/observability': '18.1.0'
    '@objectstack/runtime': '18.1.0'
  ```

  On the walk's app pinned to `18.0.0`, those eight lines (at `'18.0.0'`) took
  the tree from 17 packages at 18.1.0 to none. pnpm 10.28 ignored the same
  block under `"pnpm": { "overrides": … }` in `package.json` while
  `pnpm-workspace.yaml` exists. npm's `overrides` was not tried. Move the
  override with the pins at every upgrade. *Measured in the walk.*

#### 2. Before the first boot

- **Production `os serve`: set `OS_AUTH_SECRET`**, and do not rely on
  `--no-server` or `OS_MIGRATE_AND_EXIT=1` to boot without it. A kernel you
  embed needs it too, unless it boots with `NODE_ENV=development` or `test`.
  Without it, `os serve` exited `1` with
  `✗ This stack enables auth, but no auth secret is set, so AuthPlugin was not
  composed and no caller can authenticate` and the line to set it.
  *Measured in the walk.*
- **`os start` does not refuse: it mints a secret.** With no secret set, it
  wrote a new one to `.objectstack/auth-secret` and booted. Boot with the
  secret 18.0.0 used: with the same `OS_AUTH_SECRET`, the session signed in on
  18.0.0 was still valid on 18.1.0; a new secret ends every session.
  *Measured in the walk.*
- A stack that mounts no auth (`auth` tier off, `--preset minimal`) fails a
  production boot: enable auth.
- CORS: list every cross-origin front-end in `OS_CORS_ORIGIN`, loopback origins
  outside development included. With credentials on, `'*'` and all-host
  patterns fail the boot.
- `OS_CLOUD_MANAGED=1` needs `OS_CLOUD_API_KEY`.
- Every OIDC SSO provider's issuer matches its discovery document exactly.
- Tell users that sign-ins begun before the upgrade must be started again.

#### 3. Run the build, and fix what it refuses

```bash
os validate
os build
os migrate meta --from 17     # the step-18 conversions, listed for your sources
```

On the walk's app, `os validate` and `os build` passed on 18.1.0 with no
edit. `os migrate meta --from 17` exited `0` and printed
`417 manual change(s) require your judgment` (18.0.0 printed 406): read it as a
list to search, as on 18.0.0. `--from 18` replays nothing, and says so
(`No migration step exists for protocol 18 → 18`), so keep `--from 17`.
*Measured in the walk.*

Fix each refusal with the line in
[Breaking changes you must act on](#breaking-changes-you-must-act-on) and
[Converted for you](#converted-for-you-by-os-migrate-meta). The ones an app is
most likely to meet: `addRecord` without `enabled`, a webhook without
`'webhooks'` and `'realtime'` in `requires`, an HTML email template hole, a
`validations[]` rule that reads `parent`, a bulk action `confirmText` hole over
a name that is neither `count` nor a param, and an `external` object on a
managed datasource.

#### 4. After the boot

- The data is as 18.0.0 left it. The walk's three notes read back, and the
  administrator signed in. A clean boot printed no upgrade report at the
  default log level. *Measured in the walk.*
- Run `os migrate meta --stored` to list stored rows the step-18 conversions
  rewrite. It takes no `--from` (`--stored=true cannot also be provided when
  using --from`); on the walk's app, which had stored no metadata, it printed
  `Examined 0 stored metadata row(s)` and a warning that an empty run attests
  nothing. *Measured in the walk.*
- Run `os migrate plan`. On a database 18.0.0 created, it lists the tenant
  columns still nullable; the ownership ceremony tightens them to `NOT NULL`
  when you choose to run it. On the walk's database it printed
  `33 tenant column(s) are still nullable (ADR-0131 D1)`, said the ceremony
  tightens 31 of them, and ended
  `✓ Physical schema is in sync with metadata — nothing to migrate.`
  *Measured in the walk.*
- If the boot reports a notification preference collision, resolve it with
  `os migrate duplicates` and restart.
- Check that REST and MCP callers do not depend on a disabled package's actions
  or on an object declared `apiEnabled: false`, and that a client calling
  metadata rollback sends `toVersion` as a JSON number.
- Run each `runAs: 'system'` flow that writes positions, permission-set
  assignments, invitations or memberships, and move it to `runAs: 'user'` or
  the organization endpoints.
- Read the boot's upgrade impact report beside the access upgrade report.
- On a multi-environment host, give each environment's kernel its own `auth`
  service before callers reach it, or they get `401`.
