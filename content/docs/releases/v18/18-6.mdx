## Highlights — 18.6.0

- ⚠️ **A minor that breaks.** 68 of the 419 entries are declared breaking:
  20 graded `minor` because they narrow the metadata protocol, and 48 graded
  `patch` under the level rule. 53 need you to act; 15 carry an
  `os migrate meta` entry that lists what to check. 64 commits since 18.5.0
  carry a `!` in their subject. Read
  [the version number](#the-version-number-is-not-the-signal).
- **Outbound calls reach only public addresses.** Webhook deliveries and the
  flow `http` node refuse a loopback, private, link-local or cloud metadata
  address unless `OS_EGRESS_ALLOWED_TARGETS` lists the target; a metadata
  address is never reachable (`c37e47a`, #34284).
- **The person confirms what the AI door would run.** An action declaring
  `ai.requiresConfirmation: true` never runs on the MCP caller's own
  `confirm: true`: `run_action` and `resume_run` hand it to the person in the
  app (`60fca0f`, #34202), ask the person in the client where it advertises
  `elicitation` (`d6b1c2e`, #34318), and refuse the `confirm` member
  altogether (`8c6ddc5`, #34358). This is the release the 18.5.0 notice
  ("Announced, not yet at any door") said to wait for.
- **Invitations and sign-in.** Accepting, declining and listing an
  invitation need a verified email address on every deployment
  (`8b7c5d5`, #34883), and the invitation mail's own link accepts in one step
  (`842637a`, #34333). A locked account is refused on every door that ends in
  a session (`e735892`, #34139), and a password change ends every other
  outstanding reset link (`6dd5716`, #34667).
- **Roll-up `summary` fields are read-only**, on create as on update, whether
  or not they declare `readonly: true` (`cc5472e`, #35089; `a825152`,
  #34752).
- **Field-level security covers what a field is computed from.** A formula
  or stored computed field over a field the caller is not served whole is
  withheld from that caller (`f84dc19`, #34135).
- **A disabled package runs no flow and holds no name at the write doors.**
  Its flows' triggers skip (`7d42ba0`, #33890; `44fc2fc`, #34048), its inbound
  hooks refuse (`888c3e1`, #34278), and a bare save or delete counts the
  holders the bare read counts (`20bf222`, #34324).
- **Datasets are closed.** The dataset query door and `query_dataset` refuse
  a measure or dimension the dataset does not declare (`898655a`, #34198;
  `b4ce310`, #33958).
- **New.** A timesheet list view and its new package,
  `@object-ui/plugin-timesheet` (`4240719`, #34925); `os skills install |
  update | status` (`0c60897`, #35060); `rmbUpper()` for amounts in Chinese
  capital numerals (`12b69e1`, #34433); a packaged flow that ships switched
  off (`99bd220`, #34793); an ES256 audit checkpoint signer (`52ec26f`,
  #34506); and schema sync builds the default-order and owner indexes without
  a declaration (`479d1e4`, #34044).

## What's new in 18.6.0

### The version number is not the signal

Every package still versions in lockstep. The level of a release says whether
**the metadata protocol** moved, and nothing else:

| Kind of change | Level |
| :--- | :--- |
| Added to the metadata protocol: a new authorable key, accepted value or metadata type | `minor` |
| Narrowed or retired: a key removed or tombstoned, a value refused, a requirement tightened | `minor` |
| Semantic: the meaning or default of an authorable key changes | `minor` |
| Everything else: REST, drivers, services, the CLI, the Console, `feat:` and `fix!:` alike | `patch` |

So 18.6.0 carries 48 entries graded `patch` that say **BREAKING**, beside 20
graded `minor`. Pin exact versions of both scopes, and read the release notes
for every version you cross.

### 需手动处理 — breaking changes you must act on [#action-required]

The 53 entries that are breaking and carry no registered ADR-0087 entry. Each
line says what now answers differently and what to do, from the changeset
under its commit; the CHANGELOG entry gives the full before and after. The
[upgrade checklist](#upgrade-checklist) puts the ones an app is most likely to
meet in order.

#### Outbound calls, uploads and the audit seal

3 entries.

- **Webhook deliveries and flow `http` requests reach only public
  addresses.** Every address outside global reachability is refused —
  loopback, private, carrier-grade NAT, link-local, unique-local, multicast,
  documentation and the rest — and so is any IPv6 address outside global
  unicast, judged after DNS, on the connected socket and on every redirect.
  Cloud metadata addresses are never reachable. To keep an internal target,
  list its exact host names, IP addresses or CIDR blocks in
  `OS_EGRESS_ALLOWED_TARGETS` and restart; a malformed or over-broad entry
  fails the boot. A refused webhook dead-letters at once with
  `EGRESS_REFUSED`; a refused `http` node fails with `http: EGRESS_REFUSED`.
  These packages now need a Node.js runtime, and an HTTP proxy set in the
  environment is not used for these requests (`c37e47a`, #34284).
- **A storage host with no upload bound now enforces 100 MB per upload.**
  `max_upload_mb` resolves by one precedence — a saved setting, the host
  option, the manifest default, the built-in 100 MB — and unset never means
  unlimited. A DevPlugin-composed server, `--preset minimal`, a
  `mountStorageRoutes` host over a bare adapter, `bindToSettings: false`, a
  failed settings read and an invalid saved value all move. Pass
  `maxUploadMb` (a number, or `'unlimited'`) on `StorageServicePlugin`,
  `mountStorageRoutes` or `registerStorageRoutes`, or correct the saved
  value (`a8261ce`, #33883).
- **An `os migrate audit-* --apply` run holds the audit seal lock.** Where
  an app declares `lifecycle.seal`, a run on SQLite or Turso stops before
  writing and names `--sealer-stopped`: stop every server that seals the
  database, then run it again with the flag. On Postgres or MySQL the run
  waits up to ten minutes for a sealer pass, then refuses having changed
  nothing. A run that rewrites no sealed object, and every dry run, is
  unchanged (`35c9a30`, #33675).

#### Sign-in, invitations and cloud-managed environments

14 entries; the SCIM line covers three.

- **Accepting, declining and listing an invitation need a verified email
  address**, on every deployment and whatever its mail transport:
  `403 EMAIL_VERIFICATION_REQUIRED_BEFORE_ACCEPTING_OR_REJECTING_INVITATION`
  and `403 EMAIL_VERIFICATION_REQUIRED_FOR_INVITATION`. Under `invite_only`
  with `membershipPolicy: 'auto'`, a sign-up its invitation admits is not
  bound to the Default Organization until the address is verified. An
  invitee completes the verification mail, or opens the invitation mail's
  own link, which verifies and accepts in one step; without a live mail
  transport, a platform administrator creates the account or adds an
  existing one (`8b7c5d5`, #34883; the accept route's own answer, `c4c0794`,
  #34666).
- **The same rule under `email_domain`.** With `membershipPolicy: 'auto'`, an
  address off the allowlist that a pending invitation admits is not bound to
  the Default Organization while unverified; it joins by accepting
  (`3f5ffe7`, #34969).
- **A locked account is refused on every door that ends in a session for
  it** — the one-time code, magic link, address-change confirmation, second
  factor, identity-provider sign-ins, the device grant and the phone-number
  password door — with the answer password sign-in gives
  (`403 ACCOUNT_LOCKED` under `lockoutRefusal: 'explicit'`). Phone-number
  password failures now count toward the lock. An administrator clears a lock
  with **Unlock** (`e735892`, #34139).
- **A credential change ends every other outstanding password-reset link and
  code** of that user, which then answer `400 INVALID_TOKEN`. The person asks
  for a new one (`6dd5716`, #34667).
- **An origin an SSO register or update body names is trusted for that
  provider's discovery only.** The request's own `Origin` must be one of the
  deployment's trusted origins (`403 INVALID_ORIGIN` otherwise): send it from
  the Console or a server, or add the page's origin to `OS_TRUSTED_ORIGINS`.
  A `signOutOfIdp` switch for an OIDC provider on a private network needs its
  origin listed there too (`6feea4e`, #34099).
- **The `oidcAuthorizeGate` judges every client a `/oauth2/authorize`
  request names**, query and body, and the first refusal ends the request.
  Only a host whose gate assumes one call per request moves (`0ff3b14`,
  #33937).
- **Under direct sign-in with the local path `off`**, an auth settings save
  that turns Google off while it is the last way in the sign-in page offers
  is refused `400 SETTINGS_VALIDATION`; register another provider first, or
  set `OS_AUTH_DIRECT_SIGN_IN_LOCAL_PATH=hidden`. A client the IP allow-list
  refuses at `GET /api/v1/auth/sign-in/direct` now gets `302` to
  `/login?error=IP_NOT_ALLOWED` instead of the `403` body (`3372da0`,
  #33781).
- **A SCIM directory writes a user's manager**, from the Enterprise User
  `manager` attribute. A manager link that would make the user their own
  manager, close a cycle, pass the 20-link depth cap or cross an organization
  is refused SCIM `400 invalidValue`. An identity provider that syncs by
  replace and maps no manager clears, on its next sync, a `manager_id` set
  earlier: map the attribute before upgrading if those values should stay. A
  reference that names no user is served and recorded as one bounded
  `scim_manager_unresolved` row in `sys_audit_log`, and
  `os explain approval-approvers-may-resolve-empty` names SCIM as a route
  that fills `manager_id`. Three entries, one per package (`18194fb`,
  #34252).
- **In multi-org mode, `POST /api/v1/auth/admin/import-users` joins each
  row's user to the importing administrator's current organization.** With
  no current organization the import is refused `400 NO_ACTIVE_ORGANIZATION`;
  a row the organization's membership limit refuses fails alone. Switch to
  the people's organization before importing (`36af6b0`, #34750).
- **A cloud-managed environment sets no local password for anyone**
  (`OS_CLOUD_MANAGED=1`): Set Password, `set-initial-password` and the reset
  doors answer `409 RESOURCE_CONFLICT`. People sign in through the hosting
  organisation's identity provider (`99a6ec0`, #33268).
- **On a cloud-managed environment every organization door that writes a
  membership refuses**, add-member excepted: remove, change a member's
  tier, make owner, leave, accept invitation, create and delete
  organization answer
  `409 RESOURCE_CONFLICT`, and their actions are hidden. Make the change in
  the hosting organisation (`e2a4c66`, #34281).
- **A cloud-managed environment does not offer its file storage or AI
  provider settings**: `storage` and the provider keys of `ai` are left out
  of the settings reads, and their writes answer `409 RESOURCE_CONFLICT` with
  `details.managedBy: 'platform'`. A self-hosted deployment answers as before
  (`021abd4`, #34254).

#### Access: field security, sharing and approvals

4 entries.

- **A computed field over a field the caller is not served whole is withheld
  from that caller** — a `formula` or a stored `expression` field reading a
  field the caller may not read, or is served masked, on its own record or
  through a reference. It leaves reads and projections; filtering, sorting
  or grouping by a stored one is refused `403 PERMISSION_DENIED`, and so is a
  payload naming it. Grant read, unmasked, on every field the computed field
  reads when the caller should see it (`f84dc19`, #34135).
- **The administrator override never approves a request its actor
  submitted** (`403 FORBIDDEN`), and an override reassign to the submitter is
  refused. Rejecting and recalling stay open; `viewer.can_override_approve`
  is new (`1354d2a`, #34755).
- **The sharing write gate judges by id exactly the writes the engine runs by
  id.** A multi-row update or delete whose `where` holds a scalar `id` beside
  another key, or whose `id` is falsy, meets the bulk write scope: rows the
  caller may not write are left alone and the call answers no error. Address
  a row by id alone to have it judged by id (`c47e4ea`, #34033).
- **A share granted directly by a non-system caller is always manual.**
  `POST /api/v1/data/:object/:id/shares` refuses a `source` other than
  `'manual'`, and any `sourceId`, with `400 VALIDATION_FAILED`. Drop both
  fields; declare a rule as a sharing rule (`5d01679`, #34031).

#### MCP and the AI doors

4 entries.

- **An action declaring `ai.requiresConfirmation: true` never runs on the
  caller's own `confirm: true`.** `run_action` and `resume_run` hand the call
  to the host's pending-confirmation service and answer
  `status: 'pending_confirmation'`; a host with no such service (the open
  build ships none) refuses `428 ACTION_CONFIRMATION_REQUIRED` with
  `details.reason: 'no_confirmation_service'`. Relay the pending answer to the
  person; where the action is safe unattended, its author declares
  `ai.requiresConfirmation: false` (`60fca0f`, #34202).
- **`run_action` and `resume_run` refuse the `confirm` member**, `true` or
  `false`, on every action. Stop sending it there; keep sending it to
  `delete_record` and `delete_records` (`8c6ddc5`, #34358).
- **A resume approval is bound to the screen it was given on.** A client
  asked in place that accepts after the wizard moved on is refused
  `409 RESOURCE_CONFLICT`; a host passes `screenNodeId` back on approval to
  get the binding (`4fb8790`, #34753).
- **An AI service account does not start by name a flow that a
  confirmation-gated action targets**: the trigger routes refuse it
  `428 ACTION_CONFIRMATION_REQUIRED`, before any run. A person starts it, or
  the action's author declares `ai.requiresConfirmation: false` (`8319820`,
  #33721).

#### Namespaces, packages and metadata reads

12 entries. A name two packages hold is read and written by its package
(`?package=`); a door naming no package refuses it, naming the holders.

- **A bare save or delete counts the holders the bare read counts.** A name
  two enabled packages hold is refused `409 RESOURCE_CONFLICT` naming both,
  and a name only disabled packages hold is refused naming none, where both
  were written. Name the package, or enable it (`20bf222`, #34324).
- **A name only disabled packages hold answers `404` at `_env`**, and an
  environment customization of it is hidden from the reads and the lists
  until a holder is enabled again (`66f6638`, #33995).
- **The layered read of a name two packages hold refuses as the plain read
  does**, naming the holders as `details.candidates` (`661ede2`, #33885).
- **A doc read by name alone refuses a name two enabled packages ship**
  (`409`, `ambiguous-in-environment`); name the package (`5af956f`, #34036).
- **An exact `?package=X` read answers X's own item, never another
  package's**, for `doc`, `view`, `translation`, `field`, `seed`,
  `datasource`, `external_catalog` and `object_extension`: `409
  not-held-by-qualifier` where another package holds the name. Beside the
  environment's own entry, a bare doc read serves that entry (`89d5a41`,
  #34347).
- **The diff door of a by-package name refuses the bare name two holders
  hold**; `GET /meta/TYPE/NAME/diff?package=PKG` compares one holder's
  versions (`bb17350`, #34147).
- **A package-less action save on an object no package binds the name to
  writes the environment's own action**, where it wrote into a package and
  moved that package's action. A package's action is moved by a save naming
  it (`?package=P`). Until its read half lands, a package-less delete of the
  name removes the package's action, not the environment's (`50d655f`,
  #34238).
- **A package-less action is kept on its own owner key**, so
  `/actions/OBJECT/NAME` answers with the declaration of the action bound to
  that object beside the environment's object-less one (`0593356`, #33821).
- **An action route runs the handler of the item whose declaration it
  gated on**, never another owner's handler under the same key (`0ad377c`,
  #34734).
- **The package upgrade plan counts the fields a package adds through
  `objectExtensions`**: a retyped or suspected-renamed extension field now
  needs `--confirm-upgrade`, and a rename into a type with no column is
  refused `422` (`d5e6b20`, #34419).
- **`POST /api/v1/marketplace/install-local` parses the manifest `namespace`
  through its declaration**: an invalid, `null` or non-string namespace is
  refused `400 PLUGIN_MANIFEST_INVALID`. Declare it in lowercase snake form,
  or omit it (`614b9b5`, #34316).
- **Setup › Packaged Actions retires.** An installed app's action is switched
  on or off on the action itself, in Studio; a bookmark redirects there. A
  platform action has no switch in the Console any more: switch it through
  `POST /api/v1/actions/_activation/OBJECT/ACTION`, and find the platform
  actions a deployment switched off from `sys_metadata_activation`, as the
  entry describes (`6c1f9b3`, #34799).

#### Flows and automation

4 entries.

- **A trigger does not run a flow slot whose package is disabled**, when two
  packages ship the name; an event that fires meanwhile is dropped
  (`7d42ba0`, #33890).
- **A flow whose only holder's package is disabled is not run by its
  trigger**, and the engine's bare entries answer as for no flow (`404` at
  the bare HTTP doors) while the engine still holds it. Enable the package
  (`44fc2fc`, #34048).
- **The inbound hook door refuses a flow slot whose package is disabled**
  with its one refusal, `401 INVALID_SIGNATURE`, before anything is enqueued,
  where it answered `202` and lost the event (`888c3e1`, #34278).
- **Switching on a packaged flow whose own status is `obsolete` or `invalid`
  is refused** `409 RESOURCE_CONFLICT`, and the toggle door answers the
  engine's state. Publish the flow `active` first, then switch it on
  (`583bbf3`, #34810).

#### The data engine, hooks and roll-ups [#the-data-engine-hooks-and-roll-ups]

6 entries.

- **A roll-up `summary` field is read-only on create.** A value sent for one
  is dropped, and the column starts as for an empty child list (`0` for
  `count` and `sum`, empty otherwise), reported in `droppedFields` with
  reason `readonly`; under `strictReadonlyWrites` the create is refused
  `ERR_READONLY_FIELD_REJECTED`. The doors are REST create (single, batch,
  `createMany` and composite), an import's inserts and the rows an upsert
  creates, MCP `create_record`, a flow `create_record` that does not run as
  system, the insert-mode preview, and two the changeset's list leaves out:
  the **public form submit**, which answers the created id only, so the
  submitter is not shown the drop; and a caller's **`overrides` on clone**,
  which reports the drop through the same listener as a create. The stdio
  MCP bridge drops the value without reporting it in `droppedFields`
  (#35114). Server code that loads a total writes as system,
  `{ context: { isSystem: true } }` (`cc5472e`, #35089).
- **A roll-up `summary` field is read-only on update** whether or not it
  declares `readonly: true`: `PATCH`, an import's updates, a predicate update
  and the update-mode preview drop it the same way (`a825152`, #34752).
- **A write refused after its `before*` hook wrote through `ctx.api` no
  longer keeps that hook's write.** A metadata-bound `before*` hook opens the
  write door's unit of work, so its writes roll back with a refusal; inside
  the unit, a write to another datasource is refused, MongoDB needs a
  replica set, and on PostgreSQL a failed statement aborts the whole unit.
  Record an attempt from an `async: true` `after*` hook instead (`a8e09bb`,
  #34503).
- **A cascade delete removes a relation's children as one predicate delete
  per chunk of 500.** A delete hook on a cascaded child sees
  `ctx.dispatch.mode: 'per-row'` and a `where` over the chunk, and every
  child's `beforeDelete` runs before the set delete; judge the batch from
  `ctx.input.options` (`c934631`, #33887).
- **A multi-row insert counts its earlier rows into the parent summary a
  field-level `parent.` predicate reads**, as one-by-one inserts do; supply
  the field on every row the requirement now names (`b91cefa`, #34612).
- **On MongoDB, OData and a third-party driver that does not declare
  `readableIdsLeaf`, a nested-relation condition is refused** `INVALID_FILTER`
  / 400 up front, and an analytics dimension through a lookup `INVALID_QUERY`
  / 400. Read the related ids first and match with `$in`; a driver whose
  compiler composes the leaf declares `supports.readableIdsLeaf: true`
  (`6091b64`, #34565).

#### Analytics and datasets

4 entries.

- **The dataset query door refuses a measure or dimension the dataset does
  not declare**, `400 INVALID_FIELD`, naming the members the caller may use;
  this covers `POST /api/v1/analytics/dataset/query`, its batch and
  `AnalyticsService.queryDataset`. A dashboard compare widget whose
  date-range field is not also the name of a declared date dimension is
  refused too, and no save gate catches it yet: declare a date dimension
  named after the field (`898655a`, #34198).
- **`query_dataset` refuses the same members**, before anything is read; use
  the names `list_datasets` lists (`b4ce310`, #33958).

## Upgrade checklist

⚠️ For an 18.5.0 app. From 18.4.0, walk the
[18.5.0 checklist](/docs/releases/v18/18-5#upgrade-checklist) first, and so
on back to the [18.0.0 checklist](/docs/releases/v18/18-0#upgrade-checklist)
from 17.x.

### 18.6.0

<Callout type="warn">
**Compiled from the changesets.** Each step names the entry it comes from.
Steps 1 and 2, and the plan in step 3, were walked by the
[post-release smoke](#the-post-release-smoke) on two small SQLite apps; the
rest was not.
</Callout>

#### 1. Move the pins

- **Move every `@objectstack/*` dependency, and every `@object-ui/*` one, to
  `18.6.0` together**, with `@objectstack/skills` and `create-objectstack`
  where you use them. Pin the exact version: a caret range takes every later
  18.x by itself, and a patch can break a non-protocol surface. One package
  joins npm, `@object-ui/plugin-timesheet`; none leaves.
- **Move the AI skills with them.** A project that holds
  `@objectstack/skills` as a dependency moves it with the pins and syncs it
  as [Upgrading](/docs/upgrading#moving-the-dependency-pins) says; a catalog
  that the new `os skills install` recorded moves with `os skills update`
  (`0c60897`).

#### 2. Run the build, and fix what it refuses

```bash
os validate
os build
os migrate meta --from 17     # the protocol-18 step, with this release's entries
```

Fix each refusal with its line in [需手动处理](#action-required) or
[自动迁移](#migrated-for-you). The ones an app is most likely to meet:

- an action body that declares `input` or `ctx` again (`743308b`);
- `timestamp()` over a `date` field, in a formula, a rule, a flow condition
  or a flow value envelope (`22bf910`, `1538596`);
- an ordering or arithmetic condition on an injected column with no
  `!= null` guard (`a061708`);
- a `lookupFilters` `{ $record }` value of the wrong shape, path or
  cardinality (`aab8b31`, `d9c4b62`, `f23c71e`);
- a `record:activity` feed whose `types` leaves out `comment` beside its
  composer (`6302c2c`), and a webhook declared with `method: 'GET'`
  (`bef80d3`).

#### 3. Before the first boot

- **List the internal targets your webhooks and flow `http` nodes call** in
  `OS_EGRESS_ALLOWED_TARGETS`, exact hosts, addresses or CIDR blocks, before
  the first boot; the boot logs how many stored webhooks target a refused
  address (`c37e47a`).
- **Set `maxUploadMb` on a storage host that relied on no bound**: a
  DevPlugin-composed server, `--preset minimal`, a `mountStorageRoutes` host
  or `bindToSettings: false` now holds uploads to 100 MB (`a8261ce`).
- **Map the SCIM `manager` attribute** in an identity provider that syncs by
  replace, if the managers set so far should stay (`18194fb`).
- **Check how invitees verify their address.** On a deployment with email
  verification off, no live mail transport, or a provider that does not
  verify, an invitee cannot accept a copied link; plan for the invitation
  mail's own link or an administrator-created account (`8b7c5d5`).
- **On MongoDB**, run a replica set if an object carries a metadata-bound
  `before*` hook, and rewrite nested-relation conditions into two reads
  (`a8e09bb`, `6091b64`).
- **Read `os migrate plan`.** It lists a safe `create_index` for each
  missing `idx_TABLE_created_at_id` and `idx_TABLE_owner_id`, built
  `CONCURRENTLY` on PostgreSQL by the next sync (`479d1e4`), and on SQLite a
  `normalize_boolean_storage` step for legacy text booleans (`23c42c4`).
  Neither is destructive.

#### 4. After the boot

- **Run `os migrate audit-*` with `--sealer-stopped` on SQLite or Turso**
  where an object declares `lifecycle.seal`, with every sealing server
  stopped (`35c9a30`). `os migrate audit-side-copies` is 18.5.0's command;
  run it from 18.4.0 or earlier, as [Upgrading](/docs/upgrading#per-release-specifics)
  says.
- **Update MCP clients and agents**: stop sending `confirm` to `run_action`
  and `resume_run`, relay a `pending_confirmation` answer to the person, and
  pass `screenNodeId` back on a host's resume approval (`8c6ddc5`, `60fca0f`,
  `4fb8790`).
- **Update API clients for the doors that answer differently**: a roll-up
  `summary` value sent on create or update is dropped (`cc5472e`,
  `a825152`); a dataset query names declared members only (`898655a`,
  `b4ce310`); a bare save, delete, layered read, doc read or diff of a name
  two packages hold answers `409` (`20bf222`, `661ede2`, `5af956f`,
  `bb17350`); and a direct share takes no `source` but `'manual'`
  (`5d01679`).
- **Re-check who reads computed fields.** A formula or stored computed field
  over a field a permission set withholds or masks is now withheld with it
  (`f84dc19`), and a set's own `readable: false` row binds over its View All
  (`3e49033`).
- **Re-check flows that a disabled package ships**, and a packaged flow you
  switched on while its status was `obsolete` (`7d42ba0`, `44fc2fc`,
  `583bbf3`).
- **Replace Setup › Packaged Actions bookmarks** with the switch on each
  action in Studio, and find any platform action the retired page switched
  off from `sys_metadata_activation` (`6c1f9b3`).
