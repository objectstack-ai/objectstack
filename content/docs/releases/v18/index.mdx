> **Release status: 18.6.0 is released**, the newest release of the v18 line,
> published to npm's `latest` tag on 2026-11-18. The line opened with 18.0.0,
> released on 2026-10-20, which closed the `18.0.0-next.N` prerelease train.
> A `^17` dependency range never moves to 18 by itself, and on this line a
> `^18` range can move you to a release that breaks you: pin exact versions,
> and read each release's page before you move.

**The v18 line** exists for one decision whose changes did not fit in a 17.x
minor: [ADR-0131](https://github.com/objectstack-ai/objectstack/blob/main/docs/adr/0131-total-organization-ownership-no-null-organization-id.md),
organization ownership is total — no NULL `organization_id`; declared metadata
stays in code; a row exists only when an organization authored it. Its changes
reshape stored data and narrow what the runtime accepts, so the ADR staged them
in one major (its D14) instead of spreading them across 17.x minors. 18.0.0
shipped them; every minor since carries the breaking changes that landed on
`main` after it, under the rules below.

## Coming from 17.x

Move to 18.0.0 first, then through each minor in order.

- **The database moves through a ceremony.** A database 17.x or an 18.0
  prerelease created carries no organization-ownership birth marker, so an
  18.0.0 server refuses it and names `os migrate organization-ownership`
  (ADR-0131 D10). A fresh 18.x install never needs it. The steps are in
  [Upgrading to 18.0](/docs/upgrading#upgrading-to-180), and each step's
  measured output is in the walked
  [18.0.0 upgrade checklist](/docs/releases/v18/18-0#2-upgrade-the-database).
- **Then walk every minor's checklist**, 18.1.0 through the release you land
  on, each from its page in the table above. A minor moves the runtime without
  moving your protocol major, so most of what it changes reaches you only
  there.
- **The AI skills move with the packages.** From v18 the skills catalog is the
  `@objectstack/skills` package, on the same version as every other
  `@objectstack/*` package, and it moves only with them. A 17.x project has no
  such dependency — its skills were installed with `skills add` from the
  repository's `main` — and the sync from the package skips every skill a
  `skills add` installed (`Skipped … installed with skills add`, exit 0), so
  bumping the packages alone keeps the 17.x-era skill text. After moving the
  `@objectstack/*` dependencies to 18, remove those skills, then add the
  catalog at the new `@objectstack/spec`'s version and copy it into your
  agent's directory ([Upgrading](/docs/upgrading#moving-the-dependency-pins),
  step 4):

  ```bash
  npx skills remove objectstack-ai objectstack-api objectstack-automation \
    objectstack-data objectstack-formula objectstack-i18n objectstack-platform \
    objectstack-pm-dispatch objectstack-query objectstack-ui objectstack-upgrade -y
  pnpm add -D "@objectstack/skills@$(node -p "require('@objectstack/spec/package.json').version")"
  npx skills@1.7.2 experimental_sync --agent claude-code --copy -y
  ```

  Add the package with the manager that installed the project: in a pnpm
  project, `npm install --save-dev` fails (`npm error Cannot read properties of
  null (reading 'edgesOut')`, measured on the [18.0.0 upgrade
  walk](/docs/releases/v18/18-0#1-move-the-pins)). `npx skills remove --all`
  replaces the first command when these are the only skills the project has:
  run `npx skills list` first, because `--all` removes every installed skill
  without asking.

## How a breaking stage lands on this line

- **After 18.0.0, a breaking change ships in a minor or a patch.** The line
  takes no further major. Under the maintainer's 2026-10-21 level rule
  ([#25105](https://github.com/objectstack-ai/objectstack/issues/25105)), a
  change to the metadata protocol (added, narrowed or semantic) takes `minor`,
  and every other change takes `patch`, breaking or not: a non-protocol
  breaking change keeps its **BREAKING** banner and its ADR-0087 disposition.
  Every package versions in lockstep, so a release's level says only whether
  the protocol moved.
- **One change, one changeset, one migration.** Each change that breaks
  something says so in its own changeset: what breaks, and how to move from
  the old shape to the new one. The changesets become the `CHANGELOG.md`
  entries shipped inside each package, and each release's page groups them by
  what you must do: 需手动处理, 自动迁移, 新增能力, 语义变化 and 其他修复.
- **Protocol 18.** `PROTOCOL_VERSION` is `18.0.0` for the whole line, so the
  handshake admits `engines.protocol: '^18'` and refuses `'^17'`. The line's
  registered ADR-0087 entries sit on the protocol-18 step, which
  `os migrate meta --from 17` lists for your sources. Read
  [Upgrading](/docs/upgrading) before you move an app's declared range.
- **Two npm channels.** `latest` carries each stable release. `next` carries
  a snapshot of `main`, versioned `0.0.0-next-YYYYMMDDHHMMSS`, proposed daily
  and published only when a required reviewer approves it: it sorts below every
  stable version, takes no tag and no GitHub Release, and suits an app that
  needs a fix the day it lands (ADR-0125, amendments of 2026-11-05 and
  2026-11-06). Before 18.0.0, `next` carried the line's prerelease train,
  `18.0.0-next.N`, cut from `main` while Changesets was in pre mode; 18.0.0
  left pre mode, and npm carries no 18.x prerelease after it.

## Per-release notes

Each release below is a self-contained page: what it changed, what breaks, and
its own upgrade checklist.

- **[18.6.0](/docs/releases/v18/18-6)** — outbound calls held to public
  addresses, AI-door confirmation handed to the person, invitations that need
  a verified address, read-only roll-ups, field security over computed
  fields, and a disabled package that runs no flow. 68 of its 419 entries are
  declared breaking: 53 need you to act and 15 carry an `os migrate meta`
  entry. Written after the publish; its
  [upgrade checklist](/docs/releases/v18/18-6#upgrade-checklist) moves an
  18.5.0 app to 18.6.0, and the post-release smoke walked its first steps on
  two small SQLite apps.
- **[18.5.0](/docs/releases/v18/18-5)** — a 10 MiB request-body limit, SSO
  account linking held to the provider's proven domains, connectors and tools
  held per namespace, a disabled package that holds no name, and save
  refusals in the caller's language. 67 of its 284 entries are declared
  breaking: 45 need you to act and 22 carry an `os migrate meta` entry.
  Published on 2026-11-15; its notes were written ahead of the cut from the
  Version Packages pull request, and its
  [upgrade checklist](/docs/releases/v18/18-5#upgrade-checklist) moves an
  18.4.0 app to 18.5.0 and has not been walked.
- **[18.4.0](/docs/releases/v18/18-4)** — names held per namespace with
  exact addresses (ADR-0150), a recycle bin, one-way sync-in from a datasource,
  mobile push and declared field renames. 282 of its 1,252 entries are
  declared breaking: 244 need you to act and 38 are converted by
  `os migrate meta`. Its
  [upgrade checklist](/docs/releases/v18/18-4#upgrade-checklist) moves an
  18.3.0 app to 18.4.0; it is compiled from the changesets, and its commands
  were run once, on one small app.
- **[18.3.0](/docs/releases/v18/18-3)** — customization pairs for installed
  packages (ADR-0146), ownership queues, per-organization connector
  credentials and a whole-deployment export. 305 of its 1,379 entries are
  declared breaking: 264 need you to act and 41 are converted by
  `os migrate meta`. Its
  [upgrade checklist](/docs/releases/v18/18-3#upgrade-checklist) moves an
  18.2.0 app to 18.3.0, and is compiled from the changesets, not walked.
- **[18.2.0](/docs/releases/v18/18-2)** — the first release that ships the
  Console and the `@object-ui/*` packages from this repository, at one version
  with `@objectstack/*`. 59 of its 231 changesets are declared breaking: 52
  need you to act and 7 are converted by `os migrate meta`. Its
  [upgrade checklist](/docs/releases/v18/18-2#upgrade-checklist) moves an
  18.1.0 app to 18.2.0, and is compiled from the changesets, not walked.
- **[18.1.0](/docs/releases/v18/18-1)** — the first minor, and a minor that
  breaks: 91 of its changesets are declared breaking (ruling A grades a
  non-protocol breaking change `patch` and a protocol narrowing `minor`). Its
  [upgrade checklist](/docs/releases/v18/18-1#upgrade-checklist) moves an
  18.0.0 app to 18.1.0, and was walked on 2026-10-24 from 18.0.0 on one small
  SQLite app.
- **[18.0.0](/docs/releases/v18/18-0)** — the GA cut, which closed the
  `18.0.0-next.N` prerelease train and moved npm's `latest` tag from 17.x to
  18. Its [upgrade checklist](/docs/releases/v18/18-0#upgrade-checklist) moves
  a 17.x app and its database to 18.0.0, and was walked from 17.7.0.
