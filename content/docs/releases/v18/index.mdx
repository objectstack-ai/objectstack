> **Release status: 18.0.0 is GA — the release this page documents.** It
> closes the v18 prerelease train, which published as `18.0.0-next.N` on npm's
> `next` dist-tag. The 18.0.0 cut leaves Changesets pre mode, so the
> `@objectstack/*` packages stop publishing as `18.0.0-next.N`, and 18.0.0
> publishes to npm's `latest` dist-tag, which moves from 17.x to 18 with it. A
> `^17` dependency range still never moves to 18 by itself: move every
> `@objectstack/*` dependency to 18 together, and read
> [Upgrading](/docs/upgrading) before you do.

**The v18 line** exists for one decision whose changes do not fit in a 17.x
minor: [ADR-0131](https://github.com/objectstack-ai/objectstack/blob/main/docs/adr/0131-total-organization-ownership-no-null-organization-id.md),
organization ownership is total — no NULL `organization_id`; declared metadata
stays in code; a row exists only when an organization authored it. Its changes
reshape stored data and narrow what the runtime accepts, so the ADR stages them
in one major (its D14) instead of spreading them across 17.x minors. While the
line was open, every other breaking change that landed on `main` shipped on it
too, under the same rules.

## How a breaking stage lands on this line

- **Through `next` before `latest`.** Every major is published to the `next`
  dist-tag for at least one RC cycle before `latest`
  ([ADR-0087](https://github.com/objectstack-ai/objectstack/blob/main/docs/adr/0087-metadata-protocol-upgrade-contract.md)
  D6). While Changesets was in pre mode with the tag `next`, every release cut
  from `main` was the next `18.0.0-next.N`, carrying everything merged since
  the cut before it; 18.0.0 is the cut that takes the line to `latest`.
- **One stage, one changeset, one migration.** ADR-0131 lands in stages, in the
  order the ADR records, and each stage that breaks something says so in its
  own changeset: what breaks, and how to move from the old shape to the new
  one. Those changesets become the `CHANGELOG.md` entries shipped inside each
  `18.0.0-next.N` package, so read the CHANGELOG of every prerelease you move
  to — moving from one `18.0.0-next.N` to the next can break you.
- **Protocol 18 comes with it.** `PROTOCOL_VERSION` is `18.0.0` on `main`, so a
  v18 prerelease's handshake admits `engines.protocol: '^18'` and refuses
  `'^17'`. Read [Upgrading](/docs/upgrading) before you move an app's declared
  range.
- **The AI skills move with the packages.** From v18 the skills catalog is the
  `@objectstack/skills` package, on the same version as every other
  `@objectstack/*` package, and it moves only with them. A 17.x project has no
  such dependency — its skills were installed with `skills add` from the
  repository's `main` — and the sync from the package skips every skill a
  `skills add` installed (`Skipped … installed with skills add`, exit 0), so
  bumping the packages alone keeps the 17.x-era skill text. After moving the
  `@objectstack/*` dependencies to 18, remove those skills, then add the
  catalog at the new `@objectstack/spec`'s version and copy it into your
  agent's directory ([Upgrading](/docs/upgrading#moving-the-dependency-pins),
  step 4):

  ```bash
  npx skills remove objectstack-ai objectstack-api objectstack-automation \
    objectstack-data objectstack-formula objectstack-i18n objectstack-platform \
    objectstack-pm-dispatch objectstack-query objectstack-ui objectstack-upgrade -y
  npm install --save-dev "@objectstack/skills@$(node -p "require('@objectstack/spec/package.json').version")"
  npx skills@1.7.2 experimental_sync --agent claude-code --copy -y
  ```

  `npx skills remove --all` replaces the first command when these are the only
  skills the project has.
- **18.0.0 ends the prerelease.** It is the GA cut: it leaves pre mode and
  publishes the line to `latest`. Curated notes for the line's releases are
  compiled at release time and are not written yet; until then, the changesets
  are the record.
