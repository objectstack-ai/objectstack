> **Release status: no 19.x version is published yet.** This page covers the
> `19.0.0-next.N` prerelease line, starting with `19.0.0-next.0`, the first
> cut of the line. It was written on 2026-11-26, before that cut was
> published: npm's `latest` tag carries 18.6.0, and no `19.x` version is on
> npm. A plain install stays on 18.x until 19.0 GA; a prerelease is installed
> only on request, at an exact `19.0.0-next.N`. The [v18](/docs/releases/v18)
> line is the current release.

**The v19 line** opened on `main` with two changes. The first,
[#37230](https://github.com/objectstack-ai/objectstack/pull/37230) (merged
2026-11-25), put Changesets in pre mode with the tag `next` and carries the
line's two `major` changesets; every package versions in lockstep, so the
whole train moves to 19, and each cut until 19.0 GA is a `19.0.0-next.N`
prerelease. The second,
[#37314](https://github.com/objectstack-ai/objectstack/pull/37314) (merged
2026-11-26), moved `PROTOCOL_VERSION` to `19.0.0`. Every other breaking change
below landed on `main` after 18.6.0 and ships in `19.0.0-next.0`, each with
its own changeset saying what breaks and how to move.

## Breaking changes

**How this list was built.** From the 950 changesets pending on `main` at
`a46efa8c`, the input of the `19.0.0-next.0` version pass. Each changeset
body was classified by `classifyReleaseBullet` in
`scripts/release-github-releases.mjs`, the function that groups a GitHub
Release body: **102 are breaking**, from 101 pull requests. 71 need you to act
and 31 carry a registered ADR-0087 entry that `os migrate meta` lists for
you. Of the rest, 278 add capabilities, 7 declare a semantic change and 563
are other fixes; they are not listed here. Each line below is the changeset's
own summary, shortened, with the pull request that landed it; the changeset,
and the `CHANGELOG.md` entry the version pass writes from it, carries the
whole before and after. The 87 pull requests titled with `!` since 18.6.0 are
all in this list.
One entry landed after that measurement and is listed with them: the grid's
staged edit retirement,
[#37437](https://github.com/objectstack-ai/objectstack/pull/37437), under
[自动迁移](#migrated-for-you).

### What makes it a major

- **Protocol 19.** `PROTOCOL_VERSION` reads `'19.0.0'`, so a runtime from this
  line refuses a manifest whose `engines.protocol` admits 18 and not 19
  (`'^18'`) with `OS_PROTOCOL_INCOMPATIBLE`, before any of its metadata
  loads. Registered as `protocol-18-range-refused`, on the protocol-19 step.
  [#37314](https://github.com/objectstack-ai/objectstack/pull/37314)
- **67 translation keys retired from `@object-ui/i18n`.** Keys 18.6.0 shipped
  and no code reads any more are gone from every locale; an override of one
  of them no longer applies. The changeset lists every key.
  [#37230](https://github.com/objectstack-ai/objectstack/pull/37230)

## Coming from 18.x

Reach 18.6.0 first, walking each 18.x page's upgrade checklist, through the
[18.6.0 checklist](/docs/releases/v18/18-6#upgrade-checklist). Then:

1. **Move every pin together, to one exact `19.0.0-next.N`.** Every
   `@objectstack/*` and `@object-ui/*` dependency, with `@objectstack/skills`
   and `create-objectstack` where you use them. A caret range never moves you
   onto a prerelease by itself; pin the exact version.
2. **Declare protocol 19.** In each manifest you author, `objectstack.config.ts`
   and every package manifest of a multi-package app, move
   `engines: { protocol: '^18' }` to `engines: { protocol: '^19' }`. Move it
   with the versions, not before them: an 18.x runtime refuses `'^19'`.

   ```bash
   os migrate meta --from 18 --write   # rewrites a root defineStack manifest's range
   ```

   A manifest `composeStacks` composes from several packages has no one
   literal to rewrite, so there the command writes nothing and lists the range;
   change it by hand in each package manifest.
3. **List the line's registered entries.** `os migrate meta --from 17` also
   replays the protocol-18 step, where 39 of the
   [41 registered entries](#migrated-for-you) sit. Most are semantic entries:
   for those the command rewrites nothing, and prints each with the surface,
   the replacement and how to tell it is done.
4. **Run the build, and fix what it refuses.**

   ```bash
   os validate
   os build
   ```

   Fix each refusal with its line in [需手动处理](#action-required) or
   [自动迁移](#migrated-for-you). The command flow is the loop in
   [Upgrading](/docs/upgrading#the-loop).
5. **Remove overrides of the retired translation keys.** An i18next resource
   or Studio catalogue that overrides one of the 67 keys in
   [#37230](https://github.com/objectstack-ai/objectstack/pull/37230) is never
   read; move its text to the key the surface reads now.
6. **Read the sign-in and access entries before the first boot.** A
   development seed credential is refused and retired outside development
   mode, and the doors listed under
   [需手动处理](#action-required) answer differently for a disabled package, an
   environment you are not a member of, and a reject without a reason.

## How a breaking change lands on this line

- **Prereleases until GA.** Changesets is in pre mode with the tag `next`
  (`.changeset/pre.json`), so each cut versions as `19.0.0-next.N`. 19.0 GA
  exits pre mode and publishes to `latest`.
- **One change, one changeset, one migration.** Each breaking change says so
  in its own changeset, with what breaks and how to move, under the level rule
  the v18 line used: a metadata-protocol change takes `minor`, every other
  change `patch`, and a breaking one keeps its **BREAKING** banner and its
  ADR-0087 disposition.
- **Protocol 19.** `PROTOCOL_VERSION` is `19.0.0`, so the handshake admits
  `engines.protocol: '^19'` and refuses `'^18'`.
