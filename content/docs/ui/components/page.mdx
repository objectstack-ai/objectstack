## `page:header` [#page-header]

Namespace `page`.

| Input | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `title` | `string` \| `object` |  | Supports \{field\} interpolation and inline translation maps; falls back to the record title |
| `subtitle` | `string` \| `object` |  | Same interpolation as Title |
| `actions` | `array` of `string` |  | Action IDS — the names of actions declared on the object's own metadata — rendered in the header before any host-injected system actions. An id whose action declares neither record_header nor record_more in its locations renders nowhere. |
| `recordChrome` | `boolean` |  | Set false for the bare h1 header on non-record pages |
| `showCopyId` | `boolean` |  | — |
| `maxVisible` | `number` |  | How many header actions render as inline buttons on desktop before the rest fold into the overflow menu. A positive integer — the contract rejects 0 and fractional values. Two kinds of action are routed to the overflow menu regardless of this budget and never occupy an inline slot: an action whose locations declare record_more without record_header, and any action with component action:menu. The host's own buttons (the record page's Edit) take no slot and never fold. The first inline action, or the one declaring variant primary, is the one filled primary button; the others are outline buttons. An action declaring variant danger is never the primary: inline it is a destructive button, and in the overflow menu it is a red row below a separator. |
| `mobileMaxVisible` | `number` |  | The same inline-button budget on mobile viewports, where horizontal room is scarce. A positive integer, defaulting to 1; the desktop half is Max Inline Actions, and the overflow routing rules stated there apply unchanged. |
