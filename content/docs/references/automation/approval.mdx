### Properties

| Property | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| **approvers** | `{ type: Enum<'manager' \| 'position' \| 'department' \| 'team' \| 'queue' \| 'field' \| …>; value?: string; resolveAs?: Enum<'user' \| 'department' \| 'position' \| 'team'>; group?: string; … }[]` | ✅ | Who can approve this step |

| **behavior** | `Enum<'first_response' \| 'unanimous' \| 'quorum' \| 'per_group'>` | optional (default: `"first_response"`) | How several approvers decide: the first answer wins (the default), everyone must approve, a minimum number must approve, or one from each group must approve. Any single rejection rejects the step |
| **minApprovals** | `integer` | optional | How many approvals this step needs: in total when a minimum number must approve, or from each group when one from each group signs off. Omitted ⇒ all resolvable approvers for quorum, 1 per group for per_group |
| **lockRecord** | `boolean` | optional (default: `true`) | Stop anyone editing the record while it waits for this approval |
| **approvalStatusField** | `string` | optional | A field on the record that shows where its approval stands (pending, approved, rejected or recalled); make it read-only |

'admin_rescue' (default) opens the request on the administrators; 'fallback' opens it on fallbackApprovers instead, naming who decides; 'fail' fails the step; 'auto_approve' approves it with no one deciding |
| **fallbackApprovers** | `{ type: Enum<'manager' \| 'position' \| 'department' \| 'team' \| 'queue' \| 'field' \| …>; value?: string; resolveAs?: Enum<'user' \| 'department' \| 'position' \| 'team'>; group?: string; … }[]` | optional | Backup approvers who decide when this step finds no one else. Read only when onEmptyApprovers is 'fallback' |
| **decisionOutputs** | `(string \| { key: string; label?: string; type?: Enum<'text' \| 'user' \| 'department' \| 'position' \| 'team'>; multiple?: boolean; … })[]` | optional | Extra answers the approver gives with the decision, such as who approves a later step; later steps read them. Each entry is a plain name (a text box) or `{ key, type, multiple }` to show a picker |
| **escalation** | `{ enabled?: boolean; timeoutHours: number; action?: Enum<'reassign' \| 'auto_approve' \| 'auto_reject' \| 'notify'>; escalateTo?: string; … }` | optional | A deadline for this step, and what happens when it passes |
| **maxRevisions** | `integer` | optional (default: `3`) | How many times a request can be sent back for changes before it is rejected automatically (0 turns send-back off) |

## ApproverType

How this step finds its approvers. Prefer a role in the organization (manager, position, department, team) over one named person, who may leave or not exist in another environment. A manager step only finds someone once an administrator has recorded each user's manager in the user directory; until then it finds nobody and the request follows the node's `onEmptyApprovers` policy. `os lint` reports that at authoring time as `approval-approvers-may-resolve-empty`, and `os explain approval-approvers-may-resolve-empty` carries the ways to fill the directory in and the full remedy; the Approvals guide states the same remedy in prose.

### Allowed Values

* `manager`
* `position`
* `department`
* `team`
* `queue`
* `field`
* `expression`
* `org_membership_level`
* `role`
* `user`
