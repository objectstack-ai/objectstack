Dataset AI tools — the inputs and outputs of `list_datasets` and
`query_dataset` (ADR-0149 D2).

The two tools give an AI the business semantic layer a person already reads
through dashboards and reports: `list_datasets` returns the catalogue (the
datasets the caller may query, their dimensions and measures, each member's
business vocabulary, and which of the caller's words matched which member),
and `query_dataset` runs a `DatasetSelection` against one saved dataset and
answers rows plus a `provenance` block naming the dataset and the measures
used. The shapes are declared here once and projected to the JSON Schema an
`AIToolDefinition` carries (`getDatasetToolJsonSchemas`), so the MCP
registration and the product AI's registration read one definition.

`query_dataset`'s `selection` is `DatasetSelectionSchema` BY REFERENCE, the
body `POST /api/v1/analytics/dataset/query` takes under the same key: the AI
has no private dialect, and the selection's own aliases and guidance apply
inside it. Only a saved dataset is addressed, by `datasetName`: there is no
inline `dataset` and no `previewDrafts` on this tool, because an AI that could
author a dataset inline could author its own 口径.

Only the shapes are spec. The executor, the catalogue builder with its
admission and member withholding, the term matcher and the row cap
(`selection.limit` held to the bridge's `maxQueryLimit`) belong to
`@objectstack/service-analytics` (card #31589); the MCP registration under
`data:read` to `@objectstack/mcp` (card #31590). The tool descriptions, which
carry the ADR-0149 D3 selection rule to the model, are written by the
executor: AI guidance text does not enter the spec (ADR-0149 M1, ruled A).

Absent on a cube query answer. |
| **drillRawRows** | `Record<string, any>[]` | optional | Drill-through sidecar, aligned to `rows` by index: each `dimensionFields` dimension name to the stored value that row was grouped by (a select option's value, a lookup's record id), captured before label resolution rewrites the row to its display label. | **drillRawTotals** | `Record<string, any>[][]` | optional | Drill-through sidecar for `totals`: entry `[i][j]` aligns to `totals[i].rows[j]` and holds the stored value of the `dimensionFields` dimensions that grouping groups by, so the grand-total grouping yields an empty map per row. Set only when `dimensionFields` is and the answer carries at least one `totals` grouping. |
| **drillRanges** | `Record<string, { field: string; gte: string; lt: string }>[]` | optional | Drill-through sidecar for date ranges, aligned to `rows` by index: date dimension name to the half-open range `[gte, lt)` that row's records fall in on that dimension's field. A time bucket gets the span it covers; a `timeDimensions[].dateRange` window gets the window the query filtered by on every row, or narrows the bucket entry on the same field to the part inside the window. Bounds are `YYYY-MM-DD` calendar days, or ISO-8601 instants when the source field is `datetime` (a bucket's at midnight in the reference timezone); a row whose bucket value is null gets no bucket entry, and a window whose end is an instant or the last supported day gets none. Set only on a dataset answer that has rows and groups by at least one `type: 'date'` dimension with a `field` and a granularity, or carries a `dateRange` on a dimension with a `field`; independent of `dimensionFields`. Absent on a cube query answer. |
| **drillScopes** | `Record<string, any>` | optional | Drill-through sidecar per measure: each selected measure name to the list filter, on the answer's `object`, that selects the records that measure aggregates: the dataset's own `filter`, AND the measure's own `filter`, AND, for a measure over a `field`, that field holding a value (`{ "$null": false }`; both instants for a duration measure), with each `{token}` resolved as the query resolved it; `{}` when none of these applies.
